### 1. Создать проект по образцу

Создайте папку `121-blink-reg` и скопируйте в неё четыре файла проекта `112-blink` — папку `build` не копируйте.

``` bash
cd ~/Repositories/pico/es-student
mkdir 121-blink-reg
cp 112-blink/CMakeLists.txt 121-blink-reg
cp 112-blink/main.c 121-blink-reg
cp 112-blink/memmap_rp2040.ld 121-blink-reg
cp 112-blink/pico_sdk_import.cmake 121-blink-reg
cd 121-blink-reg
```

Имя папки совпадает с именем проекта. Правило одно на весь курс, номер задания без точек и латинское имя через дефис в формате `XYZ-kebab-style`.  По имени папки видно, для какого задания она создана.

Теперь имя нужно поменять в `CMakeLists.txt`. Здесь поможет переменная [[PROJECT_NAME#^def|${PROJECT_NAME}]].

Впишите новое имя в `project()`,

``` cmake

```

В остальных командах замените `112_blink` на `${PROJECT_NAME}`.

### 2. Найти адреса регистров в документации

Из [[т1.2.9 GPIO#^intro|теории про GPIO]] вы знаете: состоянием выводов заведует блок `SIO`, и у него есть отдельные регистры на «зажечь» и «погасить». Найдите их адреса сами — это и есть навык, ради которого написано задание.

Адрес складывается из двух частей: базовый адрес блока плюс смещение регистра внутри блока.

| Что ищем | Где смотреть | Что должно получиться |
| --- | --- | --- |
| Базовый адрес блока `SIO` | [[RP2040 Datasheet.pdf#page=25\|раздел «2.2. Address Map»]] | `SIO_BASE` |
| Смещение `GPIO_OUT_SET` | [[RP2040 Datasheet.pdf#page=43\|список регистров SIO]] | зажечь вывод |
| Смещение `GPIO_OUT_CLR` | там же | погасить вывод |

Числа выписывать не нужно: и базовый адрес, и смещения уже объявлены в заголовочных файлах SDK, `hardware/regs/addressmap.h` и `hardware/regs/sio.h`. Но найти их в документации стоит своими глазами — так вы увидите, что за именем `SIO_GPIO_OUT_SET_OFFSET` стоит строка в таблице производителя, а не «магия» SDK.

>[!info] Почему два регистра, а не один
>Казалось бы, достаточно одного регистра состояния выводов: записал туда число — получил нужные уровни. Но тогда, меняя один вывод, вы каждый раз переписывали бы состояние всех тридцати. Отдельные регистры «установить» и «сбросить» решают это: единица в разряде меняет свой вывод, нули не трогают остальные.

### 3. Заменить вызовы функции на запись по адресу

Подключите два заголовочных файла с адресами:

``` c
#include "hardware/regs/addressmap.h"
#include "hardware/regs/sio.h"
```

Перед суперциклом заведите два указателя на регистры и маску вывода светодиода:

``` c
    volatile uint32_t *gpio_out_set = (uint32_t *)(SIO_BASE + SIO_GPIO_OUT_SET_OFFSET);
    volatile uint32_t *gpio_out_clr = (uint32_t *)(SIO_BASE + SIO_GPIO_OUT_CLR_OFFSET);
    const uint32_t led_mask = 1u << LED_PIN;
```

Указатель здесь — это просто число-адрес, по которому программа будет писать. Маска `1u << LED_PIN` ставит единицу в тот разряд, который отвечает за вывод `25`, и нули во все остальные: именно так регистр понимает, о каком выводе идёт речь.

Слово `volatile` говорит компилятору, что за этим адресом не обычная переменная, а регистр устройства. Без него компилятор вправе решить, что две записи подряд бессмысленны, и выбросить одну из них.

Теперь замените в суперцикле вызовы `gpio_put()` на записи по этим адресам:

``` c
    while (1)
    {
        *gpio_out_set = led_mask;
        sleep_ms(250);
        *gpio_out_clr = led_mask;
        sleep_ms(1000);
    }
```

Инициализацию вывода — `gpio_init()` и `gpio_set_dir()` — оставьте как есть, настройку периферии делает SDK. В задании вы меняете только функцию на прямую запись по адресу на шине данных.

>[!success] Должно получиться так
> ```c
> #include "pico/stdlib.h"
> #include "hardware/gpio.h"
> #include "hardware/regs/addressmap.h"
> #include "hardware/regs/sio.h"
>
> const uint LED_PIN = 25;
>
> int main()
> {
>     gpio_init(LED_PIN);
>     gpio_set_dir(LED_PIN, GPIO_OUT);
>
>     volatile uint32_t *gpio_out_set = (uint32_t *)(SIO_BASE + SIO_GPIO_OUT_SET_OFFSET);
>     volatile uint32_t *gpio_out_clr = (uint32_t *)(SIO_BASE + SIO_GPIO_OUT_CLR_OFFSET);
>     const uint32_t led_mask = 1u << LED_PIN;
>
>     while (1)
>     {
>         *gpio_out_set = led_mask;
>         sleep_ms(250);
>         *gpio_out_clr = led_mask;
>         sleep_ms(1000);
>     }
> }
> ```

>[!tip] Со звёздочкой
>В зачёт не идёт, но если хотите тренироваться и расширять кругозор, то стоит попробовать.
>
>Замените две строки записи в суперцикле на ассемблерные вставки:
>
> ```c
> __asm volatile ("str %1, [%0]" : : "r"(gpio_out_set), "r"(led_mask) : "memory");
> sleep_ms(250);
> __asm volatile ("str %1, [%0]" : : "r"(gpio_out_clr), "r"(led_mask) : "memory");
> sleep_ms(1000);
> ```
>
>Соберите, запишите на плату — светодиод мигает по-прежнему. И это главное, что здесь нужно увидеть: **строка `*gpio_out_set = led_mask;` и команда `str` делают буквально одно и то же.** Компилятор превращает первую во вторую; вы просто написали результат его работы своей рукой. Убедиться можно, посмотрев дизассемблер, — как это делается, разобрано в приложении [[пр1.1 Команды процессора Cortex-M0+#^intro|«Команды процессора Cortex-M0+»]].
>
>Знать ассемблер точно не помешает: он пригодится при отладке и при чтении дизассемблера, когда программа ведёт себя не так, как написано. Но писать на нём в 2026 году для микроконтроллеров не обязательно — достаточно хорошо знать C.
