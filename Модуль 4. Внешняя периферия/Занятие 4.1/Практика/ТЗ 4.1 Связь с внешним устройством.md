**Техническое задание.** Разработайте [[Встроенное программное обеспечение#^def|прошивку]] `411-i2c-spi`. Пользователь задаёт по USB чтение или запись одного байта. Ведущая часть выполняет команду по [[I²C#^def|I²C]] или [[SPI#^def|SPI]]. Ведомая часть управляет светодиодом через [[Регистр#^def|регистры]], доступные по обеим шинам.
^intro

## 1. Общие сведения

| Параметр | Значение |
| --- | --- |
| Проект | `411-i2c-spi` |
| Сборка | `411_i2c_spi.uf2` |
| Плата | Одна Raspberry Pi Pico с RP2040 |
| Внешние элементы | BME280 на 3,3 В и перемычки |
| Связь с компьютером | Стандартный ввод-вывод Pico SDK через USB |
| Код | Новый проект с `stdio-text-protocol` и модулем `logic/api` по [[ТЗ 2.3 Шаблон проектирования#3. Модули проекта\|шаблону 2.3]] |
| Проверка | Скрипты `check-4-1-N.py` на компьютере и автоматические проверки курса |

## 2. Функции

| Код | Требование |
| --- | --- |
| Ф1 | Ведущий читает и записывает один байт регистра устройства по семибитному адресу I²C. |
| Ф2 | Ведущий передаёт управляющий байт SPI и читает или записывает байт данных под одним сигналом выбора. |
| Ф3 | Учебное ведомое выполняется на ядре 1. В промежуточном задании оно мигает светодиодом, в готовом проекте светодиод управляется через регистры. |
| Ф4 | Адрес `0x42` на I²C и выход выбора `0x01` на SPI дают доступ к одним регистрам ведомого. В финале на общей I²C доступен и датчик. |

## 3. Интерфейс по USB

Байты вводите и выводите как `0xNN` с двумя шестнадцатеричными цифрами и заглавными буквами A–F. `help` показывает доступные команды и справку из таблицы API. Правила приёма кадра и ответы на ошибки кадра заданы в [[ТЗ 2.3 Приложение А. Протокол#6. Ошибки кадра|ТЗ 2.3]].

| Команда | Назначение |
| --- | --- |
| `i2c_write_reg <address> <register> <value>` | Записать один байт |
| `i2c_read_reg <address> <register>` | Указать регистр и прочитать один байт с повторным START |
| `spi_write <cs> <command> <value>` | Передать управляющий байт и значение |
| `spi_read <cs> <command> [pause_us]` | Передать управляющий байт и принять ответ. Необязательная пауза задаётся в микросекундах как `0xNN`. |

Линия выбора (CS, *Chip Select*) `0x00` на GP16 предназначена для BME280. Линия `0x01` на GP5 предназначена для учебного ведомого. При чтении с учебного ведомого используйте режим 3 и паузу 100 мкс перед получением ответа. Для датчика пауза не требуется. Обе шины в этом проекте настроены на 100 кГц.

## 4. Регистры ведомого

| Регистр | Адрес  | Доступ | Значения                                                                                                                                    |
| ------- | ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `CMD`   | `0x00` | WO     | Запись `0x65` (соответствует символу ASCII `e`) включает светодиод.<br>Запись `0x64` (соответствует символу ASCII `d`) выключает светодиод. |
| `STATE` | `0x01` | RW     | `0x00` светодиод выключен.<br>`0x01` светодиод включен.<br>Состояние после сброса `0x00`.                                                   |

Записи других значений и номеров игнорируются. Чтение `CMD` и неизвестного регистра возвращает `0xFF`. На SPI младшие семь битов управляющего байта выбирают регистр, а старший бит равен единице при чтении. У I²C направление задаёт адресный байт шины, а номер регистра передаётся отдельно.

## 5. Распределение ресурсов

![[Два ядра и линии связи.excalidraw|100%]]

| Модуль | Где выполняется и чем управляет |
| --- | --- |
| `main.c` | Ядро 0 настраивает ведущие контроллеры, запускает ведомое на ядре 1 и передаёт принятую USB-команду из протокола в API. |
| `logic/api` | Ядро 0. `api.c` ищет обработчик и печатает справку. Обработчики I²C и SPI и их таблица находятся в `api-callbacks.c`. |
| `logic/slave` | Ядро 1. I²C1, SPI1 и штатный светодиод. Ведомое владеет картой регистров. |
| `platform` | Один слой доступа к периферии, общий для проекта. Каждый вызов выполняется на ядре владельца. |

Ведущая и ведомая части обмениваются байтами по перемычкам. Это позволяет работать на одной Pico. Для дополнительного опыта тот же образ можно загрузить в две Pico и перенести перемычки ведомой стороны на вторую плату. На первой USB подключён к компьютеру. Вторая может питаться от пауэрбанка. Между платами соедините землю и сигнальные линии.
