## Ход работы

>[!info] Зачем прибору говорить
>До сих пор плата сообщала о себе одним битом: светодиод горит или не горит. В этом задании канал расширяется до строки текста — и вместе с ним появляется главный инструмент отладки встраиваемых систем. Дальше в курсе почти каждый прибор будет рассказывать о себе именно так, потому что другого способа заглянуть внутрь работающей прошивки у вас нет. Почему канал устроен как COM-порт поверх USB — в [[т1.3.5 Канал связи с компьютером#^intro|теории занятия]].

### 1. Создать проект по образцу

Создайте папку `131-hello-usb` и скопируйте в неё четыре исходных файла проекта `112-blink`. Папку `build` не копируйте. Назовите проект `131_hello_usb`.

### 2. Включить вывод через USB в описании сборки

Стандартный ввод-вывод есть в `pico_stdlib`, но канал для него выбирается отдельно. Добавьте в `CMakeLists.txt` перед `pico_add_extra_outputs()` две строки:

``` cmake
pico_enable_stdio_usb(${PROJECT_NAME} 1)
pico_enable_stdio_uart(${PROJECT_NAME} 0)
```

Первая направляет поток вывода в USB, вторая выключает UART: он ведёт на два вывода корпуса, и без переходника читать с них нечего.

>[!success] Должно получиться так
>Две строки направления отладочного вывода стоят между `pico_set_linker_script()` и `pico_add_extra_outputs()`, имя цели `131_hello_usb` берётся из `${PROJECT_NAME}`. Остальное в файле не меняется — как в [[п1.2.1 Мигание светодиодом через регистр#1. Создать проект по образцу\|п1.2.1, шаг 1]].

### 3. Написать программу

Подключите заголовочный файл стандартного ввода-вывода — тот же, что в любой программе на C:

``` c
#include <stdio.h>
```

Далее заголовочный файл SDK. В нём объявлены `stdio_init_all()` и `sleep_ms()`:

``` c
#include "pico/stdlib.h"
```

>[!info] Почему `pico/stdlib.h` в кавычках, а `stdio.h` в угловых скобках
>Если сильно упростить:
>- `<>` — то, что даёт язык и его стандартная библиотека: `stdio.h`, `stdint.h`, `string.h`. Одинаково на любой платформе;
>- `""` — всё остальное: SDK производителя (`pico/stdlib.h`, `hardware/gpio.h`) и ваши собственные модули (`led.h`).

Включите канал до первого обращения к нему:

``` c
    stdio_init_all();
```

Одна эта строка готовит к работе все устройства ввода-вывода, которые вы выбрали в `CMakeLists.txt`. И сразу в обе стороны: вывод и ввод. По отдельности настраивать ничего не нужно.

Дальше — суперцикл с двумя функциями: печать строки и пауза на одну секунду.

``` c
    while (1)
    {
        printf("Hello, world!\n");
        sleep_ms(1000);
    }
```

`\n` в конце строки — не украшение и не опечатка, это перевод строки. Экранирущий символ `\` и последующий символ `n` после компиляции превращаются в один символ переноса строки. По приходу этого символа принимающий терминал перенесёт каретку на следующую строку, а принимающий Python-скрипт определит, что строка пришла полностью. Без `\n` текст пойдёт сплошной лентой.

Светодиод в этом задании не нужен: строки `gpio_init()`, `gpio_set_dir()` и вызовы `gpio_put()` из скопированного `main.c` уберите.

>[!success] Должно получиться так
> ```c
> #include <stdio.h>
> #include "pico/stdlib.h"
>
> int main()
> {
>     stdio_init_all();
>
>     while (1)
>     {
>         printf("Hello, world!\n");
>         sleep_ms(1000);
>     }
> }
> ```

### 4. Собрать, записать и открыть терминал

Соберите проект и запишите `.uf2` на плату, как в [[п1.1.3 Запуск прошивки#^intro|п1.1.3]].

Теперь в операционной системе вашего компьютера нужно подключиться к виртуальному последовательному порту (COM-порту). Этот порт реализует только что записанная в Raspberry Pi Pico программа средствами микроконтроллера.

COM-порт появится в системе только после подключения к компьютеру Raspberry Pi Pico. После того, как ВПО начнёт исполняться.

| Система | Где искать порт                                 | Как он выглядит         |
| ------- | ----------------------------------------------- | ----------------------- |
| Windows | диспетчер устройств, раздел «Порты (COM и LPT)» | `COM7`                  |
| macOS   | `ls /dev/tty.*` до и после подключения платы    | `/dev/tty.usbmodem1101` |
| Linux   | `ls /dev/tty*` до и после подключения платы     | `/dev/ttyACM0`          |

Откройте найденный порт терминальной программой.

В macOS — встроенной программой `screen`, подставив своё имя порта:

``` bash
screen /dev/tty.usbmodem1101
```

В Linux — той же командой:

``` bash
screen /dev/ttyACM0
```

В Windows штатной терминальной программы нет, в курсе используется PuTTY. Она работает окном, а не командой: в `Connection type` выберите `Serial`, в `Serial line` впишите имя порта и нажмите `Open`. Где скачать и как настроить — в карточке [[PuTTY#Установка\|PuTTY]].

Скорость порта указывайте любую: обмен идёт через USB, и заданная скорость на него не влияет.

Выход из `screen` — `Ctrl + A`, затем `K` и `y`; остальные тонкости работы с портом собраны в карточке навыка [[Работа с терминалом COM-порта#^def\|Работа с терминалом COM-порта]].

>[!success] Должно получиться так
>В окне терминала раз в секунду появляется новая строка:
>
> ```
> Hello, world!
> Hello, world!
> Hello, world!
> ```

>[!bug] Терминал молчит
>Проверьте по порядку:
>- обе строки `pico_enable_stdio_*` есть в `CMakeLists.txt`
>- и проект пересобран
>- `stdio_init_all()` вызван до цикла
>- в терминале открыт именно тот порт, который появился после подключения платы
>
>Отдельная причина — первые строки: пока компьютер не открыл порт, забирать данные некому, и SDK молча их отбрасывает. Строку, выведенную сразу после старта, вы не увидите никогда, и это не ошибка. Подробнее — [[т1.3.6 Стандартный ввод-вывод в прошивке#^intro|в теории занятия]].
