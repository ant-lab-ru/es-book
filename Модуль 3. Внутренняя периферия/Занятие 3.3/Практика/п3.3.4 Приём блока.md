**Результат** — UART0 принимает блок из 64 байтов, вдвое длиннее своей очереди приёма. С прерыванием приёма блок приходит целиком. Без прерывания прибор находит в очереди ровно половину блока и признак переполнения `OE`, и вы объясняете, куда делась вторая половина.

1. **Половина блока теряется.** Наберите `block irq`, затем `block poll`. В первом ответе `64/64`, во втором `32/64` и признак `OE`.
2. **Лог прогона лежит в проекте.** Скрипт задания записывает обмен в `device-3-3-4.log`. Провода от прошлого задания стоят весь прогон.

## Ход работы

Очередь приёма и прерывания UART разобраны в [[т3.3.3 Модуль коммуникации#FIFO между ядром и сдвиговым регистром|т3.3.3]], признак переполнения — в [[т3.3.4 UART RP2040#Ошибки приёма|т3.3.4]], обработчик и общие с ним данные — в [[т3.2.5 Обработчик прерывания#^intro|т3.2.5]]. Провода и скорость остаются от [[п3.3.3 Два модуля и допуск скорости#^intro|п3.3.3]]. Если скорость или чётность меняли, верните их командами `baud_shift 0` и `parity none none`.

### 1. Посчитать, что случится с блоком

Символ 8N1 занимает на линии 10 битов. Блок из 64 байтов на 115 200 бит/с идёт $64 \cdot 10 / 115\,200 \approx 5{,}6$ мс. Очередь приёма держит 32 символа, она заполнится за 2,8 мс. Если за это время прошивка не заберёт ни одного байта, следующий символ соберётся в сдвиговом регистре, и класть его будет некуда.

Модуль поступает так, как написано в [[RP2040 Datasheet.pdf#page=423|RP2040 Datasheet, раздел «4.2.3.2.4. Overrun bit»]]. Символ из сдвигового регистра пропадает, очередь остаётся целой, а признак `OE` ставится. В `UARTRSR` признак ставится сразу и держится до записи в `UARTECR`. В регистр данных он попадает только вместе со следующим символом, который удалось положить в очередь. После блока линия молчит, такого символа нет. Поэтому `OE` читают из `UARTRSR`, а не из битов 11:8 регистра данных.

### 2. Забирать байты в обработчике прерывания

Байты, которые забрал обработчик, нужно где-то хранить, пока задача обмена не спросит их. Буфер и счётчик живут в `platform.c`, их меняет обработчик, а читает `platform_uart_read()`.

```c
#include "hardware/irq.h"

// принятое обработчиком прерывания: блок длиннее очереди приёма
#define RX_BUFFER_SIZE 128

static volatile uint8_t rx_buffer[RX_BUFFER_SIZE];
static volatile uint32_t rx_count;

// обработчик UART0_IRQ: забирает из очереди приёма всё, что там есть
static void on_uart0_rx(void)
{
    while (uart_is_readable(uart0))
    {
        uint8_t byte = uart_get_hw(uart0)->dr & 0xff;
        if (rx_count < RX_BUFFER_SIZE)
        {
            rx_buffer[rx_count++] = byte;
        }
    }
}
```

Цикл в обработчике не ждёт. Он кончается, как только очередь опустела. Обработчик должен стоять в файле выше `platform_init()`, которая его назначает.

Прерывание UART у RP2040 одно на модуль, `UART0_IRQ` ([[т3.3.3 Модуль коммуникации#Прерывание и запрос DMA от модуля коммуникации|т3.3.3]]). В конец `platform_init()` добавьте назначение обработчика и включение прерывания в контроллере.

```c
    irq_set_exclusive_handler(UART0_IRQ, on_uart0_rx);
    irq_set_enabled(UART0_IRQ, true);
```

Пока модуль не просит прерывания, обработчик не вызывается. Просьбу включает маска в `UARTIMSC`. Добавьте в `platform.h` функцию.

```c
// прерывание приёма UART0: принятые байты забирает обработчик
void platform_uart_rx_irq_set(bool on);
```

и в `platform.c`.

```c
void platform_uart_rx_irq_set(bool on)
{
    // прерывание по четырём байтам в очереди и по паузе на линии
    uart_set_irqs_enabled(uart0, on, false);
}
```

`uart_set_irqs_enabled()` разрешает два прерывания приёма. Первое срабатывает, когда в очереди набралось четыре байта. Второе срабатывает по паузе на линии в 32 бита и забирает последние байты, если их меньше четырёх ([[RP2040 Datasheet.pdf#page=427|RP2040 Datasheet, раздел «4.2.6.4. UARTRTINTR»]]).

Осталось научить чтение и очистку видеть буфер. В `platform_uart_read()` перед циклом по очереди добавьте копирование того, что забрал обработчик, а в `platform_uart_clear()` обнулите счётчик.

>[!success] Должно получиться так
> ```c
> // platform_uart_read(): для UART0 сначала rx_count байтов из rx_buffer,
> // затем, как прежде, то, что осталось в очереди
>
> // platform_uart_clear(): для UART0 в конце rx_count = 0
> ```

### 3. Добавить команду block

Блок — 64 байта, каждый равен своему номеру, от 0 до 63. Команда разрешает или запрещает прерывание приёма и запускает обмен UART1 → UART0. Функция результата запрещает прерывание, сравнивает принятое с началом блока и печатает итог.

>[!success] Должно получиться так
> ```c
> // блок команды block — 64 байта, вдвое длиннее очереди приёма
> #define BLOCK_SIZE 64
>
> // print_block(): прерывание приёма запретить;
> // match — байты есть и совпадают с первыми байтами блока (memcmp);
> // block <irq|poll>: <принято>/64 <match|mismatch>, <признаки>
>
> // cmd_block(): аргумент irq или poll, иначе error: usage block irq|poll
> // заполнить блок номерами, прерывание приёма по аргументу,
> // обмен UART1 → UART0 с функцией print_block;
> // задача не приняла обмен — запретить прерывание, error: uart is busy
>
> // в таблице команд
> { "block", "64 bytes from UART1 to UART0: block irq|poll", cmd_block },
> ```

| Что нужно написать | Где это разбиралось |

| обмен с функцией результата | `cmd_text()`, [[п3.3.3 Два модуля и допуск скорости#3. Добавить команды обмена двух модулей\|п3.3.3, шаг 3]] |
| признаки ошибок в ответе | `print_errors()`, [[п3.3.2 Петля и перемычка#3. Добавить команды loop и echo\|п3.3.2, шаг 3]] |

Задача обмена уже умеет передавать больше 32 байтов. Пока передача идёт, она дописывает байты в очередь передачи по мере того, как та освобождается. Без прерывания в это же время никто не читает очередь приёма.
