>[!NOTE] Навык
>**Работа с битовыми полями** — умение по описанию поля в карте регистров построить его маску, прочитать значение поля, записать в него новое значение, не изменив соседние поля, и учесть тип доступа поля.
^def

## Что нужно знать

Регистр периферии — это 32-битное слово, а [[Битовое поле#^def|битовое поле]] — несколько соседних битов этого слова со своим назначением. Для каждого поля карта регистров указывает номера его битов и [[Тип доступа#^def|тип доступа]]. Например, поле `AINSEL` регистра `CS` у АЦП RP2040 занимает биты 12–14 и имеет тип RW. Биты нумеруют с нуля, начиная с младшего.

Обратиться к трём битам в середине слова напрямую язык C не позволяет. Поэтому регистр всегда читают и записывают целиком, а нужные биты выделяют побитовыми операторами и маской. Вся работа с полями сводится к шести операторам и трём приёмам, чтению поля, записи поля и изменению одного бита.

## Двоичная и шестнадцатеричная запись

Биты удобнее всего видеть в двоичной записи, но 32 цифры читать тяжело. Поэтому значения регистров записывают в шестнадцатеричной системе. Одна шестнадцатеричная цифра — это ровно четыре бита, и число переводится из одной записи в другую по цифре.

| Шестнадцатеричная | Двоичная | Единиц подряд |
| --- | --- | --- |
| `0x1` | `0b1` | 1 |
| `0x3` | `0b11` | 2 |
| `0x7` | `0b111` | 3 |
| `0xf` | `0b1111` | 4 |

Числа из таблицы — заготовки масок. Полю шириной n битов нужно n единиц подряд, это число `(1u << n) - 1`. Для `AINSEL` шириной три бита это `0x7`.

Номера битов тоже видны по шестнадцатеричной записи. Цифры справа налево покрывают биты 0–3, 4–7, 8–11, 12–15 и так далее. В числе `0x00007000` ненулевая цифра стоит четвёртой справа, значит, она описывает биты 12–15. Сама цифра `0x7` равна `0b0111`, поэтому единицы стоят в битах 12, 13 и 14.

Запись `0b111` понимает компилятор GCC, но в коде для регистров маски принято писать в шестнадцатеричном виде, как в документации.

## Побитовые операторы

Побитовые операторы работают с каждым битом числа отдельно. В примерах числа короткие, с 32-битным словом всё происходит так же.

| Оператор                | Название        | Что получается в каждом бите                                 | Пример                                       |
| ----------------------- | --------------- | ------------------------------------------------------------ | -------------------------------------------- |
| `a & b`                 | И               | единица, только если в обоих числах единица                  | `0b1100 & 0b1010` → `0b1000`                 |
| <code>a &#124; b</code> | ИЛИ             | единица, если хотя бы в одном числе единица                  | <code>0b1100 &#124; 0b1010</code> → `0b1110` |
| `a ^ b`                 | исключающее ИЛИ | единица, если биты различаются                               | `0b1100 ^ 0b1010` → `0b0110`                 |
| `~a`                    | НЕ              | бит переворачивается                                         | `~0x0000000c` → `0xfffffff3`                 |
| `a << n`                | сдвиг влево     | биты сдвигаются на n позиций к старшим, справа приходят нули | `0b0011 << 2` → `0b1100`                     |
| `a >> n`                | сдвиг вправо    | биты сдвигаются на n позиций к младшим, младшие пропадают    | `0b1101 >> 2` → `0b0011`                     |

Из таблицы следуют три правила, на которых держится вся работа с полями.

- `x & 1` оставляет бит, а `x & 0` его обнуляет. Поэтому `&` с маской вырезает нужные биты, а `&` с перевёрнутой маской их очищает.
- `x | 1` ставит единицу, а `x | 0` бит не меняет. Поэтому `|` добавляет единицы и не трогает остальные биты.
- `x ^ 1` переворачивает бит, а `x ^ 0` его не меняет.

Составные операторы `&=`, `|=`, `^=`, `<<=` и `>>=` — сокращения. Запись `value &= mask` значит то же, что `value = value & mask`, а `value |= bits` — то же, что `value = value | bits`.

Побитовые `&` и `|` не путают с логическими `&&` и `||`. Логические операторы смотрят на число целиком и дают 0 или 1, они нужны в условиях. Побитовые дают новое число, в котором каждый бит посчитан отдельно.

## Маска поля

Маска поля — число, у которого единицы стоят ровно в битах поля. Её строят из заготовки нужной ширины и сдвигают на номер младшего бита поля. Младший бит поля называют LSB, старший называют MSB ([[LSB и MSB#^def|LSB и MSB]]), отсюда и имя константы в коде ниже.

```c
// AINSEL занимает биты 12–14, это три единицы, сдвинутые на 12
#define AINSEL_LSB 12
#define AINSEL_MASK (0x7u << AINSEL_LSB)

// AINSEL_MASK == 0x00007000
```

Дальше в примерах маска и сдвиг поля называются этими именами.

Буква `u` после числа делает его беззнаковым, и с регистрами работают только такими числами. Сдвиг знаковой единицы в старший бит, `1 << 31`, в языке C даёт неопределённое поведение, а `1u << 31` даёт правильное число `0x80000000`.

В Pico SDK маски всех полей уже определены в заголовках `hardware/regs/`. Для `AINSEL` это `ADC_CS_AINSEL_BITS`, равная `0x00007000`, `ADC_CS_AINSEL_LSB`, равная 12, и `ADC_CS_AINSEL_MSB`, равная 14. Там же `ADC_CS_AINSEL_ACCESS` хранит тип доступа `"RW"`.

## Чтение значения поля

Чтобы узнать значение поля, слово регистра сдвигают вправо на номер младшего бита поля. Поле оказывается в младших битах, и его вырезают маской нужной ширины. Пусть из `CS` прочитано `0x00004103`.

```c
volatile uint32_t *cs = (volatile uint32_t *)(0x4004c000 + 0x00);
uint32_t value = *cs;

// Поле AINSEL, биты 12–14: сдвинуть вправо и оставить три бита
uint32_t channel = (value >> AINSEL_LSB) & 0x7u;
// channel == 4, в двоичном виде 0b100, это три бита поля AINSEL

// Однобитное поле READY, бит 8
uint32_t ready = (value >> 8) & 0x1u;
// ready == 1, в двоичном виде 0b1, это один бит поля READY
```

Можно и в обратном порядке, сначала вырезать поле маской на его месте, потом сдвинуть, `(value & AINSEL_MASK) >> AINSEL_LSB`. Так читает поле функция SDK `adc_get_selected_input()`.

Однобитное поле часто проверяют без сдвига. Выражение `value & (1u << 8)` равно нулю, если бит сброшен, и не равно нулю, если установлен. В условии `if` или `while` ненулевое число означает истину.

```c
// Ждать, пока АЦП закончит отсчёт и выставит READY
while (!(*cs & (1u << 8))) {
}
```

## Запись значения в поле

Присвоить регистру число нельзя, остальные поля получат нули. Поэтому поле записывают в три шага. Регистр читают, в прочитанном значении очищают биты поля и вписывают на их место новое значение, а затем записывают слово обратно. Такую запись называют «чтение, изменение, запись» (*англ. read-modify-write*).

```c
// В CS сейчас 0x00004103, в AINSEL записан канал 4
uint32_t value = *cs;

// Очистить поле, ~AINSEL_MASK == 0xffff8fff
value &= ~AINSEL_MASK;
// value == 0x00000103

// Вписать канал 2 на место поля
value |= 2u << AINSEL_LSB;
// value == 0x00002103

*cs = value;
```

Это два правила из раздела об операторах. `&` с перевёрнутой маской очищает только поле, и `EN`, `TS_EN` и `READY` сохраняются. `|` добавляет единицы нового значения. Без очистки старые единицы поля смешались бы с новыми.

Если значение приходит извне, например номер канала из команды, его проверяют до записи. Число 9 не помещается в три бита. `9u << 12` равно `0x00009000`, и лишняя единица попадёт в бит 15, за пределы поля. Если проверки нет, значение хотя бы ограничивают маской, `(9u << AINSEL_LSB) & AINSEL_MASK` оставит только биты поля.

Для однобитного поля хватает одной операции.

```c
// Установить бит EN (бит 0), остальные биты не меняются
*cs |= 1u << 0;

// Сбросить бит EN
*cs &= ~(1u << 0);

// Переключить бит EN
*cs ^= 1u << 0;
```

Каждая из этих строк — те же «чтение, изменение, запись», только короче. Компилятор читает регистр, меняет значение и записывает его обратно.

## Поля с разными типами доступа

Тип доступа из карты регистров подсказывает, что можно делать с полем.

- **RW.** Поле хранит записанное значение. Его читают и записывают приёмами выше.
- **RO.** Поле только читают. Запись его не меняет, поэтому записать единицу в `READY`, чтобы АЦП стал готов, бесполезно. Значение RO-поля меняет сам модуль, поэтому указатель на регистр объявляют с `volatile`. Без него компилятор вправе прочитать регистр один раз и в цикле ожидания проверять старое значение.
- **SC.** Записанная единица выполняет команду, и поле само возвращается в ноль. Строка `*cs |= 1u << 2` запускает отсчёт через `START_ONCE`. Очищать поле после команды не нужно.
- **WC.** Поле сбрасывают записью единицы, а ноль его не меняет. Флаг `ERR_STICKY` в бите 10 сбрасывают строкой `*cs |= 1u << 10`.

С полями WC связана ловушка. Запись «чтение, изменение, запись» возвращает в регистр всё, что прочитала. Если в `ERR_STICKY` стояла единица, любая такая запись в `CS`, например смена канала, запишет её обратно и сбросит флаг. Ошибка пропадёт раньше, чем прошивка её заметит. Поэтому перед `*cs = value` биты полей WC в значении очищают, для `ERR_STICKY` это строка `value &= ~(1u << 10)`.

## Те же приёмы в Pico SDK

У регистров периферии RP2040 есть дополнительные адреса. Запись по ним устанавливает, сбрасывает или переключает только указанные биты, а остальные не трогает. SDK обращается к ним через функции из `hardware/address_mapped.h`.

| Функция | Что делает | То же самое в коде |
| --- | --- | --- |
| `hw_set_bits(&reg, mask)` | ставит единицы в битах маски, не читая регистр | <code>reg &#124;= mask</code> |
| `hw_clear_bits(&reg, mask)` | ставит нули в битах маски, не читая регистр | `reg &= ~mask` |
| `hw_xor_bits(&reg, mask)` | переворачивает биты маски, не читая регистр | `reg ^= mask` |
| `hw_write_masked(&reg, values, mask)` | читает регистр и переключает те биты маски, которые отличаются от `values` | чтение, изменение, запись |

Биты вне маски эти функции не записывают вовсе, поэтому поля WC остаются нетронутыми. На них построены функции АЦП в SDK.

```c
// adc_select_input(): записать канал в поле AINSEL
hw_write_masked(&adc_hw->cs, input << ADC_CS_AINSEL_LSB, ADC_CS_AINSEL_BITS);

// adc_read(): запустить отсчёт и ждать READY
hw_set_bits(&adc_hw->cs, ADC_CS_START_ONCE_BITS);
while (!(adc_hw->cs & ADC_CS_READY_BITS))
    tight_loop_contents();
```

## Частые ошибки

| Ошибка | Что получится | Как правильно |
| --- | --- | --- |
| <code>value &#124;= 1u &lt;&lt; 12</code> без очистки поля | в поле было 4 (`0b100`), стало 5 (`0b101`), а не 1 | сначала `value &= ~AINSEL_MASK` |
| `value &= ~0x7u << 12` | `~` выполняется раньше сдвига, маска `0xffff8000` очищает и поле, и все биты ниже, АЦП выключается | `value &= ~(0x7u << 12)` |
| `if (value & 0x7u << 12 == 0)` | `==` выполняется раньше `&`, условие всегда ложно | `if ((value & (0x7u << 12)) == 0)` |
| `value && mask` вместо `value & mask` | получится 0 или 1 для всего числа, а не биты | `&` для битов, `&&` для условий |
| `*cs = 2u << 12` | остальные поля получат нули, АЦП выключится | чтение, изменение, запись или `hw_write_masked()` |
| `1 << 31` | неопределённое поведение | `1u << 31` |
| номер бита отсчитан с единицы | сдвиг на один бит мимо поля | биты нумеруют с нуля |

Про ошибку с `==` компилятор GCC предупреждает, если включены предупреждения (`-Wall`). Такое предупреждение стоит читать, а не отключать.

## Самопроверка

Значение регистра удобно напечатать в шестнадцатеричном виде и разобрать по цифрам.

```c
printf("CS = 0x%08lx\n", (unsigned long)*cs);
// CS = 0x00004103
```

Формат `%08lx` печатает восемь шестнадцатеричных цифр с ведущими нулями, по одной на каждые четыре бита. В `0x00004103` цифра 4 в битах 12–15 — это `AINSEL = 4`. Цифра 1 в битах 8–11 — это `READY`. Цифра 3 в битах 0–3 — это `EN` и `TS_EN`.
