**Результат** — общие для приборов курса модули стали библиотеками CMake в папке `libs/` в корне репозитория. Каждая библиотека описывает свою сборку сама. SDK она подключает только для себя, и пользователь библиотеки о нём не узнаёт. Время задачи берут из новой библиотеки `systime`. Профилирование выключается при сборке одной строкой.
^intro

## Задание

### Что должно получиться

- [ ] В `libs/` пять библиотек: `stdio-text-protocol`, `systime`, `profiling`, `device`, `logging`, каждая разложена по `include/<имя>/` и `src/`
- [ ] Проект подключает библиотеки по именам, в папке проекта их исходников не осталось
- [ ] Библиотека `logging` собирается без SDK, остальные подключают его как `PRIVATE`
- [ ] Константы прошивки лежат в `firmware.h` в папке проекта
- [ ] Профилирование выключается строкой `PROFILING_ENABLED=0`, и `profiling` отвечает, что оно выключено
- [ ] Коммит отправлен, проверка `2.3.6` зелёная

### Как проверить

1. **Прибор работает как прежде.** Все команды, кнопка, мигание и расчёт π работают так же, как до изменений.
2. **Граница проверяется сборкой.** Добавьте строку `#include "pico/stdlib.h"` в начало `libs/logging/src/log.c` и соберите проект. Сборка останавливается с ошибкой `No such file or directory`. Уберите строку.
3. **Профилирование выключается.** Поставьте `PROFILING_ENABLED=0`, соберите и запишите прошивку. Файл `.bin` стал меньше, а `profiling` отвечает `profiling is disabled in this build`. Верните `1`.
4. **Автоматическая проверка курса принимает задание.** Проверка статическая. Она проверяет раскладку каждой библиотеки и `libs/CMakeLists.txt`. Она убеждается, что SDK не подключён как `PUBLIC`, что `logging` его не подключает вовсе и что ни один заголовок в `libs/` не подключает заголовков SDK. В проекте она ищет `add_subdirectory(../libs …)` с каталогом сборки и выключатель `PROFILING_ENABLED`. Ещё она проверяет, что заголовки подключаются с именем библиотеки, а часы читаются только через `systime`.

## Ход работы

Теория задания — [[т2.3.6 Библиотека в сборке#^intro|т2.3.6]]. Раскладка и интерфейсы библиотек описаны в разделах 1 и 2 [[ТЗ 2.3 Шаблон проектирования|части 2 технического задания]].

### 1. Разложить модули по библиотекам

Создайте в корне репозитория, рядом с папками проектов, папку `libs/`. Перенесите в неё модули `stdio-text-protocol`, `profiling`, `device` и `logging`. Каждую библиотеку разложите одинаково:

```
libs/device/
├── CMakeLists.txt
├── include/
│   └── device/
│       └── device.h       интерфейс
└── src/
    └── device.c           реализация
```

Сборку библиотеки описывают три функции. Их смысл разобран в [[т2.3.6 Библиотека в сборке#^intro|т2.3.6]].

```cmake
add_library(device STATIC
    src/device.c
)

target_include_directories(device PUBLIC
    include
)

target_link_libraries(device PRIVATE
    pico_stdlib
    pico_unique_id
)
```

Тип платы `DEVICE_BOARD` библиотека `device` получает сама: перенесите в её `CMakeLists.txt` строку `target_compile_definitions()` из проекта.

Заголовок теперь подключается с именем библиотеки: `#include "device/device.h"`. Путь `include` открыт всем пользователям библиотеки, а папка `device` внутри не даёт столкнуться заголовкам разных библиотек с одинаковым именем.

Цель сборки называется так же, как папка библиотеки. Исключение составляет протокол. Его цель называется `stdio_text_protocol`, с подчёркиваниями вместо дефисов. Так её называет часть 2 ТЗ.

Создайте `libs/CMakeLists.txt`. Он добавляет к сборке каждую библиотеку строкой `add_subdirectory(<имя>)`.

>[!warning] Библиотекам с SDK нужен pico_stdlib
>Протоколу нужен стандартный ввод-вывод SDK. Подключайте ему `pico_stdlib` целиком: `pico_stdio` без него не собирается.

### 2. Перенести константы прошивки

Имя и версия прошивки, имя проекта и адрес репозитория принадлежат прибору, а не библиотеке. Перенесите их из `device.h` в файл `firmware.h` в папке проекта. Префикс `DEVICE_` им больше не подходит, назовите их `FIRMWARE_NAME`, `FIRMWARE_VERSION`, `FIRMWARE_PROJECT` и `FIRMWARE_REPO`. Обработчик `info` и `main.c` подключают `firmware.h`.

### 3. Создать библиотеку systime

Библиотека `systime` даёт время с момента сброса и проверку периода для задач.

```c
uint64_t systime_us(void);
uint64_t systime_ms(void);
bool systime_period_elapsed(uint64_t *last_us, uint64_t period_us);
```

Перенесите в неё `period_elapsed()` из задачи светодиода. Переведите задачи и команду `uptime` с функций времени SDK на `systime`. После этого код проекта читает часы только через `systime`.

### 4. Подключить libs к проекту

`libs/` лежит вне папки проекта. Поэтому `add_subdirectory()` нужен второй аргумент. Он задаёт каталог сборки для этой папки. Добавьте в `CMakeLists.txt` проекта после `pico_sdk_init()`:

```cmake
# libs лежит вне папки проекта: второй аргумент задаёт каталог сборки
add_subdirectory(../libs ${CMAKE_BINARY_DIR}/libs)
```

Уберите исходники библиотек из `add_executable()` и их папки из `target_include_directories()`. Библиотеки подключаются по именам в `target_link_libraries()`. Строку `add_compile_options(-Wall)` поставьте до `add_subdirectory()`, тогда ключ получат и библиотеки.

### 5. Выключатель профилирования

Каждый вызов секундомера стоит десятки команд. В готовом приборе их можно убрать целиком, не трогая код. В `profiling.h` задайте значение по умолчанию и пустые макросы для выключенной сборки, как в [[т2.3.6 Библиотека в сборке#^intro|т2.3.6]]:

```c
// по умолчанию профилирование включено
#ifndef PROFILING_ENABLED
#define PROFILING_ENABLED 1
#endif

#if PROFILING_ENABLED
void profiling_start(uint32_t id);
void profiling_stop(uint32_t id);
#else
// профилирование выключено: вызовы ничего не делают
#define profiling_start(id) ((void)0)
#define profiling_stop(id) ((void)0)
#endif
```

В `CMakeLists.txt` проекта после подключения `libs` добавьте выключатель:

```cmake
# выключатель профилирования: 0 — вызовов секундомеров в образе нет
target_compile_definitions(profiling PUBLIC
    PROFILING_ENABLED=1
)
```

Определение `PUBLIC`, поэтому одно значение видят и `profiling.c`, и все, кто подключает `profiling.h`. Определения `profiling_start()` и `profiling_stop()` в `profiling.c` обрамите тем же `#if PROFILING_ENABLED`. Команда `profiling` в выключенной сборке отвечает `profiling is disabled in this build`.

Сравните размеры `build/231_firmware_template.bin` в двух сборках. У нас вышло 37 472 байта с профилированием и 36 920 без него.

Скопируйте [[check-2-3-6.yml]] в `.github/workflows`. Добавьте в `README.md` строку со значком этой проверки.

``` bash
git add --all
git commit -m "Сделана п2.3.6"
git push
```
