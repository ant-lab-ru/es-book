## Задание

### Что должно получиться

- [ ] Модуль `platform` собран библиотекой: номера выводов и подключение кнопки знает только он
- [ ] Задачи и `api` лежат в `logic/` и собираются библиотекой `logic` без SDK
- [ ] Задача кнопки сообщает о нажатии функцией, переданной при запуске, и не подключает заголовок `led-task`
- [ ] В `api.c` остался механизм поиска команды, `help` и ответы на ошибки кадра, обработчики и таблица лежат в `api-callbacks.c`
- [ ] `main.c` не подключает заголовков SDK
- [ ] Функции и переменные, которых нет в заголовке, определены со `static`, файл `.c` подключает свой заголовок первым
- [ ] Коммит отправлен, проверка `2.3.7` зелёная

### Как проверить

1. **Прибор работает как прежде.** Все команды, кнопка, мигание и расчёт π работают так же, как до изменений.
2. **Граница проверяется сборкой.** Добавьте `#include "pico/stdlib.h"` в `logic/led-task/led-task.c` или в `logic/api/api.c`. Сборка останавливается. Уберите строку.
3. **Ответьте на контрольные вопросы** [[ТЗ 2.3 Прибор#Контрольные вопросы|части 1 ТЗ]]. Каждый ответ называет одно-два места из правил части 2.
4. **Автоматическая проверка курса принимает задание.** Проверка статическая. Она проверяет раскладку по части 2 ТЗ и интерфейс `platform`. В `CMakeLists.txt` она ищет библиотеки `platform` и `logic` и убеждается, что `logic` подключает протокол как `PUBLIC`, а SDK не подключает вовсе. В коде `logic/` убеждается, что нет ни заголовков SDK, ни `gpio_`, ни `time_us_`. В `api.c` ищет, что из имён команд там только `help`, а в `api-callbacks.c` — что все функции со `static`. Ещё она проверяет правила заголовков: `#pragma once`, свой заголовок первым, задачи не подключают заголовки друг друга.

## Ход работы

Теория задания — [[т2.3.7 Границы модулей#^intro|т2.3.7]] и [[т2.3.5 Программный модуль на C#^intro|т2.3.5]]. Модули проекта и правила описаны в разделах 3 и 4 [[ТЗ 2.3 Шаблон проектирования|части 2 технического задания]].

### 1. Собрать железо в platform

Создайте папку `platform` с файлами `platform.h` и `platform.c`:

```c
#pragma once

#include <stdbool.h>

// запускает стандартный ввод-вывод и настраивает выводы
void platform_init(void);

void platform_led_set(bool on);

// нажата ли кнопка сейчас, без подавления дребезга
bool platform_button_read(void);
```

Номера выводов светодиода и кнопки задайте только в `platform.c`. То, что нажатая кнопка даёт на выводе ноль, тоже знает только `platform.c`. Логики в `platform` нет, каждая функция занимает одну-две строки.

Переведите `led-task` на `platform_led_set()`, `button-task` на `platform_button_read()`, а `main.c` на `platform_init()`.

### 2. Разделить api на механизм и содержание

Механизм поиска команд от прибора не зависит. Обработчики и таблица составляют содержание этого прибора. Разделите `api` на три файла:

| Файл | Что в нём |
| --- | --- |
| `api.c` | `api_handle()`: ответ на команду с пометкой `truncated`, `help`, поиск по таблице, ответ на неизвестную команду |
| `api-callbacks.c` | обработчики команд со `static` и таблица команд прибора |
| `api-commands.h` | тип записи таблицы и объявление таблицы, внутренний заголовок модуля |

Таблица лежит в `api-callbacks.c` рядом с обработчиками, поэтому обработчики остаются `static`. Новая команда требует одной правки в одном файле. Таблицу видит `api.c` через объявление в `api-commands.h`:

```c
extern const api_command_t api_commands[];
extern const uint32_t api_command_count;
```

`extern` объявляет переменную, определённую в другом файле. Открывать так изменяемые переменные нельзя: их сможет поменять любой файл. Константную таблицу можно, это разобрано в [[т2.3.5 Программный модуль на C#^intro|т2.3.5]].

`api-commands.h` подключают только `api.c` и `api-callbacks.c`. Для остальных интерфейс модуля по-прежнему задаёт `api.h`.

### 3. Собрать логику библиотекой

Перенесите `api`, `led-task`, `button-task` и `pi-task` в папку `logic/`. Соберите их библиотекой `logic` в `CMakeLists.txt` проекта. Модуль `platform` соберите библиотекой там же.

>[!success] Должно получиться так
> ```cmake
> # железо прибора: единственное место проекта с SDK
> add_library(platform STATIC
>     platform/platform.c
> )
> # путь к заголовкам — папка проекта, platform подключает pico_stdlib как PRIVATE;
> # через этот путь logic находит и firmware.h
>
> # логика прибора: задачи и команды, без SDK
> add_library(logic STATIC
>     # исходники api, led-task, button-task и pi-task
> )
> # путь к заголовкам — папка logic
> # stdio_text_protocol — PUBLIC, остальные библиотеки — PRIVATE
>
> add_executable(${PROJECT_NAME}
>     main.c
> )
> ```

| Что нужно написать | Где это разбиралось |
| --- | --- |
| `add_library`, `target_include_directories`, `target_link_libraries` | [[п2.3.6 Библиотеки#1. Разложить модули по библиотекам\|п2.3.6, шаг 1]] |
| Почему `stdio_text_protocol` подключается как `PUBLIC` | [[т2.3.8 Протокол и API прибора#^intro\|т2.3.8]] |

Заголовки теперь подключаются с именем модуля: `#include "led-task/led-task.h"`, `#include "api/api.h"`.

### 4. Отвязать кнопку от светодиода

Задача кнопки пока сама вызывает функцию светодиода. Что делает нажатие, решает прибор в целом, а не кнопка. Пусть задача кнопки получает при запуске функцию, которую вызовет на каждое нажатие, и знает о ней только сигнатуру:

```c
// функция, которую задача вызывает на каждое нажатие
typedef void (*button_task_callback_t)(void);

void button_task_init(button_task_callback_t on_press);
```

Заголовок `led-task` задача кнопки больше не подключает. Связь кнопки со светодиодом задаёт `main.c` строкой `button_task_init(led_task_next_state)`.

| Что нужно написать | Где это разбиралось |
| --- | --- |
| Указатель на функцию как параметр и вызов по нему с проверкой на `NULL` | [[т2.1.7 Указатели на функции#^intro\|т2.1.7]] |
| Почему кнопка сообщает о нажатии функцией | [[т2.3.7 Границы модулей#^intro\|т2.3.7]] |

### 5. Убрать SDK из main.c

`main.c` только запускает модули, связывает их, заводит секундомеры и вызывает обработчики в суперцикле. Ни одного заголовка SDK он не подключает.

>[!success] Должно получиться так
> ```c
> int main()
> {
>     platform_init();
>
>     // журнал: имя и версия прошивки; секундомеры
>     // запуск протокола и задач
>
>     // нажатие переводит светодиод в следующее состояние
>     button_task_init(led_task_next_state);
>
>     while (1)
>     {
>         // команда из протокола — в api; обработчики задач под секундомерами
>     }
> }
> ```

Сборкой это не проверить. Прошивке всё равно нужен `pico_stdlib` ради кода запуска SDK до `main()`, и пути к его заголовкам видны `main.c`. Здесь граница держится правилом П7.

### 6. Навести порядок в модулях

Пройдите по каждому модулю проекта и правилам П9–П11 части 2:

- функции и переменные вне функций, которых нет в заголовке, определены со `static`;
- каждый файл `.c` подключает свой заголовок первым, тогда сборка сама проверит, что заголовок подключает всё нужное ему;
- задачи не подключают заголовков друг друга.
