## Ход работы

>[!warning] Что понадобится из железа
>Тактовая кнопка, макетная плата, два провода «папа–мама».

### 1. Собрать схему

Возьмите вывод `GP15` — это физический вывод `20`, угловой в левом ряду платы, если смотреть на неё разъёмом USB вверх. Земля рядом: вывод `18`.

Соедините кнопку так, чтобы при нажатии она замыкала `GP15` на землю:

```
   GP15 (вывод 20) ──────┐
                       [кнопка]
   GND  (вывод 18) ──────┘
```

Тактовая кнопка имеет четыре ножки, попарно соединённые внутри. Ставьте её через канавку макетной платы: тогда пары гарантированно окажутся в разных половинах, и вы не замкнёте контакт сам на себя.

>[!bug] Светодиод переключается сам по себе, без нажатия
>Скорее всего, кнопка вставлена вдоль канавки, а не поперёк — тогда её ножки замкнуты постоянно. Разверните её на 90°.

### 2. Понять, что читает вывод

Пока кнопка не нажата, `GP15` ни к чему не подключён — на нём нет ни нуля, ни единицы, и читаться будет случайный мусор. Чтобы этого не было, внутри микроконтроллера есть **подтягивающий резистор**: он мягко притягивает вывод к питанию, и незанятый вход читается как единица.

Тогда картина получается такая:

| Кнопка | Что на выводе | Что вернёт `gpio_get()` |
| --- | --- | --- |
| не нажата | подтяжка тянет к питанию | `true` |
| нажата | замкнут на землю | `false` |

Логика перевёрнута относительно интуиции: нажатой кнопке соответствует `false`. Так устроено почти во всей схемотехнике, и привыкнуть к этому лучше сразу.

>[!info] Почему подтяжка к питанию, а не к земле
>Можно и наоборот — подтянуть вывод к земле, а кнопкой подавать на него питание. Обе схемы рабочие. Подтяжка к питанию распространена шире: замыкать на землю проще и безопаснее, чем разводить питание к каждой кнопке.

### 3. Написать программу

Создайте проект `122-led-button` по образцу `121-blink-reg`, как в [[п1.2.1 Мигание светодиодом через регистр#1. Создать проект по образцу\|п1.2.1, шаг 1]]. Новая папка, четыре файла без папки `build` и имя проекта в `CMakeLists.txt` через переменную `${PROJECT_NAME}`.

**Настройте вывод светодиода** — так же, как в [[п1.1.2 Первый проект#3. Написать main.c\|п1.1.2, шаг 3]]. Объявите константу вывода, инициализируйте его и задайте направление `GPIO_OUT`.

**Настройте вывод кнопки.** Здесь всё новое: направление противоположное, и добавляется подтяжка.

Объявите константу рядом с константой светодиода:

``` c
const uint BUTTON_PIN = 15;
```

Вызовите три функции в начале `main()`:

``` c
    gpio_init(BUTTON_PIN);
    gpio_set_dir(BUTTON_PIN, GPIO_IN);
    gpio_pull_up(BUTTON_PIN);
```

`GPIO_IN` означает, что микроконтроллер будет напряжение считывать, а не выдавать. `gpio_pull_up()` включает тот самый подтягивающий резистор, из-за которого отпущенная кнопка читается как `true`.

**Объявите две переменные.** Одна будет помнить, светит ли светодиод; вторая — что вывод показывал на прошлом шаге цикла:

``` c
    bool led = false;
    bool previous = false;
```

**Проверяйте не состояние, а его смену.** Суперцикл крутится тысячи раз в секунду. Если переключать светодиод, пока кнопка нажата, он будет мигать всё время нажатия. Переключать нужно **в момент**, когда вывод перешёл из единицы в ноль, то есть когда кнопку нажали:

``` c
    while (1)
    {
        bool current = gpio_get(BUTTON_PIN);

        if (previous == true && current == false)
        {
            led = !led;
            gpio_put(LED_PIN, led);
        }

        previous = current;
    }
```

Обратите внимание, на что опирается условие: не на «кнопка нажата», а на то, что с вывода читается `true` или `false`. Это то, что можно проверить мультиметром, а «нажата» — уже наше толкование.

### 4. Собрать, записать и понажимать

Соберите проект, запишите `.uf2` на плату и нажмите на кнопку десяток раз, считая переключения.

>[!success] Должно получиться так
>Кнопка переключает светодиод — но не каждый раз. Иногда одно нажатие даёт два переключения, и светодиод возвращается в прежнее состояние.
>
>*Здесь будет GIF: `123-led-button.gif`.*

Программа написана правильно, и всё же ведёт себя нестабильно. Причина не в коде, а в физике контакта: пружинящие пластины кнопки при замыкании несколько раз отскакивают друг от друга, и вывод за доли миллисекунды успевает несколько раз перейти из единицы в ноль и обратно. Каждый такой переход ваш суперцикл честно считает нажатием.

Это и называется **дребезгом контактов**. Следующее задание — про то, как с ним быть.
