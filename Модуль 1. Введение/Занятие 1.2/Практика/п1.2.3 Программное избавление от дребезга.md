## Ход работы

>[!info] Что здесь на самом деле происходит
>Программа из прошлого задания правильна по логике: она честно ловит переход из единицы в ноль. Ошибки в ней нет. Нестабильной её делает физика: контакт дребезжит, и переходов оказывается несколько вместо одного.
>
>Это встретится вам ещё много раз. Код, верный на бумаге, и код, работающий на железе, — не одно и то же, и разница обычно прячется в деталях, которых на бумаге не видно.

### 1. Создать проект по образцу

Создайте папку `123-led-button-debounce` и скопируйте в неё четыре файла проекта `122-led-button` — папку `build` не копируйте.

``` bash
cd ~/Repositories/pico/es-student
mkdir 123-led-button-debounce
cp 122-led-button/CMakeLists.txt 123-led-button-debounce
cp 122-led-button/main.c 123-led-button-debounce
cp 122-led-button/memmap_rp2040.ld 123-led-button-debounce
cp 122-led-button/pico_sdk_import.cmake 123-led-button-debounce
cd 123-led-button-debounce
```

Впишите новое имя в `project()` — остальные команды `CMakeLists.txt` возьмут его из `${PROJECT_NAME}`:

``` cmake
project(123_led_button_debounce)
```

Схему на макетной плате не трогайте — она остаётся прежней.

### 2. Придумать, как отличить дребезг от нажатия

Дребезг — это скачки уровня, которые длятся считаные миллисекунды. Настоящее нажатие — это уровень, который держится, пока палец на кнопке, то есть десятые доли секунды как минимум.

Отсюда способ: прочитать вывод, немного подождать и прочитать снова. Совпали — уровень настоящий. Не совпали — попали в дребезг.

Двадцати миллисекунд достаточно: дребезг к этому времени заканчивается, а для человека такая задержка незаметна.

### 3. Вынести чтение в отдельную функцию

Заведите константу задержки и функцию, которая читает вывод устойчиво:

``` c
const uint DEBOUNCE_MS = 20;

bool get_button_debounce(uint pin)
{
    bool state = gpio_get(pin);
    sleep_ms(DEBOUNCE_MS);
    return state && gpio_get(pin);
}
```

Читается она так: «уровень считается высоким, только если он высок сейчас и всё ещё высок через двадцать миллисекунд». В любом другом случае функция вернёт `false`.

Теперь в суперцикле замените прямое чтение вывода вызовом функции. Больше в программе не меняется ничего:

``` c
        bool current = get_button_debounce(BUTTON_PIN);
```

>[!info] Зачем отдельная функция, а не три строки внутри цикла
>Строки можно было вписать прямо в суперцикл, и работало бы так же. Но у функции есть имя, и это имя говорит, что происходит: читается кнопка, устойчиво. Суперцикл остаётся про свою задачу — «сменился уровень, переключи светодиод», — и не разрастается подробностями чтения.
>
>В программе на тридцать строк разница невелика. К модулю 3 в суперцикле будет с десяток таких задач, и вот тогда без разделения на части в нём станет не разобраться. Привычку удобнее заводить сейчас, пока цена ошибки — три строки.
