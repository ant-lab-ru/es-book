**Результат** — прибор `231-firmware-template` принимает команды по протоколу из [[ТЗ 2.3 Приложение А. Протокол|приложения А]]. Модуль `stdio-text-protocol` собирает строку и делит её на имя команды и аргументы. Модуль `api` находит команду в таблице и выполняет её. Команда `help` перечисляет все команды прибора со справкой.

Схема из раздела [[т2.3.8 Протокол и API прибора#^intro|Протокол и API прибора]] показывает путь команды через весь шаблон. В этом задании появляются первые два его звена, протокол и `api`. Связывает их `main.c`.

## Задание

### Что должно получиться

- [ ] Проект `231-firmware-template` создан по образу `221-command-time`, опыты занятий 2.1 и 2.2 из него убраны
- [ ] Протокол `stdio-text-protocol` за вызов читает не больше одного символа, повторяет его в терминал и по концу строки возвращает команду с именем и аргументами
- [ ] Модуль `api` находит команду в таблице, у каждой команды есть справка, `help` перечисляет их все
- [ ] Ошибки отвечают строкой, которая начинается с `error:`, как требует приложение А
- [ ] `calc_pi` принимает число членов ряда аргументом, ошибки в записи числа отклоняются
- [ ] Коммит отправлен, проверка `2.3.1` зелёная

### Как проверить

1. **Команды отвечают по протоколу.** Наберите `help`, `info`, `uptime`, `calc_pi 100000`. Наберите команду с лишними пробелами в начале, в конце и между словами. Наберите команду с опечаткой и исправьте её клавишей Backspace. Всё это выполняется.
2. **Ошибки отклоняются.** Строка длиннее 63 символов, команда с пятью аргументами и неизвестная команда отвечают строкой `error:` и ничего не выполняют.
3. **Автоматическая проверка курса принимает задание.** Проверка статическая, прибор она не запускает. Она ищет файлы модулей по имени: в следующих заданиях модули переедут, и проверка их найдёт. В заголовке протокола она ищет тип `command_t` с полями `name`, `argc`, `argv` и `truncated`. В коде протокола ищет `getchar_timeout_us(0)` и обработку Backspace и убеждается, что в нём нет ни одного имени команды. В `api` ищет `api_handle()`, тип записи таблицы, команду `help`, ответ `error: unknown command` и разбор числа через `strtoul()`. В `main.c` ищет передачу команды из протокола в `api` и убеждается, что чтения символов и буфера строки там больше нет.

## Ход работы

Теория задания — [[т2.3.8 Протокол и API прибора#^intro|т2.3.8]]. Требования к прибору записаны в [[ТЗ 2.3 Прибор|части 1 технического задания]] и в приложениях А и Б.

>[!warning] Задания занятия устроены иначе
>С этого занятия задание описывает, что должно появиться в приборе и где это разобрано в теории. Пошагового кода больше нет. Новые для курса средства языка и сборки даются дословно один раз. Всё остальное вы пишете сами по логике программы и по ссылкам.

### 1. Создать проект

Скопируйте папку `221-command-time` в `231-firmware-template`. Удалите из копии папку `build`. В `CMakeLists.txt` задайте имя проекта `231_firmware_template`.

Уберите опыты занятий 2.1 и 2.2. В шаблон прибора они не входят:

- модули `memory` и `clock`, команды `mem_info`, `fw_info`, `boot_info`, `dev_info`, `clk_info`, `clk_sys_low` и `clk_sys_default`;
- функцию `dev_info()` и структуру `device_card` из модуля `device`;
- свой линкер-скрипт `memmap_rp2040.ld` и строку `pico_set_linker_script()`;
- команды `version` и `ping`, их нет в [[ТЗ 2.3 Приложение Б. Команды|приложении Б]].

Функция `uptime()` уходит вместе с модулем `clock`, а команда `uptime` остаётся. Её обработчик печатает `uptime: <время> ms`, время равно `time_us_64() / 1000`. В `device.h` задайте имя проекта `231-firmware-template`, своё имя прошивки и версию. Паспорт по приложению Б начинается с имени и версии, добавьте эти две строки в начало ответа `info`.

### 2. Написать протокол

Создайте папку `stdio-text-protocol` с файлами `stdio-text-protocol.h` и `stdio-text-protocol.c`. Заголовок задаёт интерфейс протокола. Его требует [[ТЗ 2.3 Шаблон проектирования|часть 2 технического задания]], поэтому он дан целиком:

```c
#pragma once

#include <stdbool.h>
#include <stdint.h>

#define STDIO_TEXT_PROTOCOL_LINE_SIZE 64
#define STDIO_TEXT_PROTOCOL_MAX_ARGS 4

// команда, принятая из одной строки
typedef struct
{
    const char *name;
    uint32_t argc;
    const char *argv[STDIO_TEXT_PROTOCOL_MAX_ARGS];

    // строка длиннее буфера или аргументов больше, чем помещается в argv:
    // команда принята не целиком, выполнять её нельзя
    bool truncated;
} command_t;

void stdio_text_protocol_init(void);

// Читает один символ, не ожидая его. Когда строка закончена, возвращает
// команду, иначе NULL. Команда действительна до следующего вызова.
const command_t *stdio_text_protocol_handle(void);
```

Буфер на 64 байта вмещает 63 символа и нулевой символ в конце. Как протокол обращается с каждым принятым символом, задаёт таблица раздела 4 [[ТЗ 2.3 Приложение А. Протокол|приложения А]]. Строку на слова протокол делит на месте. Пробелы он заменяет нулевыми символами, а в `name` и `argv` записывает указатели на начала слов. Поэтому команда и живёт только до следующего вызова: следующая строка ляжет в тот же буфер. Подробно это разобрано в [[т2.3.8 Протокол и API прибора#^intro|т2.3.8]].

>[!success] Должно получиться так
> ```c
> const command_t *stdio_text_protocol_handle(void)
> {
>     // читаем символ без ожидания; нет символа — возвращаем NULL
>
>     // конец строки: пустую строку пропускаем, иначе переводим строку в терминале,
>     // делим строку на слова и возвращаем команду
>
>     // Backspace (0x08 или 0x7f): убираем последний символ и стираем его на экране "\b \b"
>
>     // печатный символ: кладём в буфер и повторяем в терминал;
>     // буфер полон — помечаем строку как переполненную
> }
> ```

### 3. Написать модуль api

Создайте папку `api` с файлами `api.h` и `api.c`. В `api.h` объявите одну функцию `void api_handle(const command_t *command)`. Тип `command_t` заголовок берёт из `stdio-text-protocol.h`.

Перенесите в `api.c` таблицу команд и обработчики из `main.c`. Файл `command.h` больше не нужен, удалите его. Запись таблицы описывает тип `api_command_t` с полями `name`, `help` и `callback`. Обработчик получает команду целиком, `const command_t *`. Оба типа приведены в [[т2.3.8 Протокол и API прибора#^intro|т2.3.8]]. Справку на английском языке напишите у каждой команды. Её выводит `help`.

`api_handle()` проверяет команду в том порядке, который разобран в [[т2.3.8 Протокол и API прибора#^intro|т2.3.8]]:

1. Команду с пометкой `truncated` она не выполняет и отвечает `error: command longer than 63 characters or 4 arguments`.
2. Команду `help` она выполняет сама. Печатает строку о себе, а за ней имена и справку всех команд таблицы.
3. Если имя есть в таблице, вызывает его обработчик.
4. Если имени в таблице нет, отвечает `error: unknown command '<имя>', try help`.

Поэтому в таблице `help` нет. Справку она берёт из самой таблицы, и отдельный список команд не нужен.

Команде `calc_pi` дайте необязательный аргумент, число членов ряда. Число из строки разбирает функция `parse_u32()` на `strtoul()`, её код и разбор есть в [[т2.3.8 Протокол и API прибора#^intro|т2.3.8]]. Ошибки отвечают по приложению Б, как у `pi_start`. `error: usage calc_pi [terms]` на неверную запись и лишние аргументы, отдельное сообщение на ноль. Значение π печатайте с 9 знаками после точки, как в ответе `pi` из приложения Б.

>[!info] Почему не sscanf()
>Число можно разобрать и одной строкой `sscanf(text, "%lu%c", &number, &extra)`. Попробуйте и сравните размер `.bin`. У нас вышло 89 900 байт со `sscanf()` против 35 152 со `strtoul()`. Функция форматного ввода умеет разбирать любой формат, и весь этот код попадает в образ. С ней прибор не уложился бы в норму Н3, 48 КБ.

### 4. Связать протокол и api

Суперцикл только передаёт команду из протокола в `api`. Перед суперциклом вызовите `stdio_text_protocol_init()`. Функции `read_line()` и `handle_command()` из `main.c` больше не нужны.

>[!success] Должно получиться так
> ```c
> // принятая строка становится командой, команда — действием прибора
> const command_t *command = stdio_text_protocol_handle();
> if (command != NULL)
> {
>     api_handle(command);
> }
> ```

Добавьте новые файлы в `add_executable()`, а папки `stdio-text-protocol` и `api` добавьте в `target_include_directories()`.
