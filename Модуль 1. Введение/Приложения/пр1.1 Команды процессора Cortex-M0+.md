Это приложение к разделу [[т1.2.4 Внутреннее устройство. Процессор#^intro|«Внутреннее устройство. Процессор»]]. Там мы выяснили, что ядру Cortex-M0+ доступен набор всего из 56 команд, и посмотрели три из них — `ADD`, `LDR`, `STR`. Здесь разберём этот набор целиком: какие команды бывают, как команда выглядит в памяти, чего в наборе нет и почему это заметно даже в программе на **C**. Материал не нужен для выполнения заданий занятия 1.2 — он для тех, кто хочет увидеть, из чего в действительности собрана прошивка.

## Все 56 команд

Начнём с общей картины. Ниже — схема всего набора, сгруппированная по назначению. Заучивать её не нужно — важнее увидеть пропорции: сколько команд занято переносом данных, сколько вычислениями, сколько управлением ходом программы.

![[Набор команд ARMv6-M.excalidraw|100%]]

Первое, что бросается в глаза, — на собственно вычисления приходится меньше половины набора: 25 команд из 56. Ещё шестнадцать заняты только тем, что переносят данные между памятью и регистрами. Это прямое следствие устройства ядра, о котором шла речь в основном разделе: арифметические операции ядро может выполнять только с данными из регистров процессора и класть результат может только в них, а данные лежат в памяти, поэтому любое вычисление обрамлено чтениями и записями. Причём команд обмена так много не потому, что они делают разное, а потому, что каждая работает со своим размером данных: `LDR` читает [[Машинное слово#^def|слово]] (4 байта), `LDRH` — полуслово (2 байта), `LDRB` — байт, а `LDRSB` и `LDRSH` вдобавок расширяют знак прочитанного числа до 32 бит.

Второе — команд перехода всего четыре, и на них держится вся логика программы. Любой `if`, любой цикл, любой вызов функции из вашего кода компилятор превращает в `B`, `BL`, `BX` или `BLX`. Условность при этом заложена в саму команду `B`: она записывается с суффиксом условия — `BEQ` (если равно), `BNE` (если не равно), `BLT` (если меньше) и так далее. Само условие проверяется по флагам, а флаги выставляет предыдущая команда — как раз та, у которой есть суффикс `S`. Отсюда `ADDS` вместо `ADD` и `SUBS` вместо `SUB`: буква `S` означает «выполнить действие и обновить флаги». Пара «команда с `S` — условный переход» и есть весь механизм ветвления в ARMv6-M.

### Что делает каждая команда

Схема отвечает на вопрос «сколько чего», но не говорит, что именно делает `LDRSH` или `BICS`. Ниже — весь набор с кратким описанием, в том же порядке и по тем же группам. Читать подряд не нужно: таблица нужна, чтобы вернуться к ней, встретив незнакомую команду в выводе дизассемблера.

Запись команд дана в обозначениях, принятых в документации ARM: `Rd` — регистр-приёмник, куда попадает результат; `Rn` и `Rm` — регистры-операнды; `#imm` — число, записанное прямо в команде. Приёмник всегда стоит первым, поэтому `ADDS Rd, Rn, Rm` читается как «сложить `Rn` и `Rm`, результат положить в `Rd`». Суффикс `S`, как уже говорилось, означает «вдобавок обновить флаги».

Шестнадцать команд переноса данных не вычисляют ничего — они только перемещают числа между памятью и регистрами. Различаются они размером порции и тем, как короткое число дополняется до 32 бит:

| Команда | Что делает |
| --- | --- |
| `LDR Rt, [Rn, #imm]` | прочитать из памяти слово (4 байта) в регистр |
| `LDRH Rt, [Rn, #imm]` | прочитать полуслово (2 байта), старшие биты заполнить нулями |
| `LDRB Rt, [Rn, #imm]` | прочитать байт, старшие биты заполнить нулями |
| `LDRSH Rt, [Rn, Rm]` | прочитать полуслово и расширить его знак до 32 бит |
| `LDRSB Rt, [Rn, Rm]` | прочитать байт и расширить его знак до 32 бит |
| `STR Rt, [Rn, #imm]` | записать в память слово из регистра |
| `STRH Rt, [Rn, #imm]` | записать младшее полуслово регистра |
| `STRB Rt, [Rn, #imm]` | записать младший байт регистра |
| `LDM Rn!, {список}` | прочитать подряд несколько слов в перечисленные регистры |
| `STM Rn!, {список}` | записать подряд в память несколько регистров |
| `PUSH {список}` | положить перечисленные регистры на [[Стек#^def\|стек]] |
| `POP {список}` | снять со стека сохранённые там регистры |
| `ADR Rd, метка` | вычислить адрес метки и положить его в регистр |
| `MOV/MOVS Rd, Rm` | скопировать число из регистра или записать `#imm` в регистр |
| `MRS Rd, спецрегистр` | прочитать специальный регистр ядра — например, регистр флагов |
| `MSR спецрегистр, Rn` | записать значение в специальный регистр ядра |

Двадцать пять команд вычислений — это всё, что ядро умеет считать само. Обратите внимание на `CMP`, `CMN` и `TST`: они выполняют действие, но результат не сохраняют, а нужны только ради флагов, по которым потом сработает условный переход.

| Команда | Что делает |
| --- | --- |
| `ADD/ADDS Rd, Rn, Rm` | сложить два числа |
| `ADCS Rd, Rm` | сложить с учётом переноса — для чисел длиннее 32 бит |
| `SUB/SUBS Rd, Rn, Rm` | вычесть |
| `SBCS Rd, Rm` | вычесть с учётом заёма — для чисел длиннее 32 бит |
| `RSBS Rd, Rn, #0` | вычесть из нуля, то есть сменить знак числа |
| `MULS Rd, Rn` | перемножить; сохраняются только младшие 32 бита произведения |
| `CMP Rn, Rm` | сравнить: вычесть, результат отбросить, выставить флаги |
| `CMN Rn, Rm` | сравнить сложением: сложить, результат отбросить, выставить флаги |
| `ANDS Rd, Rm` | побитовое И |
| `ORRS Rd, Rm` | побитовое ИЛИ |
| `EORS Rd, Rm` | побитовое исключающее ИЛИ |
| `BICS Rd, Rm` | сбросить биты по маске: `Rd И НЕ Rm` |
| `MVNS Rd, Rm` | инвертировать все биты |
| `TST Rn, Rm` | проверить биты: И, результат отбросить, выставить флаги |
| `LSLS Rd, Rm, #imm` | сдвиг влево — умножение на степень двойки |
| `LSRS Rd, Rm, #imm` | сдвиг вправо, слева вдвигаются нули |
| `ASRS Rd, Rm, #imm` | сдвиг вправо с сохранением знака — деление на степень двойки |
| `RORS Rd, Rm` | циклический сдвиг вправо: выпавшие биты возвращаются слева |
| `SXTB Rd, Rm` | взять младший байт и расширить его знак до 32 бит |
| `SXTH Rd, Rm` | взять младшее полуслово и расширить его знак |
| `UXTB Rd, Rm` | взять младший байт, остальные биты обнулить |
| `UXTH Rd, Rm` | взять младшее полуслово, остальные биты обнулить |
| `REV Rd, Rm` | переставить байты слова в обратном порядке |
| `REV16 Rd, Rm` | переставить байты внутри каждого полуслова |
| `REVSH Rd, Rm` | переставить байты младшего полуслова и расширить знак |

Оставшиеся пятнадцать команд не считают и не переносят данные: четыре управляют ходом программы, одиннадцать обслуживают само ядро — режимы работы, прерывания, взаимодействие с отладчиком.

| Команда | Что делает |
| --- | --- |
| `B метка` | перейти к метке; с суффиксом условия (`BEQ`, `BNE`, `BLT`) — только при выполнении условия |
| `BL метка` | вызвать подпрограмму: перейти, сохранив адрес возврата в `lr` |
| `BX Rm` | перейти по адресу из регистра; `BX lr` — возврат из подпрограммы |
| `BLX Rm` | вызвать подпрограмму по адресу из регистра |
| `NOP` | не делать ничего, потратив один такт |
| `SVC #imm` | вызвать программное прерывание — обращение к системному коду |
| `BKPT #imm` | точка останова: передать управление отладчику |
| `CPS` | запретить или разрешить прерывания |
| `WFI` | остановить ядро до прихода прерывания — режим энергосбережения |
| `WFE` | остановить ядро до наступления события |
| `SEV` | послать событие второму ядру, ожидающему в `WFE` |
| `YIELD` | подсказка «задача может уступить время»; на Cortex-M0+ выполняется как `NOP` |
| `DMB` | барьер данных: не начинать следующие обращения к памяти, пока не завершены предыдущие |
| `DSB` | барьер синхронизации: дождаться завершения всех обращений к памяти |
| `ISB` | барьер команд: сбросить конвейер и перечитать команды заново |

Три последние команды — барьеры — на первый взгляд выглядят странно: зачем процессору команда «ничего не делать, пока не закончится начатое»? Они нужны там, где порядок обращений к памяти важен сам по себе: при работе с регистрами периферии, при переключении режимов ядра и при обмене между двумя ядрами RP2040. В обычном коде на **C** они не встречаются — их расставляет SDK.

## Команда — это число

Во всех таблицах выше команды записаны словами: `ADD`, `LDR`, `STR`. Но в памяти микроконтроллера слов нет — там лежат числа. Каждой команде соответствует своё число, и именно его ядро выбирает из памяти на первом шаге цикла «выборка — декодирование — исполнение». Такое число называют **машинным кодом** команды.

Число это не произвольное: оно составлено из полей. Одни биты задают, какая это команда, другие — с какими регистрами она работает. Возьмём уже знакомую команду сложения `ADDS r0, r1, r2`. В машинном коде она занимает 16 бит и раскладывается так:

![[Команда в машинном коде.excalidraw|100%]]

Собрав биты вместе, получим число `0x1888`. Именно оно и лежит в памяти. При декодировании ядро разбирает старшие семь бит, опознаёт по ним сложение регистров, а из трёх трёхбитных полей достаёт номера регистров-операндов и регистра-результата.

Вот ещё несколько команд рядом с их машинными кодами:

| Команда на ассемблере | Машинный код | Что делает |
| --------------------- | ------------ | ---------- |
| `MOVS r0, #1`         | `0x2001`     | положить число 1 в регистр `r0` |
| `ADDS r0, r1, r2`     | `0x1888`     | сложить `r1` и `r2`, результат — в `r0` |
| `STR  r0, [r1]`       | `0x6008`     | записать содержимое `r0` в память по адресу из `r1` |
| `BX   lr`             | `0x4770`     | вернуться из подпрограммы |

Обратите внимание: все четыре команды уместились в 16 бит — в два байта. Это не совпадение. Кодировку команд ARMv6-M называют **Thumb**, и её главная идея — компактность: почти каждая команда занимает два байта вместо четырёх. Для микроконтроллера это важно напрямую. Объемы энергонезависимой памяти (напр. Flash)  измеряются мегабайтами, и вдвое более плотный код даёт заметный выигрыш по количеству операций, которые могут хранится в памяти. Из всех 56 команд ARMv6-M четырьмя байтами записываются только шесть: `BL`, `MRS`, `MSR`, `DMB`, `DSB`, `ISB`.

За компактность приходится платить, и плата видна прямо на схеме выше. Под номер регистра отведено три бита, а три бита — это восемь значений. Значит, обычная арифметическая команда способна адресовать только регистры `r0`–`r7`; их так и называют — **младшими**. Регистры `r8`–`r12` доступны лишь нескольким командам со специальной кодировкой (`MOV`, `ADD`, `CMP`, `BX`). Пока вы пишете на **C**, это ограничение вам не встретится, но с ним постоянно имеет дело [[Компилятор#^def|компилятор]], распределяя переменные по регистрам.

## Чего в наборе нет

Вернёмся к списку из 56 команд. Иногда список говорит больше отсутствием, чем содержимым. В наборе ARMv6-M нет двух вещей, к которым вы привыкли на Raspberry Pi.

**Нет команды деления.** Умножение есть — `MULS`, хотя и оно даёт только младшие 32 бита произведения. А деления нет ни целочисленного, ни какого-либо ещё. Когда в программе на **C** встречается `a / b`, компилятор не может подставить одну команду и вместо этого вставляет вызов библиотечной подпрограммы, которая делит столбиком, командами сдвига и вычитания. Одна строка на **C** превращается в десятки команд процессора.

Разработчики RP2040 знали об этой особенности и обошли её по-своему: в микроконтроллер добавлен отдельный аппаратный делитель — не в ядре, а в блоке SIO рядом с ним. Обращается к нему ядро так же, как к любой другой периферии: записать делимое и делитель в регистры блока, подождать несколько тактов, прочитать частное и остаток. Pico SDK делает это за вас, поэтому деление на RP2040 всё-таки быстрое — но быстрым его делает не процессор, а чип вокруг процессора.

**Нет вещественной арифметики.** Ни одна из 56 команд не работает с числами типа `float` или `double`. Написать `float x = 1.5f * y;` вам никто не запретит, но каждая такая операция развернётся в вызов библиотечной функции, которая эмулирует вещественную арифметику целыми числами. Это работает, но стоит сотен тактов вместо одного. Отсюда практическое правило встраиваемой разработки, к которому мы ещё вернёмся: во внутренних расчётах прошивки вещественных чисел по возможности избегают, заменяя их числами с фиксированной точкой.

>[!INFO] Дополнительно
>Отсутствие этих команд — не недоработка, а осознанный выбор. Cortex-M0+ проектировали как самое компактное ядро линейки: чем меньше команд, тем меньше транзисторов уходит на декодирование и исполнение, тем меньше площадь кристалла и потребление. Старшие ядра той же линейки устроены иначе: Cortex-M3 и Cortex-M4 реализуют набор ARMv7-M, где деление выполняется отдельной командой, а у Cortex-M4F есть вдобавок блок вещественной арифметики. Выбирая микроконтроллер, инженер выбирает в том числе и это — какие операции чип выполнит одной командой, а какие подпрограммой.

## Как посмотреть команды своей программы

Всё сказанное можно проверить руками — и это, пожалуй, самое полезное, что даёт приложение. Собранная прошивка целиком состоит из машинных команд, а в тулчейне есть программа, которая переводит их обратно в читаемую запись. Такой обратный перевод называют **дизассемблированием**, а выполняет его утилита `objdump` из набора arm-none-eabi.

>[!NOTE] Попробуйте
>Соберите любой проект занятия и выполните в каталоге сборки:
>```
>arm-none-eabi-objdump -d blink.elf
>```
>Флаг `-d` (*disassemble*) просит показать код в виде команд. Найдите в выводе строку `<main>:` — под ней идёт ваша функция `main`, переведённая в команды процессора:
>```
>100002e0 <main>:
>100002e0:  b510        push  {r4, lr}
>100002e2:  2019        movs  r0, #25
>100002e4:  f000 f8a2   bl    1000042c <gpio_init>
>```
>В каждой строке три части: адрес команды в памяти, её машинный код и запись на ассемблере. Присмотритесь ко второй строке: `movs r0, #25` — это число 25, номер вывода светодиода, которое вы написали в `main`. Компилятор положил его в регистр `r0`, потому что через `r0` передаётся первый аргумент функции. Третья строка — `bl`, вызов `gpio_init`; она занимает четыре байта, как и положено команде `BL`.

Это упражнение стоит проделать хотя бы раз. Оно снимает ощущение, что между вашим кодом на **C** и работой микроконтроллера лежит что-то непознаваемое: между ними лежит вполне обозримый список команд, и любую строку прошивки можно найти в этом списке.

## Разбор примера: мигание светодиодом на командах процессора

Ассемблер можно не только читать, но и писать — прямо внутри программы на **C**. Компилятор GCC поддерживает **ассемблерные вставки**: конструкцию `asm volatile`, внутрь которой вы кладёте команды процессора, а компилятор вставляет их в код как есть. В каталоге «Примеры» занятия лежит файл `blink_asm.c`, где мигание светодиодом сделано именно так. Разберём его ключевые места.

Переключение светодиода выполняет одна-единственная команда:

```c
asm volatile (
    // STR: записать число из регистра в память
    "str %[mask], [%[reg]]"
    :
    // %[mask] — регистр с маской, %[reg] — регистр с адресом
    : [mask] "r" (led_mask),
      [reg]  "r" (gpio_xor)
    : "memory"
);
```

Здесь `%[mask]` и `%[reg]` — не регистры с фиксированными номерами, а имена, которые компилятор сам заменит на подходящие младшие регистры (`"r"` как раз и означает «положи это значение в какой-нибудь регистр»). Дальше работает то, о чём говорилось в разделе про [[т1.2.5 Внутреннее устройство. Шина#^intro|шину]]: регистр периферии для ядра неотличим от ячейки памяти, поэтому смена состояния вывода — это обычная запись `STR` по адресу `0xd000001c`.

Задержка сделана циклом из двух команд:

```c
asm volatile (
    // локальная метка «1»
    "1:\n"
    // SUBS: c = c - 1 и выставить флаги
    "   subs %[c], %[c], #1\n"
    // BNE: пока c != 0 — прыгать назад к метке 1
    "   bne  1b\n"
    : [c] "+r" (count)
    :
    : "cc"
);
```

Это ровно та пара, о которой шла речь выше. `SUBS` вычитает единицу и обновляет флаги; `BNE` проверяет флаг нуля и, если счётчик ещё не обнулился, возвращает ход программы к метке. Команды «подождать» в наборе нет — процессор просто крутит эти две команды, пока счётчик не дойдёт до нуля. Именно поэтому такая задержка неточна и зависит от тактовой частоты: она отмеряет не время, а количество выполненных команд.

>[!ATTENTION] Внимание!
>Ассемблерные вставки в этом примере — учебная демонстрация, а не рабочий приём. Они привязывают код к одной архитектуре, мешают компилятору оптимизировать соседние строки и легко ломаются при неверном описании операндов. В реальных проектах ассемблер применяют точечно: в стартап-коде, в обработчиках прерываний, в критичных по времени участках. Всё остальное пишут на **C**.

## Где искать полное описание

Если после этого приложения захочется разобраться глубже, полезно знать, какой документ что описывает.

- **ARMv6-M Architecture Reference Manual** — основной документ. Описывает каждую команду набора: синтаксис, точную битовую кодировку, влияние на флаги, поведение в особых случаях. Выпускается компанией ARM.
- **Cortex-M0+ Technical Reference Manual** — описание конкретного ядра, а не набора команд: сколько тактов занимает каждая команда, как устроен конвейер, какие опции конфигурации выбрал производитель чипа.
- **RP2040 Datasheet** — описание чипа. О ядре говорит кратко, зато подробно описывает то, что вокруг ядра: блок SIO с аппаратным делителем, карту памяти, периферию.

Эта тройка — хорошая иллюстрация многослойности документации, о которой шла речь в разделе про [[т1.2.2 Документация#^intro|документацию]]. Один и тот же вопрос «почему деление на RP2040 работает быстро» требует заглянуть в два документа разных организаций: в ARM ARM — чтобы убедиться, что команды деления нет, и в datasheet Raspberry Pi — чтобы найти аппаратный делитель в SIO.
