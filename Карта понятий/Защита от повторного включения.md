>[!NOTE] Определение
>**Защита от повторного включения** (*англ. include guard*) — строки в заголовочном файле, из-за которых препроцессор подставляет его содержимое только один раз, сколько бы раз этот файл ни подключили к одному исходному файлу.
^def

## Что нужно знать

Заголовок попадает в исходный файл не только напрямую: его тянут за собой другие заголовки. В программе из нескольких модулей один и тот же файл легко оказывается подключён дважды — через `main.c` и через соседний модуль. Препроцессор подставит его текст оба раза, объявления повторятся, и компилятор остановится на переопределении.

Защита пишется двумя способами, и выбор между ними — вопрос привычки, а не правильности.

## Через макрос

``` c
#ifndef LED_H
#define LED_H

// содержимое заголовка

#endif
```

При первой подстановке имени `LED_H` ещё нет: препроцессор определяет его и пропускает содержимое дальше. При второй имя уже определено, и весь текст до `#endif` выбрасывается. Способ входит в стандарт языка и работает везде, где есть препроцессор.

Цена — имя: оно должно быть уникальным на всю программу. Скопированный из соседнего модуля заголовок с забытым `LED_H` внутри молча исчезнет из сборки, потому что имя уже определено.

## Через `#pragma once`

``` c
#pragma once

// содержимое заголовка
```

Одна строка в начале файла. Имени нет — ошибиться не в чем, и компилятор сам следит, чтобы файл вошёл в сборку однажды.

В стандарт языка директива не входит, но её понимают все компиляторы, которые встречаются на практике, — в том числе `arm-none-eabi-gcc`, которым собираются прошивки курса. В курсе используется этот способ; пара `#ifndef`/`#endif` встречается в чужом коде повсеместно, и читать её нужно уметь.
