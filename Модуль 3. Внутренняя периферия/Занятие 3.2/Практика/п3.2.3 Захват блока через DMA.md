**Результат** — прибор `321-audio-recorder` захватывает блок отсчётов без участия ядра. АЦП снимает отсчёты 44 100 раз в секунду по своему делителю, канал DMA раскладывает их в массив, а о конце захвата сообщает прерывание. Команда `dma_cap` показывает, что время захвата совпадает с расчётом до микросекунд.
^intro

## Задание

### Что должно получиться

- [ ] `platform` запускает АЦП в непрерывном режиме с шагом 44,1 кГц и канал DMA по запросу АЦП
- [ ] Конец захвата отмечает обработчик прерывания DMA, прошивка ничего не ждёт
- [ ] Задача `logic/block-task` отдаёт готовый блок функции, полученной при запуске
- [ ] Команда `dma_cap <N>` отвечает временем захвата против расчёта и наименьшим, наибольшим и средним кодом
- [ ] Лог `device-3-2-3.log` снят, коммит отправлен, проверка `3.2.3` зелёная

### Как проверить

1. **Время сходится с расчётом.** `dma_cap 4410` отвечает временем около 100 000 мкс, ровно 0,1 с.
2. **Лог прогона лежит в проекте.** Скрипт задания записывает обмен в `device-3-2-3.log`.
3. **Автоматическая проверка курса принимает задание.** В коде она ищет делитель `adc_set_clkdiv()`, буфер АЦП с запросом DMA, запрос `DREQ_ADC`, обработчик прерывания DMA и задачу `block-task`, которая не печатает. Ожидания конца захвата в прошивке быть не должно. В логе она сверяет время трёх блоков с `N / 44100` секунды с точностью 1 % и проверяет, что среднее лежит между наименьшим и наибольшим кодом.

## Ход работы

Это задание выполняет требования Р2.1, Р2.2, Н1 и Н2 [[ТЗ 3.2 Рекордер|ТЗ на рекордер]]. Как канал DMA берёт отсчёты по запросу АЦП, разобрано в [[т3.2.6 DMA#Запрос данных от модуля|т3.2.6]], непрерывный режим АЦП и делитель — в [[т3.1.4 Режимы работы АЦП#Период, заданный модулем|т3.1.4]].

### 1. Захватить блок в platform

Добавьте в `platform.h` интерфейс захвата блока.

```c
// частота отсчётов АЦП в блоке и потоке
#define PLATFORM_SAMPLE_RATE_HZ 44100

// блок count отсчётов GP26 через DMA, о конце сообщает прерывание DMA;
// false — АЦП занят или count больше PLATFORM_BLOCK_MAX
#define PLATFORM_BLOCK_MAX 8192
bool platform_block_start(uint32_t count);
bool platform_block_done(void);
const uint16_t *platform_block_samples(void);

// время захвата блока, от запуска АЦП до последнего отсчёта
uint32_t platform_block_time_us(void);
```

DMA подключается к проекту библиотекой SDK. Добавьте `hardware_dma` в `target_link_libraries` библиотеки `platform` рядом с `hardware_adc`, а в `platform.c` подключите заголовки.

```c
#include "hardware/dma.h"
#include "hardware/irq.h"
```

В `adc_user_t` из прошлого задания добавьте значение `ADC_BLOCK`. Дальше идёт новый код. Две функции переключают АЦП между режимами. Непрерывный режим включает буфер АЦП с запросом DMA на каждый отсчёт и делитель на 44,1 кГц. Режим отсчётов по команде возвращает всё как было, чтобы `get_voltage` и телеметрия работали дальше.

```c
// частота clk_adc, от неё делитель отсчитывает шаг
#define ADC_CLOCK_HZ 48000000.0f

static int block_channel;
static uint16_t block_samples[PLATFORM_BLOCK_MAX];
static uint32_t block_start_us;
static volatile uint32_t block_end_us;
static volatile bool block_ready;

// АЦП в непрерывном режиме с шагом 44,1 кГц, буфер АЦП с запросом DMA
// на каждый отсчёт
static void adc_free_running(void)
{
    adc_select_input(ADC_CHANNEL);
    adc_fifo_setup(true, true, 1, false, false);
    adc_set_clkdiv(ADC_CLOCK_HZ / PLATFORM_SAMPLE_RATE_HZ - 1);
}

// АЦП обратно в режим отсчётов по команде
static void adc_one_shot(void)
{
    adc_run(false);
    adc_fifo_drain();
    adc_fifo_setup(false, false, 0, false, false);
    adc_set_clkdiv(0);
}

// обработчик прерывания DMA_IRQ_1: блок захвачен
static void on_block_done(void)
{
    dma_channel_acknowledge_irq1(block_channel);
    block_end_us = time_us_32();
    adc_one_shot();
    block_ready = true;
    adc_user = ADC_FREE;
}

bool platform_block_start(uint32_t count)
{
    if (adc_user != ADC_FREE || count == 0 || count > PLATFORM_BLOCK_MAX)
    {
        return false;
    }

    adc_free_running();

    // 16-битные передачи из одного адреса в растущий, по запросу АЦП
    dma_channel_config cfg = dma_channel_get_default_config(block_channel);
    channel_config_set_transfer_data_size(&cfg, DMA_SIZE_16);
    channel_config_set_read_increment(&cfg, false);
    channel_config_set_write_increment(&cfg, true);
    channel_config_set_dreq(&cfg, DREQ_ADC);

    block_ready = false;
    adc_user = ADC_BLOCK;

    // куда, откуда, сколько; true — запустить сразу
    dma_channel_configure(block_channel, &cfg, block_samples, &adc_hw->fifo, count, true);
    block_start_us = time_us_32();
    adc_run(true);
    return true;
}
```

Канал и его прерывание заводятся один раз, в конце `platform_init()`. Поэтому `on_block_done()` должна быть описана в файле выше `platform_init()`, иначе компилятор её не найдёт. Функция `dma_claim_unused_channel()` выдаёт свободный канал из двенадцати. Канал блока сообщает о конце через `DMA_IRQ_1`. Второй запрос, `DMA_IRQ_0`, останется потоку из следующего задания.

```c
    // канал блока сообщает о конце через DMA_IRQ_1
    block_channel = dma_claim_unused_channel(true);
    dma_channel_set_irq1_enabled(block_channel, true);
    irq_set_exclusive_handler(DMA_IRQ_1, on_block_done);
    irq_set_enabled(DMA_IRQ_1, true);
```

Это те же три условия прерывания из [[т3.2.4 Прерывания#Путь запроса прерывания|т3.2.4]]. Канал выставляет запрос, контроллер прерываний его пропускает, обработчик его сбрасывает. Остальные три функции из `platform.h` возвращают `block_ready`, адрес `block_samples` и разность `block_end_us - block_start_us`.

### 2. Отдать блок задачей

Требование Н2 запрещает ждать конца захвата. Значит, кто-то должен заметить готовый блок на итерации суперцикла и передать его тому, кто его ждёт. Это задача `logic/block-task`. Она устроена как задача телеметрии из [[п3.1.3 Телеметрия измерений#2. Написать задачу телеметрии|п3.1.3]], только функцию для результата получает не при старте прибора, а при каждом запуске захвата. Так одна задача служит разным командам. Интерфейс задачи такой.

```c
// block-task.h — задача захвата блока: запускает захват блока отсчётов через DMA
// и, когда блок готов, отдаёт его функции, переданной при запуске.
// Что делать с отсчётами, задача не знает.

#pragma once

#include <stdbool.h>
#include <stdint.h>

// готовый блок: отсчёты, их число и время захвата
typedef void (*block_task_callback_t)(const uint16_t *samples, uint32_t count, uint32_t time_us);

// false — АЦП занят или блок больше, чем помещается в буфер
bool block_task_start(uint32_t count, block_task_callback_t on_block);

// вызывается на каждой итерации суперцикла, не ждёт
void block_task_handle(void);
```

>[!success] Должно получиться так
> ```c
> // block_task_start(): захват уже идёт или platform его не начал — false;
> // запомнить число отсчётов и функцию
>
> // block_task_handle(): функции нет или блок не готов — выйти;
> // забыть функцию, затем вызвать её с отсчётами, числом и временем
> ```

Функцию забывают до вызова, потому что она сама может запустить следующий захват.

### 3. Добавить команду dma_cap

Команда запускает захват и сразу возвращает управление, ответ печатает функция, которую задача вызовет с готовым блоком.

>[!success] Должно получиться так
> ```c
> // print_dma_cap(): наименьший, наибольший и средний код блока;
> // расчёт времени — count * 1000000 / PLATFORM_SAMPLE_RATE_HZ, в uint64_t;
> // строка dma_cap: <N> samples in <мкс> us, expected <мкс> us, min <код> max <код> mean <код, 1 знак>
>
> // cmd_dma_cap(): аргумент не один или не число — error: usage dma_cap <N>
> // N = 0 или больше PLATFORM_BLOCK_MAX — error: N must be 1..8192
> // идёт телеметрия или задача не приняла захват — error: adc busy
> // иначе захват с функцией print_dma_cap, ответ придёт, когда блок будет готов
> ```

| Что нужно написать | Где это разбиралось |
| --- | --- |
| функцию, которую задача вызовет позже | `api_print_telemetry()`, [[п3.1.3 Телеметрия измерений#3. Печатать запись и добавить команды\|п3.1.3]] |
| обработчик задачи в суперцикле со своим секундомером | [[п3.1.3 Телеметрия измерений#4. Связать задачу в main.c\|п3.1.3]] |
| новый файл в библиотеке `logic` | [[п2.3.7 Железо и логика#^intro\|п2.3.7]] |

### 4. Проверить в терминале

Соберите проект, запишите прошивку и захватите три блока.

>[!success] Должно получиться так
> ```
> dma_cap 1000
> dma_cap: 1000 samples in 22675 us, expected 22675 us, min 859 max 1319 mean 936.6
> dma_cap 4410
> dma_cap: 4410 samples in 100001 us, expected 100000 us, min 852 max 1002 mean 930.8
> dma_cap 8192
> dma_cap: 8192 samples in 185761 us, expected 185759 us, min 851 max 1154 mean 930.0
> ```

Время захвата отличается от расчёта на одну-две микросекунды, а это и есть точность, с которой меряет таймер. Шаг держит делитель, и на 8192 отсчётах ошибка не накопилась. Сравните с прошлым заданием, где интервалы между отсчётами гуляли на десятки микросекунд. Пока шёл захват 0,19 с, ядро ни разу не тронуло отсчёт. Оно вошло в обработчик один раз, в конце. Коды плавают от 851 до 1319, потому что вход GP26 по-прежнему никуда не подключён.
