### Как проверить

1. **Обычная итерация короткая.** Без команд `main_time_exec` показывает среднее в две-три микросекунды. После `main_time_reset` максимум составляет сотни микросекунд.
2. **Долгая итерация видна.** После `calc_pi` максимум равен времени расчёта. Среднее подскакивает и за несколько секунд возвращается к прежнему значению.
3. **Автоматическая проверка курса принимает задание.** Она читает `profiling/profiling.c`. Ищет пять функций модуля и чтение `time_us_32()`. Проверяет, что среднее обновляется сдвигами, а в функции `profiling_iteration()` нет ни `float`, ни деления. Ищет комментарий с расчётом N и проверяет, что N лежит между 2^17 и 2^20. В `main.c` ищет вызовы `profiling_init()` и `profiling_iteration()` и строки двух новых команд в таблице. Самих вычислений профилирования в `main.c` быть не должно. Затем проверка собирает прошивку и читает лог. Среднее без нагрузки должно быть меньше 20 мкс. После `calc_pi` максимум не меньше времени расчёта, а среднее выше прежнего. Через несколько секунд среднее возвращается, а после сброса максимум меньше миллисекунды.

## Ход работы

Теория задания — [[т2.2.5 Профилирование#^intro|т2.2.5]].

>[!info] Зачем измерять итерацию
>Время реакции прибора в худшем случае не меньше длительности итерации суперцикла. Это правило из [[т2.2.4 Блокирующий и неблокирующий код#Пауза в суперцикле|т2.2.4]]. Значит, итерацию нужно знать. Нужно её обычное время и самое долгое. Первое показывает, во что обходится работа прибора. Второе показывает, успеет ли он ответить к сроку.

### 1. Завести модуль профилирования

Создайте папку `profiling` с файлами `profiling.h` и `profiling.c` и добавьте модуль в сборку, как модуль часов в [[п2.2.1 Тактовые частоты#2. Завести модуль часов|п2.2.1, шаг 2]].

Заголовок описывает всё, что модуль даёт наружу:

``` c
#pragma once

#include "pico/types.h"

void profiling_init(void);
void profiling_iteration(void);
float profiling_avg_us(void);
uint32_t profiling_max_us(void);
void profiling_reset_max(void);
```

`profiling_init()` запоминает начальное показание часов. `profiling_iteration()` вызывается в начале каждой итерации и учитывает прошлую. Остальные три функции отдают результат и сбрасывают максимум.

В `profiling.c` подключите `"profiling.h"` и `"pico/stdlib.h"`.

### 2. Измерить итерацию

Часы читаются один раз за итерацию и в одном и том же месте цикла. Тогда разность с прошлым показанием равна длительности прошлой итерации целиком:

``` c
static uint32_t previous_us = 0;
static uint32_t max_us = 0;

void profiling_init(void)
{
    previous_us = time_us_32();
}

void profiling_iteration(void)
{
    uint32_t now_us = time_us_32();
    uint32_t iteration_us = now_us - previous_us;
    previous_us = now_us;

    if (iteration_us > max_us)
    {
        max_us = iteration_us;
    }

    // обновление среднего — шаг 3
}
```

`time_us_32()` возвращает младшие 32 разряда тех же часов, что `time_us_64()`. Читать их дешевле, а переполняются они раз в 71,6 минуты. Разность двух показаний переполнение переживает, и замер остаётся верным. Почему так, разбирает [[т2.2.5 Профилирование#Разность двух показаний|т2.2.5, раздел «Разность двух показаний»]].

Переменные объявлены со словом `static`. Их видит только `profiling.c`, как `led_state` видит только `led.c`. Снаружи максимум доступен через функции модуля.

### 3. Считать среднее в целых числах

Среднее обновляется на каждой итерации. Поэтому оно должно стоить единицы тактов. Формула экспоненциального среднего и её целочисленная запись выведены в [[т2.2.5 Профилирование#Экспоненциальное среднее|т2.2.5, раздел «Экспоненциальное среднее»]] и в разделе «Эффект наблюдателя» следом за ним. Модуль хранит не само среднее, а сумму `avg_sum`. Она в N раз больше среднего. На каждой итерации из неё вычитается N-я часть и прибавляется новый замер:

``` c
#define AVG_SHIFT 19
#define FRACTION_SHIFT 8

static uint64_t avg_sum = 0;
```

``` c
    avg_sum = avg_sum - (avg_sum >> AVG_SHIFT) + ((uint64_t)iteration_us << FRACTION_SHIFT);
```

Эту строку поставьте в конец `profiling_iteration()`.

`N` выбрано степенью двойки, `N = 2^AVG_SHIFT`. Тогда деление на N превращается в сдвиг вправо на `AVG_SHIFT` разрядов. Замер перед сложением сдвигается влево на `FRACTION_SHIFT` разрядов. Так он переводится в 1/256 доли микросекунды, и среднее не теряет дробную часть.

Число 19 в примере не случайное. Посчитайте его сами. Среднее помнит примерно N последних итераций. Итерация прибора длится около 2 мкс, это видно в [[т2.2.4 Блокирующий и неблокирующий код#Проверка вместо паузы|т2.2.4]]. Посчитайте, сколько итераций проходит за секунду. Найдите ближайшую степень двойки. Запишите расчёт в комментарий над `AVG_SHIFT`.

>[!success] Должно получиться так
> ```c
> // итерация около 2 мкс, за секунду их около 500 000;
> // ближайшая степень двойки 2^19 = 524 288, среднее помнит около секунды
> #define AVG_SHIFT 19
> // замер в 1/256 долях микросекунды, чтобы среднее не теряло дробную часть
> #define FRACTION_SHIFT 8
> ```

Среднее в микросекундах модуль отдаёт по запросу. Здесь деление и `float` уже допустимы, потому что вызов бывает только по команде:

``` c
float profiling_avg_us(void)
{
    return (float)(avg_sum >> AVG_SHIFT) / (1 << FRACTION_SHIFT);
}
```

`profiling_max_us()` возвращает `max_us`, а `profiling_reset_max()` обнуляет его.

>[!failure] Не считайте среднее во float
>Строка `avg = avg + (x - avg) / N` во `float` стоит больше 200 тактов. Итерация прибора длится около 250 тактов. Такой замер удвоит то, что меряет, и среднее покажет вдвое больше правды. Это эффект наблюдателя из [[т2.2.5 Профилирование#Эффект наблюдателя|т2.2.5]].

### 4. Подключить модуль к суперциклу

В `main.c` вызовите `profiling_init()` перед суперциклом, а `profiling_iteration()` первой строкой в нём. Больше `main.c` ничего о замере не знает.

Добавьте две команды. `main_time_exec` печатает среднее и максимум одной строкой:

``` c
printf("iteration avg %.2f us, max %u us\n", profiling_avg_us(), (unsigned)profiling_max_us());
```

`main_time_reset` вызывает `profiling_reset_max()` и отвечает строкой `max reset`.

### 5. Посмотреть на итерации прибора

Соберите проект, запишите прошивку и откройте терминал. Подождите пару секунд, чтобы среднее успело набраться. Затем наберите по очереди `main_time_reset`, `main_time_exec`, `calc_pi`, `main_time_exec`. Через пять секунд наберите `main_time_exec` ещё раз.

>[!success] Должно получиться так
> ```
> max reset
> iteration avg 2.41 us, max 608 us
> pi: 3.14159165
> time: 4698 ms
> iteration avg 5.60 us, max 4699216 us
> iteration avg 2.63 us, max 4699216 us
> ```
>
>Обычная итерация длится около 2,5 мкс. Итерация с `calc_pi` длится 4,7 с и сразу становится максимумом. Среднее в момент расчёта подскочило примерно на 9 мкс. Пока вы набирали команду, прошла секунда, и от скачка осталась треть. Ещё через пять секунд обычные итерации вернули среднее на место.

Максимум после сброса составляет сотни микросекунд, а не пару микросекунд, как обычная итерация. В него попадают итерации, в которых прибор принимал команду и печатал ответ. Одна строка `printf()` стоит десятки микросекунд, это видно в таблице из [[т2.2.5 Профилирование#Эффект наблюдателя|т2.2.5, раздел «Эффект наблюдателя»]]. Ещё SDK раз в миллисекунду обслуживает USB, и итерация, на которую это пришлось, удлиняется. Об этом сказано в [[т2.2.5 Профилирование#Среднее и худшее|т2.2.5, раздел «Среднее и худшее»]].

>[!bug] Среднее равно нулю, ровному целому или сотым долям
>Если среднее равно нулю, проверьте, что `profiling_iteration()` вызывается в суперцикле. Если среднее в сотни раз меньше ожидаемого, замер при сложении не сдвинут на `FRACTION_SHIFT`, а при выводе делится на 256. Если среднее выходит ровным целым, например 3.00 вместо 2.4, дробной части нет вовсе. Сумма тогда растёт, пока среднее не дойдёт до следующего целого числа. Сдвиг влево при сложении и деление на `1 << FRACTION_SHIFT` при выводе нужны оба.
