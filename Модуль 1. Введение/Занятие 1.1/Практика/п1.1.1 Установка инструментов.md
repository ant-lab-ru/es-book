**Результат** — у вас на компьютере установлены и работают все программы, нужные для разработки под микроконтроллер RP2040 и плату Raspberry Pi Pico.
^intro

![[Цепочка сборки.excalidraw|100%]]

Это не семь случайных программ, а одна производственная линия: вы пишете текст, CMake и Make организуют работу, компилятор переводит её в машинные команды, picotool упаковывает результат, и он копируется на плату.

## Задание

### Что должно получиться

- [ ] Семь программ установлены и отвечают на запрос версии в терминале
- [ ] Pico SDK версии `2.3.0` склонирован, переменная среды `PICO_SDK_PATH` указывает на него
- [ ] В папке `pico` лежит файл `tools.log` с версиями всех программ и Pico SDK

### Как проверить

Результат проверяется тремя способами — от самого быстрого к самому строгому.

1. **Каждый инструмент отвечает на запрос версии.** Команда из таблицы ниже возвращает номер версии, а не сообщение «команда не найдена».
2. **Файл `tools.log` собран и полон.** В нём восемь строк с версиями — семь программ и Pico SDK — и непустая строка `PICO_SDK_PATH`.
3. **Автоматическая проверка курса принимает задание.** Она читает `tools.log` из вашего репозитория и ищет в нём десять вещей: сам файл, версии семи программ, версию Pico SDK и путь в `PICO_SDK_PATH`, оканчивающийся на `pico-sdk`. Проверка запустится в задании [[п1.1.5 Настройка автоматической проверки#^intro|п1.1.5 Настройка автоматической проверки]], когда файл уже будет лежать в репозитории.

## Ход работы

>[!warning] Терминал
>Все команды курса выполняются в терминале. В Windows используйте **PowerShell**: нажмите `Win+R`, наберите `powershell` и нажмите `Enter`. В macOS и Linux подойдёт стандартный терминал системы.

>[!info] Версии программ
>Для пяти инструментов подойдёт любая версия — ваша может отличаться от приведённой в таблице. Исключений два: [[pico-sdk#^def|pico-sdk]] и [[picotool#^def|picotool]] закреплены версией `2.3.0` и должны совпадать между собой.

### 1. Проверить, что уже стоит

Часть программ может быть установлена на вашем компьютере раньше. Выполните команды по очереди и отметьте, каких инструментов не хватает.

| Инструмент              | Команда проверки              | Ответ                        | Установка                                  |
| ----------------------- | ----------------------------- | ---------------------------- | ------------------------------------------ |
| Система контроля версий | `git --version`               | `git version 2.42.0`         | [[Git#Установка\|Git]]                     |
| Интерпретатор Python    | `python --version`            | `Python 3.11.4`              | [[Python#Установка\|Python]]               |
| Система сборки          | `cmake --version`             | `cmake version 3.30.0`       | [[CMake#Установка\|CMake]]                 |
| Исполнитель сценариев   | `make --version`              | `GNU Make 3.81`              | [[Make#Установка\|Make]]                   |
| Компилятор для ARM      | `arm-none-eabi-gcc --version` | `arm-none-eabi-gcc … 15.3.1` | [[GCC (Arm GNU Toolchain)#Установка\|GCC]] |
| Редактор кода           | `code --version`              | `1.133.0`                    | [[VS Code#Установка\|VS Code]]             |
| Утилита прошивок        | `picotool version`            | `picotool v2.3.0`            | [[picotool#Установка\|picotool]]           |

>[!info] Python в macOS и Linux
>Там интерпретатор обычно вызывается командой `python3`. Если `python --version` не сработала, попробуйте `python3 --version`.

### 2. Поставить недостающее

Откройте карточку инструмента из последней колонки и пройдите раздел «Установка» для своей операционной системы. В macOS установка идёт через [[Homebrew#^def|Homebrew]] — если его нет, поставьте сначала его.

После установки каждой программы **перезапустите терминал** и повторите её команду из таблицы: новый `PATH` виден только тем терминалам, которые открыты после изменения.

>[!bug] Программа установлена, но команда не находится
>Это самый частый сбой первого дня, и он не означает, что установка не удалась. Порядок разбора:
>- перезапустите терминал — чаще всего этого достаточно;
>- проверьте, что путь к программе попал в `PATH` — [[Настройка переменных среды#^def|Настройка переменных среды]];
>- убедитесь, что команда набрана точно: у `picotool version` нет двойного дефиса, в отличие от остальных.

### 3. Создать папку для разработки и клонировать Pico SDK

1. Создайте папку для работы по курсу и перейдите в неё.

В macOS и Linux — в домашней директории:

``` bash
mkdir -p ~/Repositories/pico
cd ~/Repositories/pico
```

В Windows — в корне диска `C:`:

``` powershell
mkdir C:/Repositories/pico
cd C:/Repositories/pico
```

>[!failure] Кириллица, пробелы и скобки в пути
>Путь к рабочей папке должен состоять только из латинских букв, без пробелов и без кириллицы. Папка вида `C:\Users\Иван Петров\Документы\проекты` рано или поздно сломает процесс сборки, причём сообщение об ошибке будет говорить совсем о другом. По той же причине не работайте в папке рабочего стола и в облачных папках.
>
>То же относится к папкам, куда установлены инструменты: путь вида `C:\Program Files (x86)\…` ломает сборку круглыми скобками. Для Make об этом сказано в его карточке — [[Make#Установка|Make]].

2. Склонируйте SDK версии `2.3.0` и подтяните его подмодули:

``` bash
git clone -b 2.3.0 https://github.com/raspberrypi/pico-sdk.git
cd pico-sdk
git submodule update --init
```

Что такое SDK и зачем ему подмодули — в карточке [[pico-sdk#^def|pico-sdk]]. В самой папке `pico-sdk` мы ничего не меняем: это набор инструментов производителя.

3. Убедитесь, что структура папок получилась такой:

```
Repositories
└── pico
    └── pico-sdk
```

### 4. Настроить переменную PICO_SDK_PATH

Создайте системную [[Переменная среды#^def|переменную среды]] `PICO_SDK_PATH` со значением полного пути к папке `pico-sdk` — например, `C:\Repositories\pico\pico-sdk`. Порядок действий для каждой из трёх систем описан в навыке [[Настройка переменных среды#^def|настройка переменных среды]].

После этого перезапустите терминал и проверьте значение.

В macOS и Linux:

``` bash
echo $PICO_SDK_PATH
```

В Windows:

``` powershell
$env:PICO_SDK_PATH
```

>[!warning] Без этой переменной сборка не найдёт SDK
>Пустой вывод означает, что переменная не задана либо терминал открыт раньше, чем она появилась. Это единственный шаг задания, ошибка в котором проявится не сейчас, а в следующем задании — при сборке первого проекта.

### 5. Собрать файл tools.log

Автоматическая проверка не видит ваш компьютер: она работает с содержимым репозитория. Поэтому вывод команд с версиями нужно сохранить в файл.

1. Вернитесь в папку `pico`:

``` bash
cd ~/Repositories/pico
```

2. Выполните команду для своей системы. В macOS и Linux:

``` bash
{ git --version | head -1
  python3 --version | head -1
  cmake --version | head -1
  make --version | head -1
  arm-none-eabi-gcc --version | head -1
  echo "code $(code --version | head -1)"
  picotool version | head -1
  echo "pico-sdk $(git -C "$PICO_SDK_PATH" describe --tags)"
  echo "PICO_SDK_PATH=$PICO_SDK_PATH"; } > tools.log 2>&1
```

В Windows:

``` powershell
& { git --version | Select-Object -First 1
    python --version | Select-Object -First 1
    cmake --version | Select-Object -First 1
    make --version | Select-Object -First 1
    arm-none-eabi-gcc --version | Select-Object -First 1
    "code $(code --version | Select-Object -First 1)"
    picotool version | Select-Object -First 1
    "pico-sdk $(git -C $env:PICO_SDK_PATH describe --tags)"
    "PICO_SDK_PATH=$env:PICO_SDK_PATH" } *>&1 | Out-File tools.log -Encoding utf8
```

Порядок команд тот же, что в таблице первого шага, — так файл удобно сверять построчно. От каждой команды берётся только первая строка: почти все они печатают следом текст лицензии или подпись разработчика, а в журнале нужна одна версия. VS Code отвечает голым числом, без названия, поэтому название к нему приписано вручную. Предпоследняя строка спрашивает версию у самого SDK: `git describe` называет тег, на который склонирована папка `pico-sdk`, — так проверка убеждается, что курс и вы работаете на одной версии.

>[!warning] Кодировка файла в Windows
>В команде PowerShell файл записывается через `Out-File -Encoding utf8`, а не простым `>`. Причина: PowerShell по умолчанию пишет в UTF-16, где каждая буква занимает два байта. Такой файл git считает двоичным — он не покажет по нему изменений, — а автоматическая проверка не найдёт в нём ни одной строки. Команду нужно набирать целиком, вместе с последней частью после `|`.

Команда не выводит ничего на экран — весь вывод уходит в файл. Это нормально.

3. Откройте `tools.log` и сверьте: восемь версий и непустая строка `PICO_SDK_PATH`.

>[!success] Должно получиться так
>
>Рабочая папка со всем содержимым:
>
>```
>Repositories
>└── pico
>    ├── pico-sdk
>    └── tools.log
>```
>
>Файл `tools.log` — ровно девять строк: семь версий программ, версия SDK и путь к нему. Номера и подписи в скобках у вас будут свои: они зависят от системы и способа установки.
>
>```
>git version 2.50.1 (Apple Git-155)
>Python 3.11.4
>cmake version 4.2.3
>GNU Make 3.81
>arm-none-eabi-gcc (Arm GNU Toolchain 15.3.Rel1 (Build arm-15.149)) 15.3.1 20260627
>code 1.133.0
>picotool v2.3.0 (Darwin, AppleClang-21.0.0.21000099, Release)
>pico-sdk 2.3.0
>PICO_SDK_PATH=/Users/ivan/Repositories/pico/pico-sdk
>```
>
>В переменной `PATH` появились пути ко всем установленным программам — в Windows это выглядит так:
>
>```
>C:\Program Files\Git\cmd
>C:\Program Files\CMake\bin
>C:\Program Files\GnuWin32\bin
>C:\Program Files\Arm\GNU Toolchain mingw-w64-x86_64-arm-none-eabi\bin
>C:\Program Files\picotool
>C:\Users\Ivan\AppData\Local\Programs\Microsoft VS Code\bin
>C:\Users\Ivan\AppData\Local\Programs\Python\Python311
>```
>
>В macOS и Linux отдельных строк на каждую программу не будет: пакетный менеджер складывает исполняемые файлы в общие папки — `/opt/homebrew/bin` в macOS, `/usr/bin` в Linux, — и они в `PATH` уже есть.

>[!info] Файл понадобится дальше
>`tools.log` выгружается в репозиторий курса в задании [[п1.1.4 Создание репозитория курса#^intro|п1.1.4 Создание репозитория курса]] — там его и прочитает автоматическая проверка.
