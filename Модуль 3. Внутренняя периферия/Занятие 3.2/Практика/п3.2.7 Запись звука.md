Она должна быть не меньше 2,5 с и совпадать с `recording.log`, а в логе не должно быть пропусков и переполнений. Звучание проверяете вы сами.

## Ход работы

Это задание выполняет требования Р7 и Р5 [[ТЗ 3.2 Рекордер|ТЗ на рекордер]]. Почему у сигнала микрофона есть постоянное смещение и что с ним делать при записи, разобрано в [[т3.2.1 Цифровой звук#Файл WAV|т3.2.1]].

### 1. Подключить микрофон

Сначала снимите перемычку GP20 — GP26 из [[п3.2.5 Запись испытательного сигнала#^intro|п3.2.5]]. Вывод GP20 после запуска прошивки держит ноль, и с перемычкой он замкнул бы выход микрофона на землю.

Модуль MAX9814 — это электретный микрофон и усилитель с автоматической регулировкой усиления на одной плате. Регулировка снижает усиление на громком звуке, поэтому сигнал не выходит за пределы, а на тихом его повышает. На плате модуля пять выводов. Нам нужны четыре.

| Вывод модуля | Куда на Pico | Зачем |
| --- | --- | --- |
| Vdd | 3V3(OUT), ножка 36 | питание 3,3 В |
| GND | GND, например ножка 38 | общая земля |
| Out | GP26, ножка 31 | сигнал на вход АЦП 0 |
| Gain | Vdd модуля | наибольшее усиление 40 дБ |

Вывод AR оставьте свободным, это самая медленная регулировка. На шелкографии модуля написано, что сигнал на выходе колеблется вокруг постоянных 1,25 В с размахом не больше 2 В. Значит, он лежит между 0,25 и 2,25 В и целиком помещается в диапазон АЦП от 0 до 3,3 В.

![[п3.2.7 Микрофон на макетной плате.jpeg]]

Вывод Gain задаёт, до какого усиления регулировка может дойти. Свободный даёт 60 дБ, соединённый с GND — 50 дБ, с Vdd — 40 дБ. В тишине регулировка выкручивает усиление до этого предела и вместе с ним поднимает шум комнаты. Вот что показали замеры на плате в обычной комнате.

| Gain | Усиление | Тишина, `mic_level` | Голос, громкие места | Паузы в речи |
| --- | --- | --- | --- | --- |
| свободен | 60 дБ | около 200 мВ | около 270 мВ | около 70 мВ |
| GND | 50 дБ | около 80 мВ | около 240 мВ | около 74 мВ |
| Vdd | 40 дБ | около 26 мВ | около 100 мВ | около 24 мВ |

Голос громче пауз всегда примерно в 3–4 раза. Значит, в паузах слышен в основном звук самой комнаты, а меньшее усиление его не убирает, зато не накачивает шум в тишине. При 40 дБ голосу хватает диапазона, пики доходят до 0,7 В из доступных 1,2 В в каждую сторону. Поэтому Gain соединяется с Vdd.

### 2. Посчитать смещение и уровень

Обе команды работают с блоком отсчётов, который уже умеет снимать задача `block-task` из [[п3.2.3 Захват блока через DMA#2. Отдать блок задачей|п3.2.3]]. Ей передаётся другая функция для готового блока, и задача ничего о микрофоне не знает. Смещение — это среднее блока. Уровень — среднеквадратичное отклонение отсчётов от среднего, а пик — наибольшее отклонение.

У ядра Cortex-M0+ нет блока вычислений с плавающей точкой, и каждое действие с `float` выполняет функция из библиотеки компилятора. На плате среднее и среднеквадратичное отклонение 8192 отсчётов в `float` считались 30 мс, а в целых числах 1,3 мс. Поэтому функция статистики считает в кодах АЦП, целыми числами, а в вольты переводит только итог. Это новый код, вот он целиком, место ему в `api-callbacks.c`.

```c
// среднее и отклонение от среднего в кодах АЦП: среднеквадратичное и наибольшее
static void block_stats(const uint16_t *samples, uint32_t count, float *mean, float *rms, float *peak)
{
    uint32_t sum = 0;
    for (uint32_t i = 0; i < count; i++)
    {
        sum += samples[i];
    }
    int32_t center = (int32_t)(sum / count);

    // в целых числах: в float на 8192 отсчётах ядро считало бы в 24 раза дольше
    uint64_t squares = 0;
    uint32_t largest = 0;
    for (uint32_t i = 0; i < count; i++)
    {
        int32_t deviation = (int32_t)samples[i] - center;
        uint32_t size = deviation < 0 ? -deviation : deviation;
        squares += (uint64_t)(deviation * deviation);
        if (size > largest)
        {
            largest = size;
        }
    }

    *mean = (float)sum / count;
    *rms = sqrtf((float)squares / count);
    *peak = (float)largest;
}
```

Сумма 8192 кодов до 4095 помещается в 32 бита, а сумма квадратов отклонений — уже нет, поэтому она 64-битная. Для `sqrtf()` подключите `<math.h>`.

Перевод кода в вольты знает только `platform`, там лежат опорное напряжение и число уровней ([[п3.1.1 Измерение напряжения#^intro|п3.1.1]]). Добавьте в `platform.h` функцию, которая переводит код, в том числе дробный, например среднее.

```c
// код АЦП в вольты; код может быть дробным, например средним
float platform_adc_volts(float code);
```

### 5. Записать голос

Как скрипт пишет файл WAV, вы разобрали в [[п3.2.5 Запись испытательного сигнала#5. Разобрать, как скрипт играет и пишет|п3.2.5]]. Для голоса смещение постоянно, его даёт сам микрофон, поэтому скрипт не включает фильтр, а считает смещение как среднее первых 0,1 с записи, 4410 отсчётов, и вычитает его из каждого кода.

Включите запись на 3 секунды и говорите в микрофон с полуметра.

``` bash
python rec_audio.py --seconds 3 --wav recording.wav
```

>[!success] Должно получиться так
> ```
> Плата на порту COM5, пишу 3.0 с
> Кадров 260, отсчётов 133120, пропущено кадров 0
> Запись сохранена в recording.wav
> Итог записан в recording.log
> ```
> Файл `recording.log`
> ```
> задание: 3.2.7
> ...
> <-- stream: started, 44100 Hz, 16 bit
> принято: кадров 260, отсчётов 133120, пропущено кадров 0, байтов вне кадров 70
> ...
> файл: recording.wav, 16 бит, 44100 Гц, 3.02 с, смещение 1543.6
> --> stream_stop
> <-- stream: stopped, 260 frames, 133120 samples, 0 overruns
> ```

Смещение 1544 кода, это 1,244 В, то же, что ответил `mic_bias`.

Запись длится 3,02 с, а не ровно 3. Скрипт останавливает поток через 3 с после ответа `stream: started` и принимает все кадры, которые прибор успел отправить до остановки. Файл весит 266 КБ, 88 200 байт на секунду и заголовок.

### 6. Послушать запись

Откройте `recording.wav` в любом проигрывателе. Голос должен узнаваться. На паузах будет слышен тихий шум. Это в основном звук комнаты, который поднимает регулировка усиления. Он около 24 мВ, а собственный шум АЦП, около восьми эффективных разрядов из двенадцати, на порядок тише ([[т3.1.3 АЦП RP2040#^intro|т3.1.3]]).
