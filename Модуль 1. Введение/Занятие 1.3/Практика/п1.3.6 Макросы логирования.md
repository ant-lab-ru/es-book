## Ход работы

>[!info] Чем журнал отличается от printf
>Вызов `printf()` печатает то, что вы написали, и ничего больше. Когда сообщений в программе десятки, этого мало: непонятно, откуда пришла строка, какие сообщения важные, а какие — подробности для отладки, и как выключить подробный лог перед передачей прибора заказчику. Журнал отвечает на все три вопроса: у сообщения есть уровень важности, оно само подписывается местом в коде, а порог отсекает лишнее ещё на сборке. Зачем это нужно и как выглядит на практике — в [[т1.3.7 Отладка через вывод#^intro|теории занятия]].

### 1. Завести модуль журнала

Создайте в проекте `134-led-module` папку `logging`, а в ней файлы `log.h` и `log.c`. Добавьте их в сборку так же, как модуль светодиода в [[п1.3.5 Модуль светодиода#5. Добавить модуль в сборку\|п1.3.5, шаг 5]]: `logging/log.c` — в `add_executable()`, папку `logging` — в `target_include_directories()`.

### 2. Описать прибор и уровни важности

В начале `log.h` — то, чем прибор представляется, и три уровня сообщений:

``` c
#pragma once

#include <stdio.h>

#define DEVICE_NAME "es-led-module"
#define FIRMWARE_VERSION "1.0.0"

#define LOG_LEVEL_ERR 1
#define LOG_LEVEL_INF 2
#define LOG_LEVEL_DBG 3

#ifndef LOG_LEVEL
#define LOG_LEVEL LOG_LEVEL_DBG
#endif
```

`<stdio.h>` подключается здесь, а не в `log.c`: макросы печатают вызовом `printf()`, а разворачиваются они в тех файлах, которые подключили `log.h`. Объявление `printf()` должно прийти туда же вместе с ними.

Уровни идут по убыванию важности:
- ошибка (`ERR`) — то, что пошло не так
- сведение (`INF`) — событие, о котором стоит знать всегда
- отладка (`DBG`) — подробности, нужные только при разборе

Числа возрастают, и порог `LOG_LEVEL` читается как «печатать всё, что не выше этого числа».

Знакомая по прошлому заданию конструкция `#ifndef` здесь работает иначе: она позволяет задать порог снаружи, при конфигурации сборки, а если его не задали — взять значение по умолчанию.

### 3. Написать макросы

``` c
#define LOG_INF(...)                                \
    do                                              \
    {                                               \
        if (LOG_LEVEL >= LOG_LEVEL_INF)             \
        {                                           \
            log_prefix("inf", __func__, __LINE__);  \
            printf(__VA_ARGS__);                    \
        }                                           \
    } while (0)
```

Разберём по частям, потому что здесь пять непривычных вещей сразу.

[[Макрос#^def|Макрос]] — это замена текста, которую делает препроцессор до компиляции: где в программе написано `LOG_INF("led on\n")`, туда подставится всё, что стоит справа. Обратные слеши в конце строк склеивают их в одну: макрос по определению однострочный, а читать его в одну строку невозможно.

`__VA_ARGS__` — это «всё, что передали». Благодаря ему макрос принимает столько же аргументов, сколько `printf()`: и одну строку, и строку с числами.

`__func__` и `__LINE__` подставляет компилятор: имя функции, внутри которой стоит вызов, и номер строки в файле. Вы их не пишете — и именно поэтому подпись всегда верна, даже когда код переехал.

Проверка `LOG_LEVEL >= LOG_LEVEL_INF` — то самое отсечение. Условие известно на этапе компиляции, поэтому при пониженном пороге компилятор выбрасывает и вызов, и саму строку сообщения: в образе их не остаётся.

Обёртка `do { … } while (0)` выглядит бессмысленной — цикл, который выполняется ровно один раз. Она нужна, чтобы макрос вёл себя как одна инструкция: без неё запись вида `if (условие) LOG_INF("…"); else …` развалилась бы на части и перестала собираться. Это стандартный приём, и встречать его вы будете в любом чужом коде с макросами.

Напишите так же `LOG_ERR` с уровнем `"err"` и `LOG_DBG` с уровнем `"dbg"`.

### 4. Написать строку версии и подпись сообщения

В `log.c` — две функции. Первая печатает, что за прибор перед вами и какая в нём прошивка:

``` c
void log_version(void)
{
    printf("device: %s %s, built %s %s, log level %d\n",
           DEVICE_NAME, FIRMWARE_VERSION, __DATE__, __TIME__, LOG_LEVEL);
}
```

`__DATE__` и `__TIME__` — дата и время сборки, их тоже подставляет компилятор. Строка получается неожиданно полезной: по ней вы отличаете свежесобранную прошивку от той, что лежала в плате с прошлого раза. Ошибка «правлю код, а поведение не меняется» чаще всего именно об этом — прошивка не записалась.

Вторая функция печатает подпись перед текстом сообщения:

``` c
void log_prefix(const char *level, const char *function, int line)
{
    printf("%s %s:%d ", level, function, line);
}
```

Сообщение уходит в порт в два вызова: сначала подпись, потом текст. Перевода строки в подписи нет — иначе они разъехались бы по разным строкам.

### 5. Перевести проект на журнал

Подключите `log.h` в `main.c` и замените вызовы `printf()` макросами — каждому сообщению свой уровень:

| Сообщение                  | Уровень   | Почему                                                      |
| -------------------------- | --------- | ----------------------------------------------------------- |
| новое состояние светодиода | `LOG_INF` | событие, ради которого прибор и существует                  |
| неизвестная команда        | `LOG_ERR` | отправитель сделал что-то не то, об этом нужно знать всегда |
| принятый символ            | `LOG_DBG` | подробность, полезная только при разборе                    |

Добавьте в разбор команд ещё одну ветку — `v`, по которой прибор печатает строку версии:

``` c
    else if (command == 'v')
    {
        log_version();
    }
```

Вывод через `printf()` здесь остаётся: строку версии печатает сам модуль журнала, и подпись с уровнем ей не нужна.

Отладочное сообщение о принятом символе — новое. Оно встаёт в суперцикле после раннего выхода из [[п1.3.4 Светодиод и USB#2. Разобрать команду в отдельной функции\|п1.3.4, шаг 2]], рядом с разбором команды:

``` c
        int command = getchar_timeout_us(0);

        if (command == PICO_ERROR_TIMEOUT)
        {
            continue;
        }

        LOG_DBG("got %c\n", command);
        handle_command(command);
```

Выше этих строк сообщение ставить нельзя: символа нет в подавляющем большинстве проходов суперцикла, и журнал зальёт поток строк.

>[!failure] Не оставляйте printf в обход журнала
>Одна забытая строка не сломает программу — но она не выключится порогом и останется в выводе прибора, отданного заказчику. Весь вывод проекта реализовывайте через макросы. Исключение — сам `log.c`, который их и реализует.

### 7. Создать скрипт проверки

Создайте в папке `134-led-module` файл `check-1-3-6.py` — рядом с `main.c`. Наберите в нём программу целиком.

Скрипт посылает плате четыре команды подряд и после каждой забирает всё, что она ответила: на `v` приходит строка версии, на `e` и `d` — сообщения о светодиоде, на `q` — сообщение об ошибке. Строк на одну команду приходит больше одной, поэтому чтение идёт до тех пор, пока плата не замолчит.

>[!success] Должно получиться так
> ```python
> # Проверка задания п1.3.6 на устройстве: посылает плате команды,
> # собирает подписанные строки журнала и записывает обмен в файл device-1-3-6.log.
>
> import time
> from datetime import datetime
>
> import serial
> from serial.tools import list_ports
>
> VENDOR_ID = 0x2E8A
> PRODUCT_ID = 0x000A
>
> TASK = "1.3.6"
> PROJECT = "134-led-module"
> LOG_NAME = "device-1-3-6.log"
> COMMANDS = ["v", "e", "d", "q"]
> ANSWER_TIMEOUT_S = 1
>
>
> def find_board():
>     for port in list_ports.comports():
>         if port.vid == VENDOR_ID and port.pid == PRODUCT_ID:
>             return port
>     return None
>
>
> def talk(board):
>     exchange = []
>     with serial.Serial(board.device, timeout=ANSWER_TIMEOUT_S) as port:
>         time.sleep(0.2)
>         port.reset_input_buffer()
>         started = time.monotonic()
>         for command in COMMANDS:
>             port.write(command.encode("ascii"))
>             exchange.append((time.monotonic() - started, "-->", command))
>             print("--> " + command, end="\r\n")
>             while True:
>                 line = port.readline().decode("ascii", "replace").strip()
>                 if not line:
>                     break
>                 exchange.append((time.monotonic() - started, "<--", line))
>                 print("<-- " + line, end="\r\n")
>     return exchange
>
>
> def write_log(board, exchange):
>     with open(LOG_NAME, "w", encoding="utf-8") as log:
>         log.write("задание: " + TASK + "\n")
>         log.write("проект: " + PROJECT + "\n")
>         log.write("устройство: %04x:%04x\n" % (board.vid, board.pid))
>         log.write("серийный номер: " + str(board.serial_number) + "\n")
>         log.write("порт: " + board.device + "\n")
>         log.write("начало: " + datetime.now().isoformat(timespec="seconds") + "\n")
>         for moment, direction, text in exchange:
>             log.write("%8.3f %s %s\n" % (moment, direction, text))
>         log.write("итог: отправлено команд %d\n" % len(COMMANDS))
>
>
> board = find_board()
>
> if board is None:
>     print("Плата не найдена. Проверьте кабель и запишите на плату прошивку задания.", end="\r\n")
> else:
>     print("Плата на порту " + board.device + ", посылаю команды", end="\r\n")
>     exchange = talk(board)
>     write_log(board, exchange)
>     print("Обмен записан в " + LOG_NAME, end="\r\n")
> ```
