Контроллеры RP2040 формируют сигналы [[I²C#^def|I²C]] и [[SPI#^def|SPI]]. Программа выбирает выводы, задаёт параметры обмена и проверяет ответ устройства. В этой заметке рассмотрим, какой ключевой код на C для этого нужно написать.
^intro

## Выбор контроллера и выводов

У RP2040 по два контроллера I²C и SPI. Для каждого сигнала допустимы только определённые выводы общего назначения GPIO. В примерах используем комплект средств разработки Pico SDK. Сверяйте назначение выводов с [[RP2040 Datasheet.pdf#page=238|таблицей функций GPIO]]. `gpio_set_function()` подключает вывод к периферийному блоку.

## Пример I²C

`i2c_init()` задаёт частоту 100 кГц. GP8 используем для SDA, а GP9 для SCL. Линиям нужны подтяжки на модуле или на шине. Переменная `address` содержит семибитный адрес BME280. SDK сам добавит к нему бит направления при передаче. `reg` задаёт адрес регистра идентификатора, а в `answer` попадёт прочитанный байт.

```c
i2c_init(i2c0, 100000);
gpio_disable_pulls(8);
gpio_set_function(8, GPIO_FUNC_I2C);
gpio_disable_pulls(9);
gpio_set_function(9, GPIO_FUNC_I2C);

const uint8_t address = 0x76;
const uint8_t reg = 0xD0;
uint8_t answer;

if (i2c_write_timeout_us(i2c0, address, &reg, 1, true, 10000) == 1)
{
    if (i2c_read_timeout_us(i2c0, address, &answer, 1, false, 10000) == 1)
    {
        printf("0x%02X\n", answer);
    }
}
```

Аргумент `nostop` со значением `true` оставляет шину занятой после записи номера регистра. Следующий вызов начинает чтение повторным START. Значение `false` завершает чтение через STOP. Последний аргумент ограничивает ожидание в микросекундах. Для каждой фазы проверяем, что передан или принят один байт.

## Пример SPI

`spi_init()` задаёт частоту ведущего, а `spi_set_format()` задаёт разрядность и режим. Назначаем GP2, GP3 и GP4 контроллеру SPI0, а линией выбора на GP16 управляем отдельно. До обмена на ней высокий уровень. Управляющий байт `0xD0` запрашивает идентификатор BME280.

```c
spi_init(spi0, 100000);
spi_set_format(spi0, 8, SPI_CPOL_1, SPI_CPHA_1, SPI_MSB_FIRST);
gpio_set_function(2, GPIO_FUNC_SPI); // SCK
gpio_set_function(3, GPIO_FUNC_SPI); // MOSI
gpio_pull_down(4);
gpio_set_function(4, GPIO_FUNC_SPI); // MISO

const uint cs_pin = 16;
gpio_init(cs_pin);
gpio_put(cs_pin, 1);
gpio_set_dir(cs_pin, GPIO_OUT);

const uint8_t command = 0xD0;
uint8_t answer;
gpio_put(cs_pin, 0);
spi_write_blocking(spi0, &command, 1);
spi_read_blocking(spi0, 0x00, &answer, 1);
gpio_put(cs_pin, 1);

printf("0x%02X\n", answer);
```

Первый вызов передаёт управляющий байт. Второй передаёт заполнитель и принимает ответ. Оба выполняются при активной линии выбора `cs_pin`. Для учебного ведомого в последней практике добавим паузу между этими вызовами.

>[!info] Как проверить ответ устройства
>Успешная передача и верный ответ проверяются отдельно. В I²C подтверждение адреса показывает, что устройство ответило. В SPI такты появляются даже при отключённом ведомом. Смысл прочитанного байта в обоих случаях проверяем по документации устройства.
