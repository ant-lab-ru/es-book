## Задание

### Что должно получиться

- [ ] В проекте есть папка `device` с файлами `device.h` и `device.c`
- [ ] По команде `i` плата печатает паспорт из пяти строк вида «ключ — значение»
- [ ] Серийный номер платы и сведения о кристалле прочитаны из самого чипа
- [ ] Тип платы попадает в код из настроек сборки, а не вписан руками
- [ ] Скрипт `check-1-3-7.py` сохраняет лог `device-1-3-7.log` с паспортом

### Как проверить

1. **Команды отвечают каждая о своём.** Подключите терминал и наберите `v`: приходит одна строка о прошивке — имя, версия, дата сборки, уровень журнала. Наберите `i` — приходит паспорт железа из пяти строк, и строки о прошивке в нём нет.
2. **Значения настоящие.** Строка `serial` не меняется при повторной прошивке и отличается на другой плате; `board` совпадает с `PICO_BOARD` в настройках сборки; поля `chip` разобраны по описанию регистра в документации.
3. **Автоматическая проверка курса принимает задание.** Она читает `device.h` и `device.c`: константы на месте, серийный номер берётся функцией SDK, регистр `CHIP_ID` читается по адресу через `volatile`, поля разобраны. В `CMakeLists.txt` — библиотека `pico_unique_id`, папка модуля и тип платы, переданный определением компилятора. А в логе сверяет главное: серийный номер, который прошивка напечатала сама, и серийный номер, который плата сообщила компьютеру по USB, должны совпасть.

## Ход работы

>[!info] Зачем прибору паспорт
>Пока прибор один и лежит на столе, вопрос «что в нём за прошивка» не стоит. Он появляется сразу, как только приборов становится несколько или как только один уезжает к кому-то другому: какая версия внутри, из какого репозитория её собрали, та ли это плата, о которой идёт речь в переписке. Ответ на такие вопросы должен давать сам прибор — на человеческую память тут полагаться бессмысленно.
>
>Заодно паспорт решает вашу собственную задачу: по нему видно, что в плате именно та прошивка, которую вы только что собрали, а не оставшаяся с прошлого раза.

### 1. Завести модуль device

Создайте в проекте `134-led-module` папку `device`, а в ней файлы `device.h` и `device.c`. Подключите их к сборке так же, как модуль светодиода в [[п1.3.5 Модуль светодиода#5. Добавить модуль в сборку\|п1.3.5, шаг 5]].

В `device.h` переезжают из `log.h` название устройства и версия прошивки — теперь это сведения о приборе, а не о журнале. К ним добавляются название проекта и ссылка на ваш репозиторий курса:

``` c
#define DEVICE_NAME "es-led-module"
#define FIRMWARE_VERSION "1.0.0"

#define DEVICE_PROJECT "134-led-module"
#define DEVICE_REPO "https://github.com/<ваш логин>/es-student"
```

Ссылка на репозиторий в паспорте выглядит избыточной ровно до первого случая, когда прибор оказался у другого человека и тот захотел посмотреть, из чего он собран.

### 2. Передать тип платы из настроек сборки

Тип платы уже известен системе сборки: он лежит в переменной `PICO_BOARD`, которую вы задаёте в первых строках `CMakeLists.txt`. Впишите его в код руками — и однажды он разойдётся с настройками. Поэтому значение передаётся из сборки в код определением компилятора. Добавьте в `CMakeLists.txt` после `target_link_libraries()` и перед `pico_set_linker_script()`:

``` cmake
target_compile_definitions(${PROJECT_NAME} PRIVATE
    DEVICE_BOARD="${PICO_BOARD}"
)
```

Команда создаёт макрос `DEVICE_BOARD` со строкой из `PICO_BOARD` — как если бы вы написали `#define DEVICE_BOARD "pico"` в коде, только пишет его сборка.

Проект должен собираться и тогда, когда значение почему-то не пришло, поэтому в `device.h` у макроса есть запасное значение:

``` c
#ifndef DEVICE_BOARD
#define DEVICE_BOARD "unknown"
#endif
```

### 3. Прочитать серийный номер платы

У каждой платы есть уникальный номер — он лежит во флеш-памяти, которую производитель микросхемы прошил на заводе, и одинаков во всех прогонах. Читать его руками не нужно, в SDK есть готовая функция:

``` c
#include "pico/unique_id.h"

    char board_id[PICO_UNIQUE_BOARD_ID_SIZE_BYTES * 2 + 1];
    pico_get_unique_board_id_string(board_id, sizeof(board_id));
```

Функция живёт в отдельной библиотеке SDK, её нужно добавить в сборку рядом с `pico_stdlib`:

``` cmake
target_link_libraries(${PROJECT_NAME}
    pico_stdlib
    pico_unique_id
)
```

Размер массива посчитан так: на каждый байт номера уходит два знака шестнадцатеричной записи плюс завершающий ноль строки.

>[!info] Тот же номер компьютер видит по USB
>Этим номером плата представляется и операционной системе — он же стоит в шапке лога, который пишет ваш скрипт. Автоматическая проверка сверяет два значения: то, что прошивка напечатала сама, и то, что плата сообщила компьютеру. Совпали — значит лог снят с той самой платы, на которой работает ваша прошивка.

### 4. Прочитать сведения о кристалле

Серийный номер — свойство платы. У самого кристалла RP2040 есть собственный опознавательный регистр `CHIP_ID` в блоке `SYSINFO`. Его адрес вы найдёте сами, как в [[п1.2.1 Мигание светодиодом через регистр#2. Найти адреса регистров в документации\|п1.2.1]]:

| Что ищем | Где смотреть |
| --- | --- |
| Базовый адрес блока `SYSINFO` | [[RP2040 Datasheet.pdf#page=25\|раздел «2.2. Address Map»]] |
| Описание регистра `CHIP_ID` и его полей | [[RP2040 Datasheet.pdf#page=305\|раздел «2.20. Sysinfo»]] |

Чтение — знакомое обращение по адресу, как в [[п1.2.1 Мигание светодиодом через регистр#3. Заменить вызовы функции на запись по адресу\|п1.2.1, шаг 3]], только там по такому указателю писали, а здесь читают:

``` c
    volatile uint32_t *chip_id = (uint32_t *)(SYSINFO_BASE + SYSINFO_CHIP_ID_OFFSET);
    uint32_t id = *chip_id;
```

Слово `volatile` здесь по той же причине, что и в первом задании занятия 1.2: за адресом не переменная, а регистр устройства.

В одном тридцатидвухразрядном слове лежат три поля: производитель, номер изделия и ревизия кристалла. Их границы описаны в документации, а имена масок и сдвигов — в заголовочном файле SDK `hardware/regs/sysinfo.h`:

``` c
    uint32_t manufacturer = (id & SYSINFO_CHIP_ID_MANUFACTURER_BITS) >> SYSINFO_CHIP_ID_MANUFACTURER_LSB;
```

Читается так: маска оставляет от слова только разряды нужного поля, сдвиг переносит их в младшие разряды. Разберите так все три поля: `manufacturer`, `part` и `revision`.

>[!info] Зачем в паспорте ревизия кристалла
>Микросхемы одного названия выпускаются партиями, и между ревизиями бывают отличия в поведении — часть из них описана в разделе errata документации. Когда прибор ведёт себя не так, как у соседа с виду такой же платой, ревизия — первое, что стоит сравнить.

### 5. Собрать паспорт и показать его

Всё, что нужно `device.c`, приходит из четырёх заголовочных файлов — своего, стандартного вывода и двух от SDK:

``` c
#include "device.h"

#include <stdio.h>
#include "pico/unique_id.h"
#include "hardware/regs/addressmap.h"
#include "hardware/regs/sysinfo.h"
```

`pico/unique_id.h` даёт функцию чтения серийного номера, `hardware/regs/addressmap.h` — базовый адрес `SYSINFO_BASE`, `hardware/regs/sysinfo.h` — смещение регистра и имена масок. Пару `hardware/regs/*` вы уже подключали в [[п1.2.1 Мигание светодиодом через регистр#3. Заменить вызовы функции на запись по адресу\|п1.2.1, шаг 3]] — там таким же способом брались база и смещение для блока `SIO`.

Функция `device_info()` печатает пять строк, по строке на пару «ключ — значение»:

``` c
    printf("project: %s\n", DEVICE_PROJECT);
    printf("repo: %s\n", DEVICE_REPO);
    printf("board: %s\n", DEVICE_BOARD);
    printf("serial: %s\n", board_id);
    printf("chip: manufacturer 0x%03x, part 0x%04x, revision %u\n", manufacturer, part, revision);
```

Формат «ключ: значение» выбран не для красоты: такую строку одинаково легко читает и человек, и программа. Ваш скрипт разберёт её по двоеточию, не угадывая, где что.

Печатается паспорт напрямую, а не макросами журнала: он не должен исчезать при пониженном пороге вывода.

Строки о самой прошивке в паспорте нет: о ней отвечает команда `v`. Разделение простое — `v` рассказывает о программе, `i` о железе и происхождении, и каждая команда даёт свой ответ целиком.

Имя устройства и версия переехали в `device.h`, а печатает их `log_version()`. Подключите в `log.c` заголовок `device.h` — сама функция при этом не меняется:

``` c
void log_version(void)
{
    printf("device: %s %s, built %s %s, log level %d\n",
           DEVICE_NAME, FIRMWARE_VERSION, __DATE__, __TIME__, LOG_LEVEL);
}
```

А в обработчик команд `main.c` добавьте ветку для символа `i`, вызывающую `device_info()`.

### 7. Создать скрипт проверки

Создайте в папке `134-led-module` файл `check-1-3-7.py` — рядом с `main.c`. Наберите в нём программу целиком.

Скрипт посылает единственную команду `i` и записывает всё, что пришло в ответ. Ответ читается не по числу строк, а по времени: двух секунд хватает, чтобы паспорт пришёл целиком, и скрипт не зависнет, если строк окажется меньше.

>[!success] Должно получиться так
> ```python
> # Проверка задания п1.3.7 на устройстве: запрашивает у платы паспорт командой i
> # и записывает ответ в файл device-1-3-7.log.
>
> import time
> from datetime import datetime
>
> import serial
> from serial.tools import list_ports
>
> VENDOR_ID = 0x2E8A
> PRODUCT_ID = 0x000A
>
> TASK = "1.3.7"
> PROJECT = "134-led-module"
> LOG_NAME = "device-1-3-7.log"
> COMMAND = "i"
> ANSWER_S = 2
>
>
> def find_board():
>     for port in list_ports.comports():
>         if port.vid == VENDOR_ID and port.pid == PRODUCT_ID:
>             return port
>     return None
>
>
> def ask_passport(board):
>     exchange = []
>     with serial.Serial(board.device, timeout=0.5) as port:
>         time.sleep(0.2)
>         port.reset_input_buffer()
>         started = time.monotonic()
>         port.write(COMMAND.encode("ascii"))
>         exchange.append((time.monotonic() - started, "-->", COMMAND))
>         while time.monotonic() - started < ANSWER_S:
>             line = port.readline().decode("ascii", "replace").strip()
>             if line:
>                 exchange.append((time.monotonic() - started, "<--", line))
>                 print(line, end="\r\n")
>     return exchange
>
>
> def write_log(board, exchange):
>     with open(LOG_NAME, "w", encoding="utf-8") as log:
>         log.write("задание: " + TASK + "\n")
>         log.write("проект: " + PROJECT + "\n")
>         log.write("устройство: %04x:%04x\n" % (board.vid, board.pid))
>         log.write("серийный номер: " + str(board.serial_number) + "\n")
>         log.write("порт: " + board.device + "\n")
>         log.write("начало: " + datetime.now().isoformat(timespec="seconds") + "\n")
>         for moment, direction, text in exchange:
>             log.write("%8.3f %s %s\n" % (moment, direction, text))
>         log.write("итог: принято строк %d\n" % (len(exchange) - 1))
>
>
> board = find_board()
>
> if board is None:
>     print("Плата не найдена. Проверьте кабель и запишите на плату прошивку задания.", end="\r\n")
> else:
>     print("Плата на порту " + board.device + ", спрашиваю паспорт", end="\r\n")
>     exchange = ask_passport(board)
>     write_log(board, exchange)
>     print("Паспорт записан в " + LOG_NAME, end="\r\n")
> ```
