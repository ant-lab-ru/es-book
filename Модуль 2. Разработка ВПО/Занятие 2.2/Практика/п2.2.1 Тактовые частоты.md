**Результат** — создан сквозной проект занятия `221-command-time`. По команде `clk_info` прибор печатает частоты своих тактовых сигналов. Для каждого сигнала он называет две частоты. Первую настроил SDK, вторую намерил блок измерения частоты. Отдельной строкой прибор печатает частоту кольцевого генератора ROSC.
^intro

## Задание

### Что должно получиться

- [ ] В папке `es-student` создан проект `221-command-time` по образу `211-command-usb`
- [ ] В проекте появился модуль `clock` с функцией `clk_info()` и команда `clk_info`
- [ ] Для `clk_ref`, `clk_sys`, `clk_peri`, `clk_usb` и `clk_adc` печатаются настроенная и измеренная частоты
- [ ] Отдельной строкой печатается измеренная частота ROSC
- [ ] Рядом с `main.c` лежит `device-2-2-1.log` с ответом платы

### Как проверить

1. **Две частоты сходятся.** Настроенная и измеренная частоты каждого сигнала расходятся не больше чем на пару килогерц. У `clk_ref` это 12 МГц, у `clk_sys` и `clk_peri` 125 МГц, у `clk_usb` и `clk_adc` 48 МГц.
2. **ROSC идёт своим ходом.** Его частота лежит между 1,8 и 12 МГц и не совпадает с номинальными 6,5 МГц. Сравните своё число с числами соседей. У каждой платы оно своё.
3. **Автоматическая проверка курса принимает задание.** Она ищет в `CMakeLists.txt` имя проекта `221_command_time` и модуль `clock` в сборке. В `device.h` проверяет имя проекта в паспорте. В `clock/clock.c` ищет вызовы `clock_get_hz()` и `frequency_count_khz()` и константу SDK для ROSC. В `main.c` проверяет строку `clk_info` в таблице команд. Затем проверка собирает прошивку и читает лог. В нём должны быть все пять сигналов, у каждого настроенная частота совпадает с ожидаемой, а измеренная отличается от неё не больше чем на 1 %. Частота ROSC должна лежать между 1,8 и 12 МГц. Паспорт по команде `info` должен называть проект `221-command-time`.

### 2. Завести модуль часов

Создайте в проекте папку `clock` с файлами `clock.h` и `clock.c` и добавьте их в сборку. Модуль заводится так же, как модуль памяти в [[п2.1.3 Системная память#1. Завести модуль памяти|п2.1.3, шаг 1]].

В `clock.c` понадобятся три заголовка. `<stdio.h>` нужен ради `printf()`, `"pico/stdlib.h"` ради типов SDK, а `"hardware/clocks.h"` ради функций работы с тактовыми сигналами.

Команда заводится как прежде. `main.c` подключает `"clock.h"`. Обработчик `cmd_clk_info()` вызывает `clk_info()`, а в массив `commands` дописывается строка `{ "clk_info", cmd_clk_info }`.

### 3. Прочитать настроенные частоты

Частоты тактовых сигналов настраивает код SDK ещё до `main()`. Как он это делает, разбирает [[т2.2.2 Источник времени#Частоту задаёт прошивка|т2.2.2, раздел «Частоту задаёт прошивка»]]. Настроенную частоту SDK запоминает и отдаёт функцией `clock_get_hz()`:

``` c
uint32_t sys_hz = clock_get_hz(clk_sys);
```

Аргумент называет сигнал. Имена `clk_ref`, `clk_sys`, `clk_peri`, `clk_usb` и `clk_adc` объявлены в заголовке `hardware/clocks.h`. Функция возвращает частоту в герцах. В таблице прибора все частоты будут в килогерцах, поэтому её значение делится на 1000.

>[!info] Настроенная частота записана, а не измерена
>`clock_get_hz()` не смотрит на сигнал. Она возвращает число, которое SDK записал, когда настраивал сигнал. Если настройка по какой-то причине не удалась, число останется прежним. Поэтому в следующем шаге частоту измеряют.

### 4. Измерить частоты

В RP2040 есть блок измерения частоты. Он считает периоды выбранного сигнала за интервал, отмеренный по `clk_ref`. Устройство блока описано в [[RP2040 Datasheet.pdf#page=187|RP2040 Datasheet, раздел «2.15.4. Frequency Counter»]]. SDK запускает счёт функцией `frequency_count_khz()`. Она возвращает частоту в килогерцах:

``` c
uint32_t sys_khz = frequency_count_khz(CLOCKS_FC0_SRC_VALUE_CLK_SYS);
```

Аргумент выбирает измеряемый сигнал. Это код из регистра `FC0_SRC`. Откройте описание регистра в [[RP2040 Datasheet.pdf#page=209|RP2040 Datasheet, раздел «2.15.7. List of Registers», таблица 244]] и найдите коды пяти сигналов и кольцевого генератора.

В SDK у каждого кода есть константа с тем же значением. Они лежат в файле `hardware/regs/clocks.h`. Найдите их поиском по файлу.

В Git Bash:

``` bash
grep FC0_SRC_VALUE "$PICO_SDK_PATH/src/rp2040/hardware_regs/include/hardware/regs/clocks.h"
```

В PowerShell:

``` powershell
Select-String FC0_SRC_VALUE "$env:PICO_SDK_PATH\src\rp2040\hardware_regs\include\hardware\regs\clocks.h"
```

>[!success] Должно получиться так
> ```
> #define CLOCKS_FC0_SRC_VALUE_NULL _u(0x00)
> #define CLOCKS_FC0_SRC_VALUE_PLL_SYS_CLKSRC_PRIMARY _u(0x01)
> #define CLOCKS_FC0_SRC_VALUE_PLL_USB_CLKSRC_PRIMARY _u(0x02)
> #define CLOCKS_FC0_SRC_VALUE_ROSC_CLKSRC _u(0x03)
> ...
> #define CLOCKS_FC0_SRC_VALUE_CLK_REF _u(0x08)
> #define CLOCKS_FC0_SRC_VALUE_CLK_SYS _u(0x09)
> ```
>
>| Сигнал | Код в `FC0_SRC` | Константа SDK |
>| --- | --- | --- |
>| `clk_ref` | `0x08` | `CLOCKS_FC0_SRC_VALUE_CLK_REF` |
>| `clk_sys` | `0x09` | `CLOCKS_FC0_SRC_VALUE_CLK_SYS` |
>| `clk_peri` | `0x0a` | `CLOCKS_FC0_SRC_VALUE_CLK_PERI` |
>| `clk_usb` | `0x0b` | `CLOCKS_FC0_SRC_VALUE_CLK_USB` |
>| `clk_adc` | `0x0c` | `CLOCKS_FC0_SRC_VALUE_CLK_ADC` |
>| ROSC | `0x03` | `CLOCKS_FC0_SRC_VALUE_ROSC_CLKSRC` |

У ROSC строка без настроенной частоты. Это не тактовый сигнал кристалла, а генератор. SDK его частоту не настраивает и не хранит.

### 5. Собрать clk_info

Каждая строка таблицы состоит из имени сигнала и двух чисел. Печать строки удобно вынести в отдельную функцию, как `row()` в `mem_info`:

``` c
static void row(const char *name, uint32_t set_khz, uint32_t measured_khz)
{
    printf("%-8s %9u %12u\n", name, (unsigned)set_khz, (unsigned)measured_khz);
}
```

Вот первая строка таблицы целиком. Остальные четыре пишутся по этому образцу:

``` c
row("clk_ref", clock_get_hz(clk_ref) / 1000, frequency_count_khz(CLOCKS_FC0_SRC_VALUE_CLK_REF));
```

>[!success] Должно получиться так
> ```c
> void clk_info(void)
> {
>     // шапка таблицы: сигнал, настроенная частота, измеренная частота
>
>     // clk_ref, clk_sys, clk_peri, clk_usb, clk_adc — clock_get_hz() в кГц и frequency_count_khz()
>
>     // rosc — прочерк вместо настроенной частоты и измеренная частота
> }
> ```

| Что нужно написать | Где это разбиралось |
| --- | --- |
| Модуль из двух файлов, его место в `add_executable()` и в путях заголовков | [[п2.1.3 Системная память#1. Завести модуль памяти\|п2.1.3, шаг 1]] |

| Прочерк в строке ROSC через `%9s` и строку `"-"` | здесь, шаг 5 |

### 6. Сверить частоты

Соберите проект, запишите прошивку, откройте терминал и наберите `clk_info`.

>[!success] Должно получиться так
> ```
> signal     set_khz measured_khz
> clk_ref      12000        12001
> clk_sys     125000       125000
> clk_peri    125000       125000
> clk_usb      48000        48000
> clk_adc      48000        48000
> rosc             -         5774
> ```

Настроенные частоты совпадают с таблицей из [[т2.2.2 Источник времени#Частоту задаёт прошивка|т2.2.2]]. Измеренные частоты расходятся с ними на один-два килогерца. Это погрешность самого счёта, а не сигнала. Блок считает целые периоды за короткий интервал. Последний период он может не досчитать.

Частота ROSC у вас будет своей. У платы из примера она на 11 % ниже номинальных 6,5 МГц. Кварц за сутки уходит не больше чем на 30 миллионных долей. Сравните два числа, и станет ясно, почему время в прошивке берут от кварца.

>[!bug] Измеренная частота равна нулю
>Скорее всего, в `frequency_count_khz()` передан не тот код. Сверьте константы с таблицей из шага 4. Константа `CLOCKS_FC0_SRC_VALUE_NULL` выбирает пустой источник, и блоку нечего считать.
