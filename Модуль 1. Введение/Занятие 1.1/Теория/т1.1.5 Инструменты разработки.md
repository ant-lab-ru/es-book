## От исходного текста к машинным командам

Процессор выполняет инструкции из фиксированного набора — мы говорили об этом во втором разделе занятия, когда разбирали определение процессора. А программа на языке C — обычный текстовый файл, и ни одна его строка инструкцией процессора не является. Переводит одно в другое компилятор.

![[Компилятор#^def]]

В определении существенны последние слова: *для конкретной аппаратной платформы*. Наборы инструкций у разных процессоров разные, поэтому результат компиляции жёстко привязан к архитектуре: программа, скомпилированная для процессора x86 персонального компьютера, на ядре ARM Cortex-M не пойдёт — и наоборот. Стандартный компилятор языка C — это [[GCC (Arm GNU Toolchain)#^def|GCC]] (GNU Compiler Collection), свободный компилятор, существующий в вариантах для десятков архитектур.

## Кросс-компиляция

Когда вы разрабатываете программу для персонального компьютера, она компилируется и выполняется на одном и том же процессоре. С микроконтроллером так не выйдет: как мы выяснили в третьем разделе, у него нет ни операционной системы, ни памяти, ни средств ввода, чтобы запустить на нём компилятор. Получается уже знакомое вам по описанию рабочего места разделение: компиляция идёт на [[Целевое устройство#^def|хосте]] с процессором x86, а выполняться программа будет на целевом устройстве с ядром ARM Cortex-M0+.

![[Кросс-компиляция#^def]]

Для микроконтроллеров с ядрами ARM Cortex-M служит кросс-компилятор `arm-none-eabi-gcc` — тот же GCC, но порождающий инструкции ARM. Его имя читается как паспорт целевой платформы: `arm` — архитектура целевого процессора; `none` — на целевом устройстве нет операционной системы; `eabi` (*embedded application binary interface*) — соглашение о формате двоичных файлов и вызовах функций для встраиваемых систем.

## Набор инструментов компиляции

Компилятор — не единственная программа, которая участвует в создании прошивки. Его результат ещё не готов к загрузке на плату: проект состоит из многих файлов, каждый компилируется отдельно, и получившиеся части нужно свести вместе и преобразовать в формат, пригодный для записи. Этим заняты ещё несколько программ, и распространяются они вместе с компилятором, последовательно передавая друг другу результат.

![[Набор инструментов компиляции#^def]]

Ставить эти программы по отдельности вам не придётся: устанавливая `arm-none-eabi-gcc`, вы получаете весь набор целиком. В документации и в разговоре набор чаще называют английским словом *toolchain*, и вторая половина слова — *chain*, «цепочка» — здесь по делу: программы не лежат рядом, а выстроены друг за другом. Приставка `arm-none-eabi` стоит в имени каждой из них:

- `arm-none-eabi-gcc` — компилятор: переводит файлы `.c` в объектные файлы `.o`;
- `arm-none-eabi-as` — [[Ассемблер#^def|ассемблер]]: переводит в машинные команды текст на языке ассемблера, который встречается в стартовом коде SDK;
- `arm-none-eabi-ld` — [[Компоновщик#^def|компоновщик]]: объединяет объектные файлы в единый образ;
- `arm-none-eabi-objcopy`, `objdump`, `size` — утилиты для преобразования формата файла и осмотра готового образа.

Вызывать их вручную тоже не придётся: этим займётся система сборки, о которой пойдёт речь ниже.

Через какие шаги проходит код внутри набора и какие файлы появляются на каждом шаге, мы разберём на занятии 1.3, когда будем говорить о ВПО и его формах. Сейчас достаточно знать результат: на выходе получается файл `blink.uf2` — прошивка, готовая к загрузке на плату. Там же объяснится, зачем в практической части в проект копируется файл `memmap_default.ld` из SDK: он описывает набору инструментов, какая память есть на этом чипе и по каким адресам она расположена.

## SDK: готовые компоненты производителя

Набор инструментов переводит исходный код в прошивку, но не отвечает на вопрос, откуда этот код взять. Даже для мигания светодиодом одного вашего `main.c` мало: прежде чем дело дойдёт до вызова `main()`, микроконтроллер нужно подготовить к работе — настроить тактирование, инициализировать память. Начинать первый проект с написания такого кода — значит начинать с самого сложного. Производители решают эту задачу поставкой SDK.

![[SDK (Набор инструментов разработки)#^def]]

Для [[RP2040#^def|RP2040]] производитель поставляет [[pico-sdk#^def|pico-sdk]]. В него входят стартовый код, выполняющийся до `main()`, функции работы с периферией, описание сборки, примеры проектов и документация. Благодаря функциям SDK ваша первая программа уместится в несколько строк:

```c
// подготовить вывод: отдать его блоку GPIO и настроить на выход
gpio_init(PICO_DEFAULT_LED_PIN);
gpio_set_dir(PICO_DEFAULT_LED_PIN, GPIO_OUT);

// зажечь светодиод на полсекунды
gpio_put(PICO_DEFAULT_LED_PIN, 1);
sleep_ms(500);
```

Распространяется pico-sdk как Git-репозиторий — здесь вы впервые встретитесь на практике с системой контроля версий, о которой шла речь в предыдущем разделе: SDK не скачивается архивом, а клонируется командой `git clone`. Путь к склонированной копии записывается в переменную среды `PICO_SDK_PATH` — по ней инструменты сборки и находят SDK на диске.

## Система сборки

Проект — это ваши собственные файлы плюс десятки файлов SDK. Каждый нужно скомпилировать с правильными параметрами, а потом скомпоновать в правильном порядке. Вызывать инструменты вручную для каждого файла можно, но это трудоёмко и чревато ошибками. Такую работу автоматизирует система сборки.

![[Система сборки#^def]]

В курсе, как и в pico-sdk, используется связка двух инструментов, работающих в два этапа.

1. **Конфигурация.** [[CMake#^def|CMake]] читает описание проекта — файл `CMakeLists.txt`, в котором перечислены исходные файлы и используемые библиотеки SDK, — и порождает сценарий сборки. Этап выполняется командой `cmake` и повторяется только при изменении состава проекта.
2. **Сборка.** [[Make#^def|Make]] исполняет порождённый сценарий: вызывает компилятор и компоновщик для каждого файла. Этап выполняется командой `make` и повторяется после каждого изменения кода, причём перекомпилируются только изменённые файлы.

Обе команды встретятся вам в практической части в точности в этом порядке: сначала `cmake` в новой директории `build`, затем `make` после каждой правки кода.

## Загрузка прошивки

Файл `blink.uf2` получен и лежит на диске хоста. Остался последний шаг — записать его в постоянную память микроконтроллера. Традиционно для этого служит [[Программатор#^def|программатор]] — отдельное устройство между компьютером и микроконтроллером. Платформу для курса мы выбирали в том числе за возможность обойтись без него: в постоянную память RP2040 на заводе записан USB-[[Загрузчик#^def|загрузчик]]. Если удерживать кнопку BOOTSEL при подключении платы к компьютеру, загрузчик покажет плату как USB-накопитель; копирование файла `.uf2` на этот накопитель и есть запись прошивки — после неё микроконтроллер перезапускается и начинает исполнять программу.

Работать с прошивками из командной строки помогает утилита [[picotool#^def|picotool]]: она показывает сведения о собранном файле и о подключённой плате и умеет загружать прошивку без копирования вручную.

## Рабочее место и порядок действий

Остался инструмент, с которого работа фактически начинается, — редактор кода. Мы будем пользоваться [[VS Code#^def|Visual Studio Code]], но принципиальной роли выбор редактора не играет: все инструменты разработки — компилятор, CMake, Make, picotool — вызываются из командной строки, а редактор нужен лишь для удобного набора текста и встроенного терминала. Специальную среду разработки, которая прячет эти вызовы за кнопкой «собрать», мы сознательно не используем: на каждом шаге вы должны видеть, какой инструмент работает и что он делает.

Теперь можно записать полный порядок действий при создании проекта — вместе с инструментом каждого шага.

| Шаг | Инструмент | Команда |
| --- | --- | --- |
| Получение SDK | [[Git#^def\|Git]] | `git clone` |
| Написание исходного кода | [[VS Code#^def\|Visual Studio Code]] | — |
| Конфигурация сборки | [[CMake#^def\|CMake]] | `cmake` |
| Сборка прошивки | [[Make#^def\|Make]] + [[GCC (Arm GNU Toolchain)#^def\|arm-none-eabi-gcc]] | `make` |
| Загрузка на плату | USB-загрузчик, [[picotool#^def\|picotool]] | копирование `.uf2` |

Этот путь вам предстоит пройти вручную в практической части занятия: установить перечисленные инструменты, склонировать pico-sdk, создать проект `blink`, собрать его и запустить на плате. Каждую команду из таблицы вы выполните в терминале, а результат каждого шага увидите в виде конкретного файла и мигающего светодиода.
