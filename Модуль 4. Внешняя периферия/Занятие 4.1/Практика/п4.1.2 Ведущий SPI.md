**Результат** — Pico принимает по USB команды чтения и записи одного байта по SPI. С шестиконтактным модулем вы читаете идентификатор датчика.
^intro

## Задание

### Что должно получиться

- [ ] Проект `411-i2c-spi` собирается с общими библиотеками курса.
- [ ] `help` показывает `spi_write` и `spi_read`.
- [ ] С шестиконтактным BME280 чтение возвращает ID. С четырёхконтактным модулем лог содержит нулевой ответ.

### Как проверить

1. В USB-терминале `help` показывает команды обеих шин.
2. Нумерованный скрипт сохраняет в `device-4-1-2.log` ответ `0x60` от BME280 или `0x00` со свободного MISO.
3. Приёмка проверяет сборку и команды SPI0. Лог без датчика принимается с предупреждением.

## Ход работы

### 1. Добавить ведущий SPI

Продолжайте проект `411-i2c-spi`. В `CMakeLists.txt` добавьте `hardware_spi` к зависимостям цели `platform`. В `platform.h` объявите константу `PLATFORM_SPI_CS_COUNT = 2` и обе функции обмена из блока ниже.

В `platform.c` подключите `hardware/spi.h`. Добавьте в перечисление `SPI_CS_HOLD_US = 2`. Перед `platform_master_init()` задайте массив `static const uint spi_cs_pins[PLATFORM_SPI_CS_COUNT] = {16, 5};`. Вставьте настройку SPI в конец `platform_master_init()`.

>[!info] Настройка SPI0
>```c
>     for (uint cs = 0; cs < PLATFORM_SPI_CS_COUNT; cs++)
>     {
>         uint pin = spi_cs_pins[cs];
>         gpio_init(pin);
>         gpio_put(pin, 1);
>         gpio_set_dir(pin, GPIO_OUT);
>     }
>
>     spi_init(spi0, BUS_BAUD);
>     spi_set_format(spi0, 8, SPI_CPOL_1, SPI_CPHA_1, SPI_MSB_FIRST);
>     gpio_set_function(2, GPIO_FUNC_SPI);  // SCK
>     gpio_set_function(3, GPIO_FUNC_SPI);  // MOSI
>     gpio_pull_down(4);
>     gpio_set_function(4, GPIO_FUNC_SPI);  // MISO
>```

У GP4 слабая внутренняя подтяжка к земле. Она задаёт ноль, когда на MISO никто не отвечает. Выход подключённого датчика при этом может передать и ноль, и единицу.

Добавьте функции обмена в `platform.c`.

>[!info] Обмен по SPI0
>```c
> void platform_spi_write(uint8_t cs, uint8_t command, uint8_t value)
> {
>     const uint8_t bytes[] = {command, value};
>     gpio_put(spi_cs_pins[cs], 0);
>     spi_write_blocking(spi0, bytes, sizeof(bytes));
>     busy_wait_us_32(SPI_CS_HOLD_US);
>     gpio_put(spi_cs_pins[cs], 1);
> }
>
> uint8_t platform_spi_read(uint8_t cs, uint8_t command, uint8_t pause_us)
> {
>     uint8_t value;
>     gpio_put(spi_cs_pins[cs], 0);
>     spi_write_blocking(spi0, &command, 1);
>     if (pause_us != 0)
>     {
>         busy_wait_us_32(pause_us);
>     }
>     spi_read_blocking(spi0, 0x00, &value, 1);
>     busy_wait_us_32(SPI_CS_HOLD_US);
>     gpio_put(spi_cs_pins[cs], 1);
>     return value;
> }
>```

В режиме 3 линия SCK в покое высокая. При чтении ведущий держит CS низким, отправляет управляющий байт и выдаёт ещё восемь тактов для приёма ответа. Для BME280 пауза между байтами равна нулю. См. [[т4.1.5 Контроллеры I²C и SPI RP2040#Пример SPI|пример SPI в теории]].

### 2. Добавить USB-команды SPI

Откройте `logic/api/api-callbacks.c`. После `read_byte()` добавьте проверку номера CS. Обработчики SPI разместите рядом с обработчиками I²C.

>[!info] Разбор CS и чтение в `api-callbacks.c`
>```c
> static bool read_cs(const char *text, uint8_t *cs)
> {
>     return read_byte(text, cs) && *cs < PLATFORM_SPI_CS_COUNT;
> }
>
> static void cmd_spi_read(const command_t *command)
> {
>     uint8_t cs, control, pause_us = 0;
>     if ((command->argc != 2 && command->argc != 3) ||
>         !read_cs(command->argv[0], &cs) ||
>         !read_byte(command->argv[1], &control) ||
>         (command->argc == 3 && !read_byte(command->argv[2], &pause_us)))
>     {
>         puts("error: usage spi_read <cs> <command> [pause_us]");
>         return;
>     }
>
>     uint8_t value = platform_spi_read(cs, control, pause_us);
>     printf("spi: cs 0x%02X command 0x%02X value 0x%02X\n", cs, control, value);
> }
>```

>[!info] Обработчик записи в `api-callbacks.c`
>```c
> static void cmd_spi_write(const command_t *command)
> {
>     uint8_t cs, control, value;
>     if (command->argc != 3 || !read_cs(command->argv[0], &cs) ||
>         !read_byte(command->argv[1], &control) ||
>         !read_byte(command->argv[2], &value))
>     {
>         puts("error: usage spi_write <cs> <command> <value>");
>         return;
>     }
>
>     platform_spi_write(cs, control, value);
>     printf("spi: cs 0x%02X command 0x%02X sent 0x%02X\n", cs, control, value);
> }
>```

Добавьте две записи в конец `api_commands` внутри массива. Справка появится в выводе `help` из таблицы, как в [[п2.3.7 Железо и логика#2. Разделить api на механизм и содержание|шаблоне API]].

>[!info] Записи для SPI в таблице команд
>```c
>     {"spi_write", "<cs> <command> <value>", cmd_spi_write},
>     {"spi_read", "<cs> <command> [pause_us]", cmd_spi_read},
>```

### 3. Подключить датчик

![[Монтаж ведущего SPI и BME280.excalidraw|100%]]

С шестиконтактным BME280 снимите питание. Отключите соединения I²C с датчика, включая прежние подключения CSB и SDO. Соберите цепь по схеме. Выход выбора `CS 0x00` расположен на GP16. GP5 оставьте свободным до п4.1.5.

>[!info] Если у модуля четыре контакта
>Оставьте датчик на I²C и оставьте GP4 свободным. Ведущий всё равно передаст команду по SPI. На обратной линии подтяжка даст байт `0x00`, поэтому запустите скрипт в режиме без датчика на SPI.

>[!info] Подтяжки SPI
>Выходы SPI активно задают уровни. У BME280 есть внутренняя подтяжка CSB. Ведущий выставляет высокий уровень CS перед переводом GPIO в режим выхода. Поэтому на учебном стенде отдельный резистор CS не нужен. Подтяжка MISO задаёт исходный уровень свободного входа.

### 4. Проверить SPI и снять лог

Соберите проект и загрузите бинарный файл на Pico. Наберите `help` и проверьте, что список содержит команды обеих шин. Закройте терминал и скопируйте [[check-4-1-2.py]] в папку проекта.

Для шестиконтактного датчика, подключённого по SPI, запустите:

```bash
python check-4-1-2.py
```

Ниже приведён конец вывода после справки.

>[!success] Должно получиться так
>```text
> --> spi_read 0x00 0xD0
> <-- spi_read 0x00 0xD0
> <-- spi: cs 0x00 command 0xD0 value 0x60
> Обмен записан в device-4-1-2.log
>```

С четырёхконтактным модулем запустите:

```bash
python check-4-1-2.py --without-sensor
```

Ниже приведён конец вывода после справки.

>[!success] Должно получиться так
>```text
> --> spi_read 0x00 0xD0
> <-- spi_read 0x00 0xD0
> <-- spi: cs 0x00 command 0xD0 value 0x00
> Предупреждение. SPI вернул 0x00 без датчика на шине.
> Обмен записан в device-4-1-2.log
>```

Отправьте лог в обоих вариантах. Приёмка засчитывает нулевой ответ в режиме без датчика с предупреждением. Если шестиконтактный модуль подключён по SPI и вернул ноль, проверьте соединения.

### 5. Вернуть датчик на I²C

Если переставляли шестиконтактный модуль на SPI, снимите питание и восстановите соединения I²C по [[п4.1.1 Ведущий I²C#5. Подключить датчик|схеме первой практики]]. После включения снова прочитайте ID по I²C. Питание выключают, потому что после активного CSB датчик остаётся в режиме SPI до следующего включения. Четырёхконтактный модуль уже на I²C.
