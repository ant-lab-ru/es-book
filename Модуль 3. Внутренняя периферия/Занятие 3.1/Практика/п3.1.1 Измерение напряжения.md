В логе она ищет три ответа `get_voltage` в формате `voltage: <напряжение> V` со значениями от 0 до 3,3 В и паспорт с именем проекта `311-adc`.

Так же вы создавали проект `239-two-buttons` в [[п2.3.9 Изменение требований#1. Создать проект из шаблона|п2.3.9, шаг 1]].

### 2. Найти вход АЦП

Откройте [[RP2040 Datasheet.pdf#page=558|RP2040 Datasheet, раздел «4.9. ADC and Temperature Sensor»]]. Входы АЦП с 0 по 3 стоят на выводах GPIO26–GPIO29. Нам нужен канал 0, вывод GP26. На плате Pico это ножка 31. Рядом с ней, на ножке 33, стоит земля АЦП `AGND`, а на ножке 36 выход `3V3` ([[Pico Datasheet.pdf#page=8|Pico Datasheet, раздел «2.1. Pinout»]]).

>[!warning] Не больше 3,3 В
>Не подавайте на GP26 напряжение выше 3,3 В, например с вывода `VBUS` или `VSYS`. Через защитные диоды вывода потечёт ток, и измерение будет неверным, а вывод можно испортить.

### 3. Подключить АЦП в platform

С АЦП работает только модуль `platform`, как с выводами светодиода и кнопки (правила П4 и П13 [[ТЗ 2.3 Шаблон проектирования#4. Правила|ТЗ 2.3]]). Функции АЦП лежат в библиотеке SDK `hardware_adc`. Подключите её к `platform` в `CMakeLists.txt`:

```cmake
target_link_libraries(platform PRIVATE
    pico_stdlib
    hardware_adc
)
```

В `platform.c` добавьте заголовок АЦП, номер вывода и канала и две константы перевода в вольты:

```c
#include "hardware/adc.h"

// вход АЦП: вывод GP26, канал 0
#define ADC_PIN 26
#define ADC_CHANNEL 0

// опорное напряжение АЦП на плате Pico и число уровней 12-разрядного кода
#define ADC_VREF_V 3.3f
#define ADC_LEVELS 4096
```

В конец `platform_init()` добавьте запуск АЦП:

```c
    adc_init();
    adc_gpio_init(ADC_PIN);
```

`adc_init()` сбрасывает модуль и включает его. `adc_gpio_init()` отдаёт вывод аналоговому входу. Она отключает у вывода цифровую часть и подтяжки, которые иначе исказили бы напряжение. Как эти функции устроены внутри, разобрано в [[т3.1.5 Регистры АЦП#Одно измерение по шагам|т3.1.5]].

Теперь функция, которая снимает один отсчёт и переводит его в вольты:

```c
float platform_voltage_read(void)
{
    adc_select_input(ADC_CHANNEL);
    return adc_read() * ADC_VREF_V / ADC_LEVELS;
}
```

`adc_select_input()` выбирает канал, `adc_read()` запускает преобразование, ждёт его конца и возвращает 12-разрядный код от 0 до 4095. Код умножают на опорное напряжение и делят на число уровней. Объявите функцию в `platform.h`:

```c
// напряжение на входе АЦП, выводе GP26, в вольтах
float platform_voltage_read(void);
```

### 4. Добавить команду get_voltage

Новая команда добавляется правкой только `api-callbacks.c` (правило П2 [[ТЗ 2.3 Шаблон проектирования#4. Правила|ТЗ 2.3]]). Обработчик спрашивает напряжение у `platform` и печатает его с тремя знаками после точки. Шаблон не подключал `platform.h` в этот файл, теперь он нужен.

>[!success] Должно получиться так

>
> // напряжение на GP26 у platform, ответ voltage: <напряжение> V
> static void cmd_get_voltage(const command_t *command)
>
> // в таблице команд
> { "get_voltage", "voltage on GP26, ADC input 0", cmd_get_voltage },

### 5. Проверить на плате

Соберите проект и запишите прошивку на плату:

``` bash

cd build
cmake -G "Unix Makefiles" ..

```

Откройте терминал и спросите напряжение. Пока к GP26 ничего не подключено, вывод висит в воздухе, и прибор показывает случайное значение, которое плывёт от запроса к запросу.

>[!success] Должно получиться так
> ```

> voltage: 0.666 V
> get_voltage
> voltage: 0.492 V
> ```

Теперь соедините GP26 перемычкой с `AGND` и спросите ещё раз. Прибор покажет несколько десятков милливольт, а не ровный ноль. Затем соедините GP26 с `3V3`. Прибор покажет чуть меньше 3,3 В. Откуда берутся эти отклонения, разобрано в [[т3.1.3 АЦП RP2040#Разрядность и точность|т3.1.3]]. Опорой АЦП служит его питание, а оно на плате немного ниже 3,3 В и шумит.
