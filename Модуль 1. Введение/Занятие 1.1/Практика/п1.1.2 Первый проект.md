**Результат** — создан проект `112-blink` из четырёх файлов: программа, мигающая светодиодом, и описание её сборки.
^intro

## Задание

### Что должно получиться

- [ ] В папке `pico` создана папка проекта `112-blink`
- [ ] В ней ровно четыре файла: `main.c`, `CMakeLists.txt`, `memmap_rp2040.ld`, `pico_sdk_import.cmake`
- [ ] В `main.c` описано мигание светодиодом на выводе `25`
- [ ] В `CMakeLists.txt` описана сборка прошивки для платы Raspberry Pi Pico

### Как проверить

1. **Состав проекта.** В папке `112-blink` ровно четыре файла и ни одного лишнего.
2. **Сверка с эталоном.** Содержимое `main.c` и `CMakeLists.txt` совпадает с приведённым в конце каждого шага.
3. **Сборка.** Окончательная проверка — в задании [[п1.1.3 Запуск прошивки#^intro|п1.1.3 Запуск прошивки]]: если в файлах есть ошибка, `cmake` или `make` о ней сообщат.

## Ход работы

>[!info] Проект — это папка с исходными файлами
>Всё, что вы создадите в этом задании, — четыре текстовых файла в одной папке. Никаких скрытых настроек, спрятанных в среде разработки, у проекта нет. То, что лежит в папке, и есть проект целиком.

### 1. Создать папку проекта

Перейдите в рабочую папку `pico` и создайте в ней папку `112-blink`: цифры — номер задания, слово — что делает программа.

``` bash
cd ~/Repositories/pico
mkdir 112-blink
cd 112-blink
```

>[!info] Почему из терминала, а не мышью
>Эти команды делают ровно то же, что привычные щелчки: открыть папку, создать папку, войти в неё. Разница в том, что набранное в терминале можно повторить, записать в инструкцию и автоматизировать, а последовательность щелчков — нет.

### 2. Взять из SDK два готовых файла

Два файла из четырёх писать не нужно — они входят в [[pico-sdk#^def|pico-sdk]], их достаточно скопировать в папку проекта.

**Первый — `pico_sdk_import.cmake`.** Возьмите его из `pico-sdk/external/pico_sdk_import.cmake`.

>[!info] Что он делает
>Это вспомогательный сценарий: он находит SDK на диске по переменной среды `PICO_SDK_PATH` и подключает его к проекту. Без него описание сборки не знало бы, где искать библиотеки производителя.

**Второй — скрипт компоновщика.** Возьмите файл `pico-sdk/src/rp2040/pico_platform/memmap_default.ld`, скопируйте в папку проекта и переименуйте в `memmap_rp2040.ld`.

Имя `memmap_default.ld` говорит «раскладка по умолчанию» и ничего не сообщает о том, для какого микроконтроллера она написана. В проекте этот файл будет один, и лучше, чтобы имя называло чип.

![[Что делает скрипт компоновщика.excalidraw|100%]]

Линкер-скрипт — карта памяти микроконтроллера: по каким адресам начинается постоянная память и сколько её, где оперативная, сколько отвести под стек. Компоновщик читает эти правила и расставляет части программы по адресам, когда собирает образ. Сам файл остаётся на вашем компьютере — в микроконтроллер уезжают только адреса, которые он задал.

Откройте скопированный файл, и вы увидите одну строку:

``` ld
INCLUDE "memmap_default.incl"
```

Сама карта памяти в него не входит — она собрана из 44 файлов внутри SDK: девять описывают, где какая память, остальные — что в какую область попадёт. В проекте лежит обёртка, которая на них ссылается; менять её не нужно, но знать, что за ней стоит, стоит.

### 3. Написать main.c

Создайте в папке проекта файл `main.c`. Прежде чем писать, посмотрите, из чего он будет состоять.

![[Структура main.c.excalidraw|100%]]

**Подключите заголовочные файлы.** Функции для работы с микроконтроллером написаны за вас и лежат в SDK; чтобы ими пользоваться, их нужно объявить в своей программе.

``` c
#include "pico/stdlib.h"
#include "hardware/gpio.h"
```

Первый файл даёт базовые типы и функцию задержки `sleep_ms`, второй — функции работы с выводами микроконтроллера.

**Задайте номер вывода.** Светодиод на плате Raspberry Pi Pico подключён к выводу `25`.

``` c
const uint LED_PIN = 25;
```

Число `25` встретится в программе трижды. Названная константа избавляет от необходимости его помнить и позволяет поменять вывод в одном месте.

**Создайте точку входа.** Исполнение программы начинается с функции `main`.

``` c
int main()
{
    // весь дальнейший код пишем здесь
}
```

**Подготовьте вывод к работе.** Первое, что делает программа, — настраивает вывод: инициализирует его и задаёт направление работы.

``` c
    gpio_init(LED_PIN);
    gpio_set_dir(LED_PIN, GPIO_OUT);
```

`gpio_init` включает вывод, `gpio_set_dir` задаёт направление: `GPIO_OUT` означает, что микроконтроллер будет выдавать напряжение, а не считывать его. Обе строки выполняются один раз при включении питания.

**Заведите бесконечный цикл.** Всё, что должно повторяться, помещается внутрь него.

``` c
    while (1)
    {
        // код мигания пишем здесь
    }
```

>[!info] Задумайтесь: почему цикл бесконечный?
>В микроконтроллере нет операционной системы: `main` стартует сразу после подачи питания, и вернуть управление ей некому. Если выйти из `main`, микроконтроллер больше ничего делать не будет. Поэтому программа заканчивается не выходом, а бесконечным циклом, который прервёт только снятие питания.

**Опишите мигание.** Внутри цикла — четыре строки: включить, подождать, выключить, подождать.

``` c
        gpio_put(LED_PIN, 1);
        sleep_ms(250);
        gpio_put(LED_PIN, 0);
        sleep_ms(1000);
```

`gpio_put` задаёт напряжение на выводе. При значении `1` вывод подключается к питанию микроконтроллера. Микроконтроллер RP2040 на плате Raspberry Pi Pico питается от 3,3 В, а значит и напряжение на выводе станет равным 3,3 В. При значении `0` вывод соединяется с `GND`, землёй, и напряжение на выводе становится равным 0,0 В. В документации эти два состояния называют высоким и низким уровнем, но за словами стоят конкретные напряжения. Светодиод светит, когда на выводе 25 напряжение 3,3 В, и не светит, когда на этом выводе напряжение 0,0 В.

`sleep_ms` останавливает выполнение программы на указанное число миллисекунд. Поэтому светодиод будет гореть четверть секунды и гаснуть на секунду.

>[!success] Должно получиться так
>
> ``` c
> #include "pico/stdlib.h"
> #include "hardware/gpio.h"
>
> const uint LED_PIN = 25;
>
> int main()
> {
>     gpio_init(LED_PIN);
>     gpio_set_dir(LED_PIN, GPIO_OUT);
>
>     while (1)
>     {
>         gpio_put(LED_PIN, 1);
>         sleep_ms(250);
>         gpio_put(LED_PIN, 0);
>         sleep_ms(1000);
>     }
> }
> ```

### 4. Описать сборку в CMakeLists.txt

Программа написана, но сама по себе она — текст. Чтобы получить прошивку, нужно описать сборку: из каких файлов собирать, с какими библиотеками, по каким правилам размещать в памяти и в каких форматах выдать результат. Это описание читает [[CMake#^def|CMake]] из файла `CMakeLists.txt`.

![[Структура CMakeLists.txt.excalidraw|100%]]

Создайте файл `CMakeLists.txt` в папке проекта и заполняйте его по частям.

**Версия CMake.** Типовая первая строка любого проекта: ниже этой версии описание понято не будет.

``` cmake
cmake_minimum_required(VERSION 3.15)
```

**Плата и микроконтроллер.** Специфика Pico: по этим двум значениям SDK выберет нужные библиотеки и загрузчик под микросхему памяти, распаянную на плате.

``` cmake
set(PICO_BOARD pico)
set(PICO_PLATFORM rp2040)
```

**Подключение SDK.** Сначала подключается сценарий поиска, затем объявляется проект, затем вызывается инициализация — после неё становятся доступны библиотеки и команды производителя.

``` cmake
include(pico_sdk_import.cmake)

project(112_blink)

pico_sdk_init()
```

Строка `project` — типовая, она задаёт имя проекта. Порядок важен: `pico_sdk_init()` вызывается после объявления проекта.

**Из чего собирать.** Типовая команда: создать цель сборки с именем `112_blink` из перечисленных исходных файлов. У нас он один.

``` cmake
add_executable(112_blink
    ${CMAKE_CURRENT_SOURCE_DIR}/main.c
)
```

**С какими библиотеками.** Тоже типовая: указать, на что опирается ваш код. `pico_stdlib` — основная библиотека SDK, из неё берутся `gpio_init`, `gpio_put`, `sleep_ms`.

``` cmake
target_link_libraries(112_blink
    pico_stdlib
)
```

>[!info] Скобки и переносы строк
>CMake безразлично, записана команда в одну строку или в несколько: значение имеет только то, что стоит внутри скобок. Эти две записи одинаковы, и результат сборки от выбора не зависит:
>
> ``` cmake
> target_link_libraries(112_blink
>     pico_stdlib
> )
>
> target_link_libraries(112_blink pico_stdlib)
> ```
>
>Выбирают по удобству чтения. Одну библиотеку удобно записать в строку. Когда их пять, столбик читается лучше: список виден целиком, а добавление новой библиотеки меняет одну строку, а не всю команду.

**По каким правилам размещать.** Специфика микроконтроллера: указать скрипт компоновщика, скопированный на втором шаге.

``` cmake
pico_set_linker_script(112_blink
    ${CMAKE_CURRENT_SOURCE_DIR}/memmap_rp2040.ld
)
```

**В каких форматах выдать результат.** Специфика Pico: кроме основного образа получить файлы `.bin` и `.uf2` — последний понадобится для записи прошивки в плату.

``` cmake
pico_add_extra_outputs(112_blink)
```

>[!success] Должно получиться так
>
> ``` cmake
> cmake_minimum_required(VERSION 3.15)
>
> set(PICO_BOARD pico)
> set(PICO_PLATFORM rp2040)
>
> include(pico_sdk_import.cmake)
>
> project(112_blink)
>
> pico_sdk_init()
>
> add_executable(112_blink
>     ${CMAKE_CURRENT_SOURCE_DIR}/main.c
> )
>
> target_link_libraries(112_blink
>     pico_stdlib
> )
>
> pico_set_linker_script(112_blink
>     ${CMAKE_CURRENT_SOURCE_DIR}/memmap_rp2040.ld
> )
>
> pico_add_extra_outputs(112_blink)
> ```

### 5. Проверить состав проекта

>[!success] Должно получиться так
>
> ```
> Repositories
> └── pico
>     ├── pico-sdk
>     └── 112-blink
>         ├── main.c
>         ├── CMakeLists.txt
>         ├── memmap_rp2040.ld
>         └── pico_sdk_import.cmake
> ```

Этих четырёх файлов достаточно, чтобы получить работающую прошивку. Два вы написали сами, два взяли из SDK — и все четыре относятся к исходным файлам проекта: именно они, и только они, попадут в репозиторий курса в задании [[п1.1.4 Создание репозитория курса#^intro|п1.1.4 Создание репозитория курса]].

Пока это просто текст, микроконтроллер не может исполнить эти строки. Превратить текст в формат, пригодный для микроконтроллера, — работа инструментов, установленных в первом задании. CMake прочитает описание сборки и составит план работ, компилятор переведёт `main.c` в машинные команды, компоновщик разложит их по адресам из скрипта компоновщика, и на выходе появится файл `112_blink.uf2`.

Этим займёмся в следующем задании — [[п1.1.3 Запуск прошивки#^intro|п1.1.3 Запуск прошивки]]. Там же запишем прошивку в плату и наконец увидим мигающий светодиод.
