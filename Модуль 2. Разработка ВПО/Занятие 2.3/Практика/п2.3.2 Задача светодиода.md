**Результат** — мигание ушло из суперцикла в программную задачу `led-task`. Светодиод выключен, горит или мигает, и состояние меняют команды `led_enable`, `led_disable` и `led_blink`. Период мигания задаёт команда `led_period`. Моменты переключений не уползают от сетки периода.

## Задание

### Что должно получиться

- [ ] Задача `led-task` с перечисляемым типом состояний `led_state_t`, обработчиком на `switch` и действием при входе в состояние
- [ ] Проверка периода `period_elapsed()` отсчитывает следующее срабатывание от прошлого
- [ ] Команды `led_enable`, `led_disable`, `led_blink` и `led_period` отвечают состоянием и периодом светодиода
- [ ] В суперцикле нет ни переменных мигания, ни записи в вывод светодиода
- [ ] Проект собирается с ключом `-Wall` без предупреждений
- [ ] Коммит отправлен, проверка `2.3.2` зелёная

### Как проверить

1. **Светодиод слушается команд.** После запуска светодиод мигает раз в секунду. `led_enable` включает его, `led_disable` выключает, `led_blink` возвращает мигание. После `led_period 2000` светодиод мигает раз в две секунды. Период, заданный в состоянии «горит», действует, как только светодиод начнёт мигать.
2. **Ошибки отклоняются.** `led_period` без аргумента, `led_period 5x` и `led_period -1` отвечают `error: usage led_period <period_ms>`. `led_period 0` отвечает отдельным сообщением, и период не меняется.
3. **Автоматическая проверка курса принимает задание.** Проверка статическая. В `led-task.h` она ищет тип `led_state_t` с тремя состояниями и шесть функций задачи. В `led-task.c` она ищет `switch` в обработчике, действие при входе в функции смены состояния и вызов проверки периода. В самой проверке периода она ищет сдвиг метки `+=`: в задании п2.3.6 эта функция переедет в библиотеку, и проверка найдёт её там. Ещё она ищет четыре команды светодиода, ключ `-Wall` и убеждается, что мигания в `main.c` больше нет.

## Ход работы

Теория задания — [[т2.3.3 Программная задача#^intro|т2.3.3]] и [[т2.3.4 Машина состояний#^intro|т2.3.4]]. Требования к светодиоду записаны в Ф3 [[ТЗ 2.3 Прибор|части 1 технического задания]].

### 1. Написать задачу светодиода

Создайте папку `led-task` с файлами `led-task.h` и `led-task.c`. Заголовок задачи разобран в [[т2.3.5 Программный модуль на C#^intro|т2.3.5]]. Возьмите его и добавьте функцию `uint32_t led_task_get_period_ms(void)`.

Перечисляемый тип в курсе встречается впервые. Он даёт имена набору целых значений:

```c
typedef enum {
    LED_STATE_OFF,
    LED_STATE_ON,
    LED_STATE_BLINK,
} led_state_t;
```

Компилятор раздаёт именам значения 0, 1 и 2 по порядку. Переменная типа `led_state_t` хранит одно из них, а `switch` выбирает действие по имени, а не по числу.

>[!success] Должно получиться так
> ```c
> void led_task_init(void)
> {
>     // настраиваем вывод светодиода, период 1000 мс, состояние «мигает»
> }
>
> void led_task_set_state(led_state_t state)
> {
>     // запоминаем состояние и выполняем действие при входе:
>     // «выключен» — гасим, «горит» — зажигаем, «мигает» — первое переключение сразу
> }
>
> void led_task_handle(void)
> {
>     switch (led_state)
>     {
>     // «выключен» и «горит» — ничего не делаем, светодиод установлен при входе
>     // «мигает» — каждые полпериода переключаем светодиод
>     }
> }
> ```

| Что нужно написать | Где это разбиралось |
| --- | --- |
| Состояние на `enum`, `switch` в обработчике, действие при входе | [[т2.3.4 Машина состояний#^intro\|т2.3.4]] |
| Переменные задачи и вспомогательные функции со `static` | [[т2.3.5 Программный модуль на C#^intro\|т2.3.5]] |
| `led_task_set_period_ms()`, которая отказывает в нулевом периоде | [[т2.3.5 Программный модуль на C#^intro\|т2.3.5]] |
| Проверка периода `period_elapsed()` | [[т2.3.3 Программная задача#^intro\|т2.3.3]] |

Проверку периода `period_elapsed(uint64_t *last_us, uint64_t period_us)` положите в `led-task.c`. Следующее срабатывание она отсчитывает от прошлого: `*last_us += period_us`. Если прибор отстал больше чем на период, пропущенные срабатывания не догоняются, а отсчёт начинается заново. Почему так, разобрано в разделе [[т2.3.3 Программная задача#^intro|Программная задача]]. Так требует и Ф3.4.

### 2. Убрать мигание из суперцикла

Удалите из `main.c` константу полупериода, метку прошлого переключения и функцию `blink()`. Модуль `led` из задания [[п1.3.5 Модуль светодиода#^intro|п1.3.5]] больше не нужен: выводом светодиода теперь владеет задача. Удалите его папку и строки в `CMakeLists.txt`.

Перед суперциклом вызовите `led_task_init()`, а в суперцикле вызывайте `led_task_handle()`.

### 3. Добавить команды светодиода

Добавьте в таблицу `api` команды `led_enable`, `led_disable`, `led_blink` и `led_period <period_ms>`. Каждая отвечает состоянием и периодом: `led: blink, period 1000 ms`. Код `led_period` разобран в [[т2.3.8 Протокол и API прибора#^intro|т2.3.8]]. Ответ печатает одна функция, общая для всех четырёх команд.

### 4. Включить предупреждения компилятора

Добавьте в `CMakeLists.txt` перед `add_executable()` строку:

```cmake
add_compile_options(-Wall)
```

Ключ `-Wall` включает предупреждения о коде, который скорее всего написан с ошибкой. `add_compile_options()` отдаёт ключ всем целям проекта. В задании п2.3.6 появятся библиотеки, и он достанется и им.

Соберите проект. Скорее всего, компилятор найдёт старый код. У нас предупреждения нашлись в `device.c` из задания [[п1.3.7 Паспорт устройства#^intro|п1.3.7]]:

```
device.c:27:37: warning: format '%x' expects argument of type 'unsigned int', but argument 2 has type 'uint32_t' {aka 'long unsigned int'} [-Wformat=]
```

На RP2040 тип `uint32_t` объявлен как `long unsigned int`, а `%x` и `%u` ждут `unsigned int`. Размер у них одинаковый, и вывод был верным. Но компилятор прав: формат и аргумент не совпадают. Приведите аргументы к `(unsigned)`. Добейтесь сборки без единого предупреждения, этого требует Н4.

### 5. Проверить в терминале

Запишите прошивку. Светодиод мигает раз в секунду.

>[!success] Должно получиться так
> ```
> led_enable
> led: on, period 1000 ms
> led_disable
> led: off, period 1000 ms
> led_period 2000
> led: off, period 2000 ms
> led_blink
> led: blink, period 2000 ms
> led_period 0
> error: period_ms must be greater than 0
> ```

>[!bug] Светодиод горит ровно, а должен мигать
>Если после `led_blink` светодиод замер, проверьте действие при входе в «мигает». Метка прошлого переключения должна указывать в прошлое, иначе первое переключение случится через целый полупериод от метки. Если светодиод светится тускло, полупериод считается в миллисекундах, а сравнивается с микросекундами.
