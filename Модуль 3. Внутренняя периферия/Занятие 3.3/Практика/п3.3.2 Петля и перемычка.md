**Результат** — модуль UART0 стенда `331-uart` настроен через Pico SDK и проверен петлёй. Сначала строка возвращается внутри модуля, через бит `LBE`, затем через выводы GP0 и GP1 и перемычку между ними. Прибор печатает принятое вместе с признаками ошибок приёма.

![[п3.3.2 Перемычка UART0.excalidraw|100%]]

Перемычка соединяет выход `TX` модуля с его же входом `RX`. На линии один выход, поэтому столкновения драйверов нет.

## Задание

### Что должно получиться

- [ ] UART0 настроен функцией `uart_init()` на 115 200 бит/с в формате 8N1
- [ ] Команда `loop internal` ставит бит `LBE`, команда `loop pins` снимает его и отдаёт модулю GP0 и GP1
- [ ] Задача `uart-task` передаёт строку без ожиданий и отдаёт принятое функции вместе с признаками ошибок
- [ ] Команда `echo <строка>` возвращает строку в обоих режимах, `rx: ping err: none`
- [ ] Лог `device-3-3-2.log` снят с перемычкой, коммит отправлен, проверка `3.3.2` зелёная

### Как проверить

1. **Петля работает в обоих режимах.** В терминале наберите `loop internal` и `echo ping`, затем `loop pins` и снова `echo ping`. Оба раза вернётся `rx: ping err: none`. Снимите перемычку. Строка по-прежнему возвращается в режиме `internal` и пропадает в режиме `pins`.
2. **Лог прогона лежит в проекте.** Скрипт задания записывает обмен в `device-3-3-2.log`. Перемычка стоит весь прогон.
3. **Автоматическая проверка курса принимает задание.** В коде она ищет `uart_init()` для UART0 на 115 200, функцию `GPIO_FUNC_UART`, бит `UART_UARTCR_LBE_BITS`, чтение `UARTRSR` и запись в `UARTECR`. Она проверяет, что прошивка не ждёт линию, а логика не обращается к SDK. В логе она ищет `rx: ping err: none` и строку из 32 символов в обоих режимах и ответы на неверные аргументы.

## Ход работы

Регистры UART и порядок его настройки разобраны в [[т3.3.4 UART RP2040#^intro|т3.3.4]]. Прочитайте статью до начала работы. Это задание опирается на её разделы о порядке настройки, о регистре данных и об ошибках приёма.

### 1. Подключить UART в platform

Функции UART лежат в библиотеке SDK `hardware_uart`. Подключите её к `platform` в `CMakeLists.txt` рядом с `hardware_adc`.

В стенде два модуля UART, второй понадобится в [[п3.3.3 Два модуля и допуск скорости#^intro|п3.3.3]]. Логика выбирает модуль по своему имени, а номер модуля SDK знает только `platform`. Добавьте в `platform.h`.

```c
#include <stddef.h>
#include <stdint.h>

// модули UART: UART0 — GP0 (TX) и GP1 (RX), UART1 — GP8 (TX) и GP9 (RX)
typedef enum {
    PLATFORM_UART0,
    PLATFORM_UART1,
} platform_uart_t;

// признаки ошибок приёма, биты регистра UARTRSR
#define PLATFORM_UART_FE 0x1
#define PLATFORM_UART_PE 0x2
#define PLATFORM_UART_BE 0x4
#define PLATFORM_UART_OE 0x8

// true — петля LBE внутри UART0, выводы GP0 и GP1 модулю не отданы;
// false — петли нет, выводы отданы UART0
void platform_uart_loop_set(bool internal);

// очередь приёма пуста, признаки ошибок сброшены
void platform_uart_clear(platform_uart_t uart);

// кладёт байт в очередь передачи; false — очередь полна
bool platform_uart_put(platform_uart_t uart, uint8_t byte);

// передатчик ещё работает: байты в очереди или в сдвиговом регистре
bool platform_uart_busy(platform_uart_t uart);

// всё принятое с прошлой очистки, не больше size байтов
size_t platform_uart_read(platform_uart_t uart, uint8_t *data, size_t size);

// признаки ошибок приёма с прошлой очистки
uint32_t platform_uart_errors(platform_uart_t uart);
```

В `platform.c` подключите `hardware/uart.h` и добавьте выводы, скорость и функцию, которая переводит имя модуля в указатель SDK.

```c
// выводы модуля UART0
#define UART0_TX_PIN 0
#define UART0_RX_PIN 1

#define UART_BAUD 115200

static uart_inst_t *uart_of(platform_uart_t uart)
{
    return uart == PLATFORM_UART0 ? uart0 : uart1;
}
```

Петля и выводы. Бит `LBE` у SDK отдельной функции не имеет, его ставят в регистре `UARTCR` ([[RP2040 Datasheet.pdf#page=434|RP2040 Datasheet, таблица 433]]). Пока петля включена, выводы модулю не нужны, и им ставят пустую функцию `GPIO_FUNC_NULL`.

```c
void platform_uart_loop_set(bool internal)
{
    uint function = internal ? GPIO_FUNC_NULL : GPIO_FUNC_UART;
    gpio_set_function(UART0_TX_PIN, function);
    gpio_set_function(UART0_RX_PIN, function);

    if (internal)
    {
        hw_set_bits(&uart_get_hw(uart0)->cr, UART_UARTCR_LBE_BITS);
    }
    else
    {
        hw_clear_bits(&uart_get_hw(uart0)->cr, UART_UARTCR_LBE_BITS);
    }
}
```

Очистка, передача и приём. Регистры `UARTRSR` и `UARTECR` — один адрес, в SDK это поле `rsr`. Чтение даёт накопленные признаки ошибок, запись сбрасывает их ([[RP2040 Datasheet.pdf#page=431|таблица 427]]).

```c
void platform_uart_clear(platform_uart_t uart)
{
    uart_inst_t *u = uart_of(uart);

    while (uart_is_readable(u))
    {
        (void)uart_get_hw(u)->dr;
    }

    // запись в UARTECR сбрасывает признаки ошибок
    uart_get_hw(u)->rsr = 0;
}

bool platform_uart_put(platform_uart_t uart, uint8_t byte)
{
    uart_inst_t *u = uart_of(uart);

    if (!uart_is_writable(u))
    {
        return false;
    }

    // место в очереди есть, поэтому uart_putc_raw() не ждёт
    uart_putc_raw(u, byte);
    return true;
}

bool platform_uart_busy(platform_uart_t uart)
{
    return uart_get_hw(uart_of(uart))->fr & UART_UARTFR_BUSY_BITS;
}

size_t platform_uart_read(platform_uart_t uart, uint8_t *data, size_t size)
{
    uart_inst_t *u = uart_of(uart);
    size_t n = 0;

    while (uart_is_readable(u) && n < size)
    {
        data[n++] = uart_get_hw(u)->dr & 0xff;
    }

    return n;
}

uint32_t platform_uart_errors(platform_uart_t uart)
{
    return uart_get_hw(uart_of(uart))->rsr & 0xf;
}
```

Цикл в `platform_uart_clear()` и `platform_uart_read()` не ждёт. Он кончается, как только очередь приёма опустела. Байт кладут в очередь, только если в ней есть место, флаг `TXFF` проверяет `uart_is_writable()`. Готовые функции `uart_getc()` и `uart_puts()` здесь не годятся. Первая ждёт символа и отбрасывает признаки ошибок, вторая ждёт места в очереди. Признаки каждого символа лежат в битах 11:8 регистра данных, но здесь их читают сразу за всю строку из `UARTRSR`.

`BUSY` нужен задаче, чтобы узнать конец передачи. `TXFE` становится единицей раньше, пока последний байт ещё идёт по линии ([[т3.3.4 UART RP2040#Регистр данных UARTDR и флаги UARTFR|т3.3.4]]).

В конец `platform_init()` добавьте запуск модуля. `uart_init()` выполняет первые четыре шага настройки из [[т3.3.4 UART RP2040#Порядок настройки модуля|т3.3.4]], а выводы отдаёт `platform_uart_loop_set()`.

```c
    // делитель, формат 8N1, очереди, включение модуля
    uart_init(uart0, UART_BAUD);
    platform_uart_loop_set(false);
```

### 2. Написать задачу обмена

На 115 200 бит/с символ идёт по линии 87 мкс. Строка из 32 символов — почти 3 мс, и прошивке ждать её нельзя. Поэтому обмен ведёт задача. Она дописывает байты в очередь передачи, пока там есть место. Когда последний стоп-бит ушёл, задача выжидает 1 мс тишины и отдаёт всё принятое функции, полученной при запуске. Создайте `logic/uart-task/uart-task.h`.

```c
// uart-task.h — задача обмена по UART: передаёт байты через один модуль,
// а когда передача кончилась и линия помолчала, отдаёт принятое другим модулем
// функции, переданной при запуске. Что делать с байтами, задача не знает.
#pragma once

#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

#include "platform/platform.h"

// самый длинный обмен: блок из 64 байтов
#define UART_TASK_MAX 64

// принятые байты и признаки ошибок приёма из UARTRSR
typedef void (*uart_task_callback_t)(const uint8_t *data, size_t size, uint32_t errors);

// false — обмен уже идёт или байтов больше UART_TASK_MAX
bool uart_task_start(platform_uart_t tx, platform_uart_t rx, const uint8_t *data, size_t size,
                     uart_task_callback_t on_done);

// вызывается на каждой итерации суперцикла, не ждёт
void uart_task_handle(void);
```

И `logic/uart-task/uart-task.c`.

```c
#include "uart-task/uart-task.h"

#include "systime/systime.h"

#include <string.h>

// пауза после передачи: 1 мс — это 115 битов на 115 200 бит/с, дольше
// 32 битов, после которых приёмник сообщает о последних байтах
#define QUIET_US 1000

typedef enum {
    UART_STATE_IDLE,
    UART_STATE_SEND,
    UART_STATE_QUIET,
} uart_state_t;

static uart_state_t state;
static platform_uart_t tx_uart;
static platform_uart_t rx_uart;
static uint8_t tx_data[UART_TASK_MAX];
static size_t tx_size;
static size_t tx_sent;
static uint64_t quiet_start_us;
static uart_task_callback_t callback;

bool uart_task_start(platform_uart_t tx, platform_uart_t rx, const uint8_t *data, size_t size,
                     uart_task_callback_t on_done)
{
    if (state != UART_STATE_IDLE || size > UART_TASK_MAX)
    {
        return false;
    }

    // в приёмнике не должно остаться ни байтов, ни ошибок прошлых обменов
    platform_uart_clear(rx);

    tx_uart = tx;
    rx_uart = rx;
    memcpy(tx_data, data, size);
    tx_size = size;
    tx_sent = 0;
    callback = on_done;
    state = UART_STATE_SEND;
    return true;
}

void uart_task_handle(void)
{
    switch (state)
    {
    case UART_STATE_IDLE:
        break;
    case UART_STATE_SEND:
        // дописать в очередь передачи столько, сколько в неё помещается
        while (tx_sent < tx_size && platform_uart_put(tx_uart, tx_data[tx_sent]))
        {
            tx_sent++;
        }

        // ушёл стоп-бит последнего символа
        if (tx_sent == tx_size && !platform_uart_busy(tx_uart))
        {
            quiet_start_us = systime_us();
            state = UART_STATE_QUIET;
        }
        break;
    case UART_STATE_QUIET:
        if (systime_us() - quiet_start_us >= QUIET_US)
        {
            uint8_t rx_data[UART_TASK_MAX];
            size_t size = platform_uart_read(rx_uart, rx_data, sizeof(rx_data));
            uint32_t errors = platform_uart_errors(rx_uart);

            // функцию вызываем последней: она сама может запустить следующий обмен
            state = UART_STATE_IDLE;
            callback(rx_data, size, errors);
        }
        break;
    }
}
```

Перед обменом задача очищает приёмник. Так в ответ не попадут байты и ошибки прошлого обмена. В `main.c` вызовите `uart_task_handle()` в суперцикле со своим секундомером `uart`. Файл `logic/uart-task/uart-task.c` добавьте в библиотеку `logic` в `CMakeLists.txt` рядом с `edge-task.c`.

Задача передаёт строку через `tx` и читает её через `rx`. В этом задании оба — UART0. В следующих заданиях один модуль передаёт, другой принимает, а задача та же.

### 4. Проверить петлю внутри модуля

Соберите проект и запишите прошивку. Перемычку пока не ставьте.

>[!success] Должно получиться так
> ```
> loop internal
> loop: internal
> echo ping
> rx: ping err: none
> echo 0123456789ABCDEFGHIJKLMNOPQRSTUV
> rx: 0123456789ABCDEFGHIJKLMNOPQRSTUV err: none
> ```

Строка ушла в модуль и вернулась, не выходя на выводы. Значит, модуль настроен верно. Если здесь строка не вернулась, искать нужно в настройке, а не в проводах.

### 5. Проверить петлю через выводы

Соедините GP0 (ножка 1) и GP1 (ножка 2) перемычкой по схеме выше.

>[!success] Должно получиться так
> ```
> loop pins
> loop: pins
> echo ping
> rx: ping err: none
> ```

Теперь строка вышла на вывод GP0, прошла по перемычке и вернулась через GP1.

>[!info] Без перемычки
>Снимите перемычку и повторите `echo ping` в обоих режимах. С `loop internal` строка вернётся, с `loop pins` не вернётся. Так петля `LBE` отделяет ошибку настройки от ошибки соединения. На неподключённом входе `RX` после сброса включена подтяжка вниз, и линия держит ноль. Модуль может отметить это признаком разрыва `BE` ([[т3.3.4 UART RP2040#Ошибки приёма|т3.3.4]]). Этот опыт в лог для сдачи не входит. Верните перемычку перед следующим шагом.
