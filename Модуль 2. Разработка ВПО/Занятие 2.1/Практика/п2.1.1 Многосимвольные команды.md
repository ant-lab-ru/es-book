## Ход работы

>[!info] Зачем прибору слова вместо букв
>В занятии 1.3 команда была одним символом: `e` включал светодиод, `d` выключал. Пока команд три, этого хватает; на десятой заканчиваются удобные буквы, и прибором становится невозможно пользоваться, не держа перед глазами таблицу. Слово решает обе беды сразу — оно читается без подсказки и не кончается. Плата за это одна: символы приходят по одному, и прошивка должна собрать их в строку прежде, чем что-то решать.

>[!warning] Теория этого задания — в занятии 1.3
>Приём строки опирается на [[т1.3.6 Стандартный ввод-вывод в прошивке#^intro\|т1.3.6]] и [[т1.3.7 Отладка через вывод#^intro\|т1.3.7]]. Разбор строк и командный протокол как отдельная тема ждут вас в занятии 2.3; здесь команды нужны как инструмент, которым вы будете спрашивать прибор о его памяти в остальных заданиях занятия.

### 2. Завести буфер строки

Символы из порта приходят по одному, а решение принимается по всей команде — значит, принятое нужно где-то копить. Добавьте в `main.c` буфер и его текущую длину:

``` c
#define LINE_SIZE 32

char line[LINE_SIZE];
uint line_length = 0;
```

Размер выбран с запасом: самая длинная команда занятия — `boot_info`, девять символов. Массив объявлен вне какой-либо функции, поэтому живёт всё время работы прибора, а не до выхода из неё.

>[!info] Куда этот массив попадёт
>`line` объявлен без начального значения — такие переменные не занимают в образе ни байта, а обнуляются при запуске. Почему так и где они лежат, разбирает [[т2.1.2 Состав образа ВПО. Секции#^intro\|т2.1.2]]; в задании [[п2.1.3 Системная память#^intro\|п2.1.3]] вы найдёте границы этой области своими глазами.

### 3. Собрать строку из символов

Приём одного символа у вас уже написан в `main()`. Вынесите его в отдельную функцию и достройте до приёма строки:

``` c
void read_line(void)
{
    int symbol = getchar_timeout_us(0);

    if (symbol == PICO_ERROR_TIMEOUT)
    {
        return;
    }

    if (symbol == '\r' || symbol == '\n')
    {
        putchar('\n');
        line[line_length] = '\0';

        if (line_length > 0)
        {
            LOG_DBG("got %s\n", line);
            handle_command(line);
        }

        line_length = 0;
        return;
    }

    if (line_length + 1 < LINE_SIZE)
    {
        line[line_length] = (char)symbol;
        line_length = line_length + 1;
        putchar(symbol);
    }
}
```

Здесь четыре решения, и каждое стоит проговорить.

*Ранний выход по таймауту* остался тем же, что в [[п1.3.4 Светодиод и USB#2. Разобрать команду в отдельной функции\|п1.3.4]]: символа нет в подавляющем большинстве проходов суперцикла.

*Конец команды — `\r` или `\n`.* Что именно пришлёт терминал, зависит от программы и операционной системы: PuTTY по Enter шлёт `\r`, многие другие — `\n`, а некоторые оба подряд. Принимая любой из них и отбрасывая пустую строку, прошивка работает одинаково везде.

*Нулевой байт в конце.* Массив символов становится строкой языка **C** только тогда, когда за последним символом стоит `'\0'`: по нему `strcmp()` и `printf("%s")` понимают, где строка кончилась. Место под него есть всегда — условие `line_length + 1 < LINE_SIZE` отводит последнюю ячейку именно ему.

*Возврат символа в терминал.* `putchar(symbol)` печатает то, что вы набрали. Прошивка обязана это делать сама: терминал показывает не ваши нажатия, а то, что ответил прибор. Без этой строки набор идёт вслепую.

>[!bug] Команда не выполняется, хотя набрана верно
>Если прибор молчит на Enter, а следующая команда срабатывает через раз — скорее всего, терминал шлёт `\r\n`, а обработан только один из двух символов: второй попадает в начало следующей строки. Проверка `line_length > 0` это лечит: пустая строка просто отбрасывается.

### 4. Сравнивать строки, а не символы

Разбор команды из занятия 1.3 сравнивал символы оператором `==`. Со строками так нельзя: имя массива — это адрес, и `line == "enable"` сравнит два адреса, а не то, что по ним лежит. Строки сравнивает функция `strcmp()` из `<string.h>`: она возвращает ноль, когда строки совпадают.

Перепишите `handle_command()` так, чтобы она принимала строку, и переведите на слова все команды прибора: `e` становится `enable`, `d` — `disable`, `i` — `info`, `v` — `version`.

>[!success] Должно получиться так
> ```c
> void handle_command(const char *command)
> {
>     if (strcmp(command, "enable") == 0)
>     {
>         // включаем светодиод и сообщаем новое состояние
>     }
>     else if (strcmp(command, "disable") == 0)
>     {
>         // выключаем светодиод и сообщаем новое состояние
>     }
>     else if (strcmp(command, "info") == 0)
>     {
>         // печатаем паспорт устройства
>     }
>     else if (strcmp(command, "version") == 0)
>     {
>         // печатаем строку журнала о версии прошивки
>     }
>     else
>     {
>         LOG_ERR("unknown command: %s\n", command);
>     }
> }
> ```

>[!warning] Дальше полного кода не будет
>Вы написали приём строки дословно — он новый. Всё остальное в этом задании вы уже делали: включение светодиода, сообщение о состоянии, вызов паспорта. Повторять их здесь незачем: скопированный целиком блок не оставляет работы, а вместе с ней и понимания.
