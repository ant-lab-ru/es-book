## Ход работы

### 1. Создать директорию для сборки

Перейдите в папку проекта `112-blink`, создайте в ней директорию `build` и перейдите в неё:

``` bash
mkdir build
cd build
```

>[!info] Зачем отдельная директория
>Сборку проектов принято выполнять в отдельной директории с названием `build`. Это позволяет изолировать в ней все процессы сборки — при сборке создаётся огромное количество промежуточных файлов, — а также легко очищать и пересобирать проект.
>
>Всё содержимое `build` — производное: оно порождается инструментами из ваших исходных файлов и воспроизводится заново в любой момент. Поэтому директорию не хранят в репозитории, а добавляют в `.gitignore` — этим мы займёмся в задании [[п1.1.4 Создание репозитория курса#^intro|п1.1.4 Создание репозитория курса]].

### 2. Сконфигурировать сборку

``` bash
cmake -G "Unix Makefiles" ..
```

>[!info] Что делает CMake
>CMake генерирует сценарий сборки, по которому Make на следующем шаге выполнит сборку проекта.

В выводе не должно быть ошибок, а в конце — сообщения об успешной генерации:

```
-- Configuring done
-- Generating done
-- Build files have been written to: …/112-blink/build
```

### 3. Собрать прошивку

``` bash
make
```

>[!info] Что делает Make
>Make запускает компилятор и компоновщик для всех файлов проекта, подставляя нужные флаги и следя за зависимостями. Здесь происходят препроцессинг, компиляция, компоновка двоичного файла и преобразование его в формат `uf2`. Make работает по сценарию, который сгенерировал ему CMake.

Признак успеха в конце вывода:

```
[100%] Linking CXX executable 112_blink.elf
[100%] Built target 112_blink
```

Если сборка завершилась ошибкой, прочитайте сообщение и исправьте причину — обычно это опечатка в исходном файле или в описании сборки.

>[!success] Должно получиться так
>В директории `build` появилось множество файлов, среди которых нужны два:
>
>```
>112-blink
>└── build
>    ├── 112_blink.bin
>    └── 112_blink.uf2
>```

### 4. Перевести плату в режим загрузчика

1. Отключите плату Raspberry Pi Pico от компьютера.
2. Нажмите и удерживайте кнопку `BOOTSEL`.
3. Подключите плату к компьютеру кабелем USB — microUSB, не отпуская кнопку.
4. Отпустите кнопку `BOOTSEL`.

Плата появится в системе как съёмный диск `RPI-RP2`.

>[!info] Почему не нужен программатор
>Запись прошивки в память микроконтроллера — низкоуровневая процедура, и почти всегда для неё нужен отдельный прибор, [[Программатор#^def|программатор]]. RP2040 устроен иначе: на заводе в его постоянную память записан [[Загрузчик#^def|загрузчик]], который нельзя удалить или изменить. Кнопка `BOOTSEL` в момент подачи питания заставляет его представить плату как USB-накопитель.

>[!bug] Плата не появилась как съёмный диск
>Повторите шаги с самого начала: возможно, кнопка была нажата не до конца или в кабеле плохой контакт.

### 5. Записать прошивку

Скопируйте файл `112_blink.uf2` из директории `build` на диск `RPI-RP2` — мышью или командой из терминала. Команды выполняются из директории `build`, в которой вы собирали прошивку:

В macOS:

``` bash
cp 112_blink.uf2 /Volumes/RPI-RP2/
```

В Linux:

``` bash
cp 112_blink.uf2 /media/$USER/RPI-RP2/
```

В Windows — вместо `E:` подставьте букву, под которой появился диск:

``` powershell
Copy-Item .\112_blink.uf2 -Destination E:\
```

Сразу после копирования диск пропадёт: плата перезагрузится и начнёт исполнять записанную прошивку. Светодиод замигает.

>[!info] Команда может закончиться ошибкой — это нормально
>Плата отключается от компьютера в тот момент, когда файл ещё дописывается, и система успевает пожаловаться: `Input/output error`, «диск извлечён неправильно» или похожее. Прошивка при этом записана целиком — загрузчик перезагружает плату сам, получив последний нужный ему блок. Верный признак успеха здесь один: мигающий светодиод.

>[!info] Чем отличаются `.bin` и `.uf2`
>`.bin` — двоичный файл прошивки, в точности то, что должно оказаться во флеш-памяти микроконтроллера. Его записывают программатором напрямую.
>`.uf2` — формат для упрощённой записи через USB, обёртка вокруг той же прошивки. Она позволяет просто скопировать файл на плату, у которой есть соответствующий загрузчик. Результат в обоих случаях одинаковый.

>Светодиод на плате мигает: включается на четверть секунды, гаснет на секунду.
