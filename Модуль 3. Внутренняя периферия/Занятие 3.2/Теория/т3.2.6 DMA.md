В прошлом разделе мы разделили работу между обработчиком прерывания и суперциклом. Срочное делается в обработчике, долгое откладывается в суперцикл. Для рекордера и этого мало. Отсчёты приходят 44 100 раз в секунду, и, если на каждый из них вызывать обработчик, ядро будет входить в него и выходить из него каждые 23 мкс. Хотелось бы, чтобы отсчёты попадали в память сами, а ядро узнавало о них, когда набралась целая порция. Кто может переносить данные без ядра и как он узнаёт, когда брать очередной отсчёт?

## Контроллер DMA RP2040

В разделе [[т3.1.1 Управление периферией#^intro|об управлении периферией]] мы назвали [[DMA#^def|DMA]] среди способов, которыми модуль отдаёт результат, а в разделе [[т3.1.4 Режимы работы АЦП#^intro|о режимах работы АЦП]] выяснили, что DMA подходит для быстрого и долгого потока прямо в память. Посмотрим теперь, как он устроен. Контроллер DMA — это отдельный модуль на шине, который умеет то же, что ядро делает командами чтения и записи, и больше ничего. Он читает слово по одному адресу и записывает его по другому, за каждый такт по одному чтению и одной записи.

У контроллера DMA RP2040 двенадцать независимых каналов ([[RP2040 Datasheet.pdf#page=92|RP2040 Datasheet, раздел «2.5. DMA»]]). Канал — это четыре регистра, в которых записано задание на перенос. `READ_ADDR` указывает, откуда читать, `WRITE_ADDR` — куда писать, `TRANS_COUNT` — сколько передач сделать, а `CTRL` задаёт остальное.

- *Размер передачи.* Сколько данных канал переносит за один раз, 8, 16 или 32 бита. Отсчёт АЦП занимает 12 бит, поэтому для него берут 16.
- *Изменение адресов.* После каждой передачи канал может увеличить адрес чтения, адрес записи или оба на размер передачи. Так он проходит по массиву, а адрес регистра модуля оставляет на месте.
- *Следующий канал.* Закончив все передачи, канал может запустить другой канал.

![[Регистры канала DMA.excalidraw|100%]]

По сути, канал со значением `0x001F8025` в регистре `CTRL` выполняет цикл, который на C выглядел бы вот так.

```c
for (uint32_t i = 0; i < count; i++)
{
    dst[i] = *src;
}
```

Здесь адрес чтения не меняется, а адрес записи растёт. Так и переносят данные из модуля в память. Регистр результата модуля всегда по одному адресу, а отсчёты ложатся в массив подряд. Для переноса из массива в модуль, например на отправку, растёт адрес чтения, а для копирования из массива в массив растут оба.

## Запрос данных от модуля

В таком виде у цикла есть изъян. Канал выполнит его так быстро, как позволяет шина, а АЦП выдаёт отсчёт раз в 22,68 мкс. Значит, канал должен ждать, пока модуль приготовит очередное значение. Для этого у модулей RP2040 есть сигнал запроса данных, DREQ (*data request*). Буфер АЦП выставляет запрос, когда в нём лежит отсчёт, а канал, настроенный на этот запрос, делает одну передачу и ждёт следующего ([[RP2040 Datasheet.pdf#page=96|раздел «2.5.3. Data Request (DREQ)»]]). Получается, что шаг задаёт делитель АЦП, а перенос выполняет DMA, и ядро ни в том, ни в другом не участвует.

Вот как прошивка захватывает блок из `N` отсчётов в массив `samples`.

```c
// буфер АЦП с запросом DMA на каждый отсчёт, 44,1 кГц
adc_fifo_setup(true, true, 1, false, false);
adc_set_clkdiv(48000000.0f / 44100 - 1);

int ch = dma_claim_unused_channel(true);
dma_channel_config cfg = dma_channel_get_default_config(ch);

// 16-битные передачи из одного адреса в растущий
channel_config_set_transfer_data_size(&cfg, DMA_SIZE_16);
channel_config_set_read_increment(&cfg, false);
channel_config_set_write_increment(&cfg, true);
channel_config_set_dreq(&cfg, DREQ_ADC);

// куда, откуда, сколько, true — запустить сразу
dma_channel_configure(ch, &cfg, samples, &adc_hw->fifo, N, true);
adc_run(true);
```

Функция `adc_fifo_setup()` включает буфер АЦП и запрос DMA, который выставляется, как только в буфере окажется хотя бы один отсчёт. Канал берёт отсчёты из регистра `FIFO` модуля АЦП и раскладывает по массиву. После `adc_run(true)` АЦП начинает снимать отсчёты, и через `N` шагов, то есть через `N / 44100` секунды, массив заполнен. Всё это время ядро свободно.

Как ядро узнает, что блок готов? Можно опрашивать канал функцией `dma_channel_is_busy()` на каждой итерации суперцикла, а можно попросить канал выставить по окончании запрос прерывания. У контроллера DMA два таких запроса, `DMA_IRQ_0` и `DMA_IRQ_1`, и каждый канал можно подключить к любому из них ([[RP2040 Datasheet.pdf#page=97|раздел «2.5.4. Interrupts»]]).

Теперь прибор умеет захватывать блок отсчётов без участия ядра. Но рекордеру нужен не блок, а поток, который идёт без разрывов, пока запись не остановят. Как его получить, разберём в следующем разделе.
