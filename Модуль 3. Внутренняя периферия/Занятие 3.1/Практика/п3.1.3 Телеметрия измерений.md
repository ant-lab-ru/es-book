**Результат** — прибор `311-adc` умеет отправлять телеметрию. По команде `tm_start` он сам, без запросов, с заданным периодом отправляет строки с временем, напряжением и температурой, а по команде `tm_stop` прекращает. Телеметрию ведёт новая задача `telemetry-task`, и она устроена по правилам шаблона.
^intro

## Задание

### Что должно получиться

- [ ] Задача `logic/telemetry-task` с состояниями `IDLE` и `RUN` снимает напряжение и температуру с периодом по `systime`
- [ ] Задача не печатает сама, запись она отдаёт функции, полученной при запуске
- [ ] `tm_start [<period_ms>]` запускает телеметрию, `tm_stop` останавливает
- [ ] Строки потока идут в формате `tm: <время, мкс> <напряжение, В> <температура, °C>`, шаг между метками времени равен периоду
- [ ] Лог `device-3-1-3.log` снят, коммит отправлен, проверка `3.1.3` зелёная

### Как проверить

1. **Поток идёт и останавливается.** В терминале `tm_start 500` запускает строки дважды в секунду, `tm_stop` их прекращает.
2. **Лог прогона лежит в проекте.** Скрипт задания записывает обмен в `device-3-1-3.log`.
3. **Автоматическая проверка курса принимает задание.** В коде она ищет задачу с состояниями `IDLE` и `RUN`, проверку периода через `systime_period_elapsed()` и тип функции для записей. Задача не должна печатать, а логика не должна подключать SDK. В логе она считает шаг между метками времени. При периоде 50 мс и 100 мс средний шаг должен совпасть с периодом с точностью 2%. После ответа `tm_stop` строк потока быть не должно, а неверные аргументы `tm_start` отклоняются.

## Ход работы

Что такое телеметрия и чем поток отличается от опроса, разобрано в [[т3.1.6 Телеметрия#^intro|т3.1.6]]. Почему отсчёты по команде задачи стоят на сетке времени с небольшим опозданием, разобрано в [[т3.1.4 Режимы работы АЦП#Период, заданный прошивкой|т3.1.4]].

### 1. Дополнить протокол прибора

Протокол прибора описан в [[ТЗ 2.3 Приложение А. Протокол|приложении А ТЗ 2.3]]. До сих пор прибор только отвечал на команды. Теперь у него появляется ещё один вид строки, строка телеметрии. Прибор отправляет её сам, без запроса.

```
tm: SP <время> SP <напряжение> SP <температура> CR LF
```

| Поле | Формат |
| --- | --- |
| `<время>` | время отсчёта по часам прибора, десятичное число микросекунд с момента сброса |
| `<напряжение>` | напряжение на GP26 в вольтах, три знака после точки |
| `<температура>` | температура кристалла в градусах Цельсия, один знак после точки |

Строка телеметрии начинается с `tm:`, и по этому началу программа на компьютере отличает её от ответов на команды. Команды телеметрии описаны так же, как в [[ТЗ 2.3 Приложение Б. Команды|приложении Б]]:

| | `tm_start` | `tm_stop` |
| --- | --- | --- |
| Синтаксис | `tm_start [<period_ms>]` | `tm_stop` |
| Описание | запускает телеметрию с периодом в миллисекундах, по умолчанию 100. Запущенную телеметрию перезапускает с новым периодом | останавливает телеметрию |
| Ответ | `telemetry: started, period <период> ms` | `telemetry: stopped` |
| Ошибки | `error: usage tm_start [<period_ms>]` — больше одного аргумента или ошибка в записи<br>`error: period_ms must be at least 10` — период меньше 10 мс | нет |

### 2. Написать задачу телеметрии

Задача живёт в `logic/telemetry-task`, как задачи светодиода и кнопки. Измерения она берёт у `platform`, время у `systime`. Печатать задача не может (правило П3 [[ТЗ 2.3 Шаблон проектирования#4. Правила|ТЗ 2.3]]). Каждую запись она отдаёт функции, которую получила при запуске, как задача кнопки сообщает о нажатии. Интерфейс задачи такой:

```c
// telemetry-task.h — задача телеметрии: с заданным периодом снимает напряжение
// и температуру и отдаёт запись функции, переданной при запуске.
// Как запись попадёт на компьютер, задача не знает.

#pragma once

#include <stdbool.h>
#include <stdint.h>

typedef enum {
    TELEMETRY_STATE_IDLE,
    TELEMETRY_STATE_RUN,
} telemetry_state_t;

// одна запись: время отсчёта по часам прибора и измеренные значения
typedef struct {
    uint64_t time_us;
    float voltage_v;
    float temp_c;
} telemetry_record_t;

// функция, которой задача отдаёт каждую запись
typedef void (*telemetry_task_callback_t)(const telemetry_record_t *record);

void telemetry_task_init(telemetry_task_callback_t on_record);

// вызывается на каждой итерации суперцикла, не ждёт
void telemetry_task_handle(void);

// false — период не принят
bool telemetry_task_start(uint32_t period_ms);
void telemetry_task_stop(void);

telemetry_state_t telemetry_task_get_state(void);
uint32_t telemetry_task_get_period_ms(void);
```

Запись отдаётся указателем на структуру. Так одна функция получает сразу все три значения, а когда в записи появится новое поле, тип функции менять не придётся.

>[!success] Должно получиться так
> ```c
> // telemetry_task_init(): запомнить функцию для записей, состояние IDLE
>
> // telemetry_task_start(): период меньше 10 мс не принять,
> // запомнить период, первую запись — на ближайшей итерации, состояние RUN
>
> // telemetry_task_stop(): состояние IDLE
>
> // telemetry_task_handle():
> // в состоянии RUN, если прошёл период:
> //     записать время systime_us(), напряжение и температуру у platform
> //     отдать запись функции, полученной при запуске
> ```

| Что нужно написать | Где это разбиралось |
| --- | --- |
| состояния на `enum` и обработчик со `switch` | [[п2.3.2 Задача светодиода#^intro\|п2.3.2]] |
| период через `systime_period_elapsed()` | [[п2.3.6 Библиотеки#^intro\|п2.3.6]] |
| функция, переданная задаче при запуске | [[п2.3.7 Железо и логика#^intro\|п2.3.7]] |
| переменные задачи со `static` | [[т2.3.5 Программный модуль на C#^intro\|т2.3.5]] |
| новый файл в библиотеке `logic` | [[п2.3.7 Железо и логика#^intro\|п2.3.7]] |

### 3. Печатать запись и добавить команды

Строку телеметрии печатает `api`, как ответы на команды. Объявите в `api.h` функцию печати записи:

```c
#include "telemetry-task/telemetry-task.h"

// печатает запись телеметрии строкой tm: <время, мкс> <напряжение, В> <температура, °C>
void api_print_telemetry(const telemetry_record_t *record);
```

Определите её в `api-callbacks.c` рядом с обработчиками команд. Время типа `uint64_t` печатается форматом `%llu`, как в ответе `uptime`.

>[!success] Должно получиться так
> ```c
> // период телеметрии по умолчанию
> #define TELEMETRY_DEFAULT_PERIOD_MS 100
>
> // api_print_telemetry(): строка tm: <время> <напряжение %.3f> <температура %.1f>
>
> // cmd_tm_start(): аргументов больше одного или аргумент не число — error: usage
> // период не принят задачей — error: period_ms must be at least 10
> // иначе ответ telemetry: started, period <период> ms
>
> // cmd_tm_stop(): остановить задачу, ответ telemetry: stopped
> ```

| Что нужно написать | Где это разбиралось |
| --- | --- |
| необязательный числовой аргумент | `pi_start [<terms>]`, [[п2.3.1 Протокол и API#^intro\|п2.3.1]] |
| проверку, которую делает сама задача | `led_period` и `led_task_set_period_ms()`, [[п2.3.2 Задача светодиода#^intro\|п2.3.2]] |

### 4. Связать задачу в main.c

Связи между модулями задаёт `main.c` (правило П6 [[ТЗ 2.3 Шаблон проектирования#4. Правила|ТЗ 2.3]]). При запуске он передаёт задаче телеметрии функцию печати из `api`, а в суперцикле вызывает её обработчик. Заведите для обработчика свой секундомер.

>[!success] Должно получиться так
> ```c
> // номер секундомера STOPWATCH_TELEMETRY, имя "telemetry"
>
> // записи телеметрии печатает api
> telemetry_task_init(api_print_telemetry);
>
> // в суперцикле, между секундомерами
> telemetry_task_handle();
> ```

### 5. Проверить в терминале

Соберите проект, запишите прошивку и запустите телеметрию с периодом по умолчанию:

>[!success] Должно получиться так
> ```
> tm_start
> telemetry: started, period 100 ms
> tm: 20933443 0.528 24.8
> tm: 21033450 0.519 24.8
> tm: 21133444 0.526 24.3
> tm: 21233449 0.527 24.8
> tm: 21333448 0.530 24.3
> tm_stop
> telemetry: stopped
> ```

Посмотрите на столбец времени. Метки идут через 100 000 мкс, отклоняясь на единицы микросекунд. Задача отсчитывает следующий момент от прошлого, поэтому опоздания не складываются. Посмотрите и на температуру. Она прыгает между 24,3 и 24,8 °C. Это один шаг квантования АЦП. Соседние коды отличаются на 0,8 мВ, а для датчика температуры это около половины градуса ([[т3.1.2 Сигналы#Цифровой сигнал|т3.1.2]]).

Пока вы набираете `tm_stop`, строки потока продолжают приходить и перемешиваются с набранными символами. Прибор всё равно примет команду, потому что эхо и поток идут в один канал, а кадр собирается по символам.
