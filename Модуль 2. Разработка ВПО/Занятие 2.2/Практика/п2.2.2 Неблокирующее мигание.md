**Результат** — светодиод мигает с периодом в секунду, и прибор при этом сразу отвечает на команды. Мигание отмеряют часы прибора, пауз в суперцикле нет. Новая команда `uptime` сообщает, сколько миллисекунд прошло с запуска прибора.
^intro

## Задание

### Что должно получиться

- [ ] Команда `uptime` печатает время с запуска прибора в миллисекундах
- [ ] Команд `enable` и `disable` в таблице больше нет, светодиодом управляет мигание
- [ ] Опрос кнопки и подавление дребезга убраны из суперцикла
- [ ] Светодиод переключается каждые 500 мс по показаниям `time_us_64()`, в `main.c` нет ни одного `sleep_ms()`
- [ ] Рядом с `main.c` лежит `device-2-2-2.log` с ответами платы

### Как проверить

1. **Светодиод мигает, прибор отвечает.** Светодиод загорается и гаснет раз в секунду. Наберите `uptime`. Ответ приходит сразу, и мигание не сбивается.
2. **Время растёт и начинается заново.** Наберите `uptime` ещё раз. Число выросло на столько, сколько прошло между вызовами. Отключите и снова подключите USB. После перезагрузки отсчёт начинается почти с нуля.
3. **Автоматическая проверка курса принимает задание.** Она читает `main.c`. В нём не должно быть `sleep_ms()`, опроса кнопки и команд `enable` и `disable`, мигание должно опираться на `time_us_64()`, а полупериод задан константой 500 мс. В модуле `clock` проверка ищет функцию `uptime()`. Затем собирает прошивку и читает лог. Показания `uptime` растут так же, как время между запросами в логе. Ответ на каждый запрос приходит быстрее чем за десятую долю секунды. Разряд светодиода в ответах `boot_info` меняется сам, без команд. Значит, светодиод мигает.

## Ход работы

Теория задания — [[т2.2.2 Источник времени#Монотонное время|т2.2.2, раздел «Монотонное время»]] и [[т2.2.4 Блокирующий и неблокирующий код#^intro|т2.2.4]].

### 1. Добавить команду uptime

Монотонное время прибора ведёт таймер. Он прибавляет единицу раз в микросекунду, начиная с момента сброса. Показание счёта возвращает функция `time_us_64()`. Добавьте в модуль `clock` функцию, которая печатает это показание в миллисекундах:

``` c
void uptime(void)
{
    printf("uptime: %llu ms\n", time_us_64() / 1000);
}
```

`time_us_64()` возвращает `uint64_t`. Такое число печатают через `%llu`. Деление на 1000 переводит микросекунды в миллисекунды.

Заведите команду `uptime`, как `clk_info` в прошлом задании. Соберите проект, запишите прошивку и наберите `uptime` два раза подряд.

>[!success] Должно получиться так
> ```
> uptime: 4939 ms
> uptime: 6562 ms
> ```
>
>Первое число показывает, сколько прошло с последнего запуска прибора. Второе больше первого на время между двумя вызовами.

### 2. Убрать то, что мешает миганию

С этого задания светодиодом управляет мигание. Команды `enable` и `disable` ему только мешают. Мигание переключит светодиод через полсекунды, и их действие пропадёт. Удалите из `main.c` обработчики `cmd_enable()` и `cmd_disable()` и их строки в массиве `commands`.

Кнопку тоже придётся убрать. Функция `get_button_debounce()` из [[п1.2.3 Программное избавление от дребезга#^intro|п1.2.3]] на каждой итерации вызывает `sleep_ms(DEBOUNCE_MS)`. Это пауза в 20 мс, и суперцикл на это время останавливается. Удалите из `main.c` функцию `get_button_debounce()`, константы `BUTTON_PIN` и `DEBOUNCE_MS`, настройку вывода кнопки и её опрос в суперцикле. Заголовок `"hardware/gpio.h"` в `main.c` после этого больше не нужен, его тоже можно убрать.

>[!info] Пауза в 20 мс тоже блокирует
>Подавление дребезга ждёт, пока контакт кнопки успокоится. Ждёт оно вызовом `sleep_ms()`, а это блокирующий код. Итерация с ним длится не меньше 20 мс. Без неё итерация будет длиться единицы микросекунд. Как это сказывается на ответе прибора, разбирает [[т2.2.4 Блокирующий и неблокирующий код#Пауза в суперцикле|т2.2.4, раздел «Пауза в суперцикле»]].

### 3. Мигать по часам

Пауза отмеряет полсекунды ожиданием. Часы отмеряют их проверкой. На каждой итерации прошивка сравнивает прошедшее время с полупериодом. Если полупериод прошёл, она переключает светодиод и запоминает новую метку. Если нет, суперцикл идёт дальше.

Добавьте в `main.c` константу полупериода, метку прошлого переключения и функцию `blink()`:

``` c
const uint BLINK_HALF_PERIOD_MS = 500;

uint64_t last_toggle_us = 0;

void blink(void)
{
    uint64_t now_us = time_us_64();

    if (now_us - last_toggle_us >= BLINK_HALF_PERIOD_MS * 1000)
    {
        last_toggle_us = now_us;
        led_toggle();
    }
}
```

Полупериод задан в миллисекундах, а часы идут в микросекундах. Поэтому константа умножается на 1000.

Условие записано разностью «сейчас минус прошлый раз». Сравнение с моментом «прошлый раз плюс полупериод» здесь тоже сработало бы. Но с 32-битными часами оно раз в 71,6 минуты ошибается. Почему так, разбирает [[т2.2.5 Профилирование#Разность двух показаний|т2.2.5, раздел «Разность двух показаний»]]. Привычку лучше заводить сразу.

Вызовите `blink()` в суперцикле рядом с `read_line()`.

>[!success] Должно получиться так
> ```c
> int main()
> {
>     // инициализируем стандартный ввод-вывод и светодиод
>
>     while (1)
>     {
>         blink();
>
>         read_line();
>     }
> }
> ```

### 4. Проверить мигание и ответ

Соберите проект, запишите прошивку и откройте терминал. Светодиод мигает раз в секунду. Наберите `uptime`. Ответ приходит сразу, а светодиод продолжает мигать в прежнем ритме.

>[!info] Как было бы с паузой
>Вспомните `blink` из [[п1.1.2 Первый проект#^intro|п1.1.2]]. Там светодиод переключался вызовом `sleep_ms()`, и итерация длилась целую секунду. Поставьте такое мигание в этот прибор, и ответа на `uptime` пришлось бы ждать шесть-семь секунд. Каждая итерация забирала бы из порта всего один символ, а в команде шесть букв и перевод строки. Такой же расчёт для команды `ping` разобран в [[т2.2.4 Блокирующий и неблокирующий код#Пауза в суперцикле|т2.2.4]].

>[!bug] Светодиод горит вполсилы или не мигает вовсе
>Если светодиод светится тускло и ровно, он переключается слишком часто. Скорее всего, полупериод сравнивается с разностью микросекунд без умножения на 1000. Тогда светодиод переключается каждые полмиллисекунды, и глаз видит среднюю яркость. Если светодиод не мигает вовсе, проверьте, что `blink()` вызывается в суперцикле.

Скопируйте [[check-2-2-2.py]] в папку проекта, а [[check-2-2-2.yml]] в `.github/workflows`. Добавьте в `README.md` строку со значком этой проверки.

Скрипт четыре раза подряд отправляет `uptime` и `boot_info` с промежутком в 0,4 с. По `uptime` проверка видит, что часы идут вровень со временем в логе. По разряду светодиода в ответах `boot_info` она видит, что светодиод мигает сам. Все эти команды отвечают сразу, поэтому быстрый ответ тоже виден в логе.
