## Задание

### Что должно получиться

- [ ] Ведомое запускает отдельный суперцикл на ядре 1.
- [ ] Ведущий отвечает на `help`, пока светодиод мигает.

### Как проверить

1. Светодиод мигает, пока ведущий отвечает на `help`.
2. Для самопроверки скрипт печатает ответ USB в терминал.
3. Автоматическая проверка собирает проект и проверяет запуск ядра 1, суперцикл ведомого и карту регистров.

## Ход работы

### 1. Определить интерфейс ведомого

Ведомый будет управлять штатным светодиодом Pico. Номера и режимы доступа к регистрам из [[ТЗ 4.1 Связь с внешним устройством#^intro|ТЗ на проект 411-i2c-spi]] войдут в `logic/slave/slave.h`. Обращаться к этим регистрам по шине начнём в следующем задании.

Запись других значений игнорируется. При чтении CMD или неизвестного регистра вернётся `0xFF`. Команды повторяют знакомое управление из [[п1.3.4 Светодиод и USB#^intro|п1.3.4]], а оформление карты опирается на [[п1.2.1 Мигание светодиодом через регистр#^intro|п1.2.1]].

>[!info] Регистры внутренней и внешней периферии
>Через регистры программа читает состояние и задаёт поведение устройства. Регистры внутренней периферии доступны процессору по адресам на параллельной внутренней шине. Для внешнего устройства процессор обращается к контроллеру интерфейса через то же адресное пространство. Контроллер передаёт запрос по последовательным линиям. Наше ведомое хранит регистры программно.
>
>![[Регистры внутри и снаружи микроконтроллера.excalidraw|100%]]

### 2. Создать файлы ведомого

Создайте папку `logic/slave`. Скопируйте каждый блок целиком в указанный новый файл. Заголовок задаёт карту регистров и адрес устройства. Реализация пока только мигает без остановки суперцикла, как в [[п2.2.2 Неблокирующее мигание#^intro|п2.2.2]].

>[!info] Готовый код `logic/slave/slave.h`
>```c
> #pragma once
>
> enum
> {
>     SLAVE_I2C_ADDRESS = 0x42,
>     SLAVE_REG_CMD = 0x00,  // Только запись: 'e' (0x65) включает светодиод, 'd' (0x64) - выключает
>     SLAVE_REG_STATE = 0x01 // Чтение и запись: 0 — выключен, 1 — включён
> };
>
> void slave_device_init(void);
> void slave_device_handle(void);
>```

>[!info] Готовый код `logic/slave/slave.c`
>```c
> #include "logic/slave/slave.h"
> #include "platform/platform.h"
>
> enum { BLINK_PERIOD_MS = 500 };
>
> static uint32_t last_change;
> static bool led_on;
>
> void slave_device_init(void)
> {
>     platform_slave_init();
>     last_change = platform_time_ms();
> }
>
> void slave_device_handle(void)
> {
>     if (platform_time_ms() - last_change >= BLINK_PERIOD_MS)
>     {
>         last_change += BLINK_PERIOD_MS;
>         led_on = !led_on;
>         platform_led_set(led_on);
>     }
> }
>```

### 3. Запустить второй суперцикл

В `CMakeLists.txt` добавьте `pico_multicore` к зависимостям `platform`, а `logic/slave/slave.c` к файлам цели `logic`. В `platform.c` подключите `pico/multicore.h` и добавьте функции ниже. Объявите их в `platform.h`.

>[!info] Запуск ядра и доступ к светодиоду в `platform.c`
>```c
> void platform_start_core1(void (*entry)(void))
> {
>     multicore_launch_core1(entry);
> }
>
> void platform_slave_init(void)
> {
>     gpio_init(PICO_DEFAULT_LED_PIN);
>     gpio_put(PICO_DEFAULT_LED_PIN, 0);
>     gpio_set_dir(PICO_DEFAULT_LED_PIN, GPIO_OUT);
>
> }
>
> void platform_led_set(bool on)
> {
>     gpio_put(PICO_DEFAULT_LED_PIN, on);
> }
>
> uint32_t platform_time_ms(void)
> {
>     return to_ms_since_boot(get_absolute_time());
> }
>```

В `main.c` подключите `slave/slave.h` и перед `main()` добавьте функцию `slave_core()`. Она станет точкой входа ядра 1.

>[!info] Точка входа ядра 1 в `main.c`
>```c
> static void slave_core(void)
> {
>     slave_device_init();
>
>     while (1)
>     {
>         slave_device_handle();
>     }
> }
>```

В `main()` после `stdio_text_protocol_init()` и перед суперциклом вызовите `platform_start_core1(slave_core)`. Суперцикл ядра 0 получает команду от протокола и передаёт её в `api_handle()`, как в п4.1.1.

>[!info] Второе ядро на Pico
>Pico SDK запускает функцию на ядре 1 одним вызовом. У других микроконтроллеров запуск может быть устроен иначе. Здесь ядро 0 владеет USB, SPI0 и I²C0. Ядро 1 владеет светодиодом, а дальше получит SPI1 и I²C1. Обмен между двумя устройствами пойдёт по проводам. Короткие примеры запуска, распределения ресурсов и обработки событий собраны в [[пр4.2 Второе ядро Cortex-M0+ в RP2040#^intro|приложении о втором ядре]].

### 4. Проверить параллельное исполнение

Соберите проект и загрузите бинарный файл на Pico. Убедитесь, что светодиод меняет состояние примерно дважды в секунду. Скопируйте [[check-4-1-3.py]] в папку проекта. Закройте USB-терминал и запустите скрипт.

```bash
python check-4-1-3.py
```

>[!success] Должно получиться так
>```text
> --> help
> <-- help
> <-- help             list of commands
> <-- i2c_write_reg    <address> <register> <value>
> <-- i2c_read_reg     <address> <register>
> <-- spi_write        <cs> <command> <value>
> <-- spi_read         <cs> <command> [pause_us]
>```

Пока ведущий отвечает на `help`, светодиод продолжает мигать. Для сдачи достаточно кода и сборки. Скрипт проверяет ответ USB, а мигание проверяем глазами.
