**Результат** — учебное ведомое доступно через SPI и I²C. BME280 продолжает отвечать по I²C.
^intro

## Задание

### Что должно получиться

- [ ] Оба интерфейса учебного ведомого меняют одно и то же состояние светодиода.
- [ ] Лог `device-4-1-5.log` подтверждает перекрёстный обмен и ответ BME280.

### Как проверить

1. Прочитайте по I²C состояние, записанное по SPI. Затем запишите по I²C и прочитайте по SPI.
2. Скрипт сохраняет ответы датчика и ведомого в `device-4-1-5.log`.
3. Автоматическая проверка проверяет обработку кадров SPI и последовательность ответов обеих шин в логе.

## Ход работы

### 1. Добавить перемычки SPI

![[SPI — соединения контроллеров Pico.excalidraw|100%]]

Снимите питание. Оставьте I²C и BME280 на месте. Добавьте четыре перемычки. У выхода выбора `0x01` свой провод GP5 → GP13. Выход `0x00` был предусмотрен для датчика во второй практике и сейчас свободен.

| Линия | Ведущий | Ведомый SPI1 |
| --- | --- | --- |
| SCK | GP2, контакт 4 | GP10, контакт 14 |
| MOSI | GP3, контакт 5 | GP12, контакт 16 |
| MISO | GP4, контакт 6 | GP11, контакт 15 |
| CS | GP5, контакт 7 | GP13, контакт 17 |

![[Стенд SPI и I²C — соединения Pico.jpeg|100%]]

На фото показан собранный стенд. Сверяйте провода по номерам контактов на схеме. При SPI две линии данных соединяют выход со входом, поэтому провода MOSI и MISO перекрещены относительно одного ряда.

>[!info] Подтяжка выбора ведомого
>Вход CS ведомого подтянут к единице внутренним резистором GPIO. Пока выход ведущего не настроен, ведомый остаётся невыбранным. На SCK, MOSI и MISO в этой схеме отдельных подтяжек нет.

### 2. Настроить SPI1

В `platform.c` добавьте константу `SPI_SLAVE_CS = 13`. Перед `platform_slave_init()` поместите функцию настройки и очистки очередей. Внутри `platform_slave_init()` после настройки светодиода вызовите эту функцию. Подтяните вход CS через `gpio_pull_up(SPI_SLAVE_CS)`. Назначьте SPI на GP10, GP11, GP12 и GP13 через `gpio_set_function()`.

>[!info] Настройка SPI1 в `platform.c`
>```c
> void platform_spi_slave_reset(void)
> {
>     spi_init(spi1, BUS_BAUD);
>     spi_set_format(spi1, 8, SPI_CPOL_1, SPI_CPHA_1, SPI_MSB_FIRST);
>     spi_set_slave(spi1, true);
>     // Первый принятый ведущим байт не содержит результата.
>     spi_get_hw(spi1)->dr = 0x00;
> }
>```

Добавьте функции доступа к очередям. Объявите эти три функции и `platform_spi_slave_reset()` в `platform.h`.

>[!info] Чтение и запись очередей в `platform.c`
>```c
> bool platform_spi_slave_selected(void)
> {
>     return !gpio_get(SPI_SLAVE_CS);
> }
>
> bool platform_spi_slave_receive(uint8_t *byte)
> {
>     if (!spi_is_readable(spi1))
>     {
>         return false;
>     }
>
>     *byte = (uint8_t)spi_get_hw(spi1)->dr;
>     return true;
> }
>
> void platform_spi_slave_reply(uint8_t byte)
> {
>     spi_get_hw(spi1)->dr = byte;
> }
>```

### 3. Добавить обработку кадра

В `logic/slave/slave.c` сохраните `led_state`, `read_register()` и `write_register()` из предыдущей практики. Добавьте три фазы кадра перед `read_register()`.

>[!info] Состояние кадра в `slave.c`
>```c
> static enum
> {
>     SPI_COMMAND,
>     SPI_DATA,
>     SPI_DONE
> } spi_phase;
>
> static uint8_t spi_register;
> static bool spi_reading;
>```

Добавьте `handle_spi_byte()` и замените `slave_device_handle()` блоком ниже. В фазе команды старший бит задаёт чтение, младшие семь выбирают регистр. При чтении ведущий тактирует подготовленный ответ. При записи ведомый применяет второй байт. Когда CS снова высокий, ведомый сбрасывает очереди и ждёт новый кадр.

>[!info] Обработка кадра в `slave.c`
>```c
> static void handle_spi_byte(uint8_t byte)
> {
>     switch (spi_phase)
>     {
>     case SPI_COMMAND:
>         spi_register = byte & 0x7F;
>         spi_reading = (byte & 0x80) != 0;
>         if (spi_reading)
>         {
>             platform_spi_slave_reply(read_register(spi_register));
>         }
>         else
>         {
>             platform_spi_slave_reply(0x00);
>         }
>         spi_phase = SPI_DATA;
>         break;
>     case SPI_DATA:
>         if (!spi_reading)
>         {
>             write_register(spi_register, byte);
>         }
>         spi_phase = SPI_DONE;
>         break;
>     case SPI_DONE:
>         break;
>     }
> }
>
> void slave_device_handle(void)
> {
>     uint8_t byte;
>     while (platform_spi_slave_receive(&byte))
>     {
>         handle_spi_byte(byte);
>     }
>
>     if (spi_phase != SPI_COMMAND && !platform_spi_slave_selected())
>     {
>         // Новый кадр начинается с пустых очередей, даже после обрыва.
>         platform_spi_slave_reset();
>
>         spi_phase = SPI_COMMAND;
>     }
>
>     platform_led_set(atomic_load_explicit(&led_state, memory_order_relaxed) != 0);
> }
>```

Ведомый опрашивает очередь SPI1 в суперцикле ядра 1. Для чтения ведущий оставляет между байтами 100 мкс. Аргумент `0x64` задаёт эту паузу в микросекундах. Так ведомый успевает поместить ответ в очередь при низком CS.

### 4. Проверить обмен и записать лог

Соберите проект и загрузите бинарный файл на Pico. Скопируйте [[check-4-1-5.py]] в папку проекта. Закройте USB-терминал и запустите скрипт. Он читает ID датчика и проверяет, что запись по одной шине видна при чтении по другой. Для BME280 на `0x77` добавьте `--address 0x77`.

```bash
python check-4-1-5.py
```

Ниже приведён фрагмент вывода.

>[!info] Две Pico
>При наличии второй платы можно загрузить тот же UF2 в обе. Подключите USB первой Pico к компьютеру. Вторую можно запитать по USB от пауэрбанка. Соедините GND плат. Концы перемычек SPI0 и I²C0 оставьте на первой Pico, а концы SPI1 и I²C1 перенесите на соответствующие выводы второй. Оставьте BME280 на линии I²C первой платы. Скрипт запускается через порт первой Pico. Если видны оба USB-порта, задайте ведущий через `--port`.
