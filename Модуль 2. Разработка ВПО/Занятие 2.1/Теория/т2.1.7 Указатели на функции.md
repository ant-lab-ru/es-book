В прошлом разделе мы прочитали по адресу функции её первую команду и увидели, что код — такие же данные, как всё остальное. Но код читают редко, а вызывают постоянно, и вопрос, которым тот раздел закончился, остался открытым: что нужно, чтобы вызвать функцию по адресу? Ответ на него замкнёт занятие. В разделе [[т2.1.4 Цепочка загрузки RP2040#^intro|Цепочка загрузки RP2040]] мы разобрали таблицу векторов как массив адресов, который ядру дан свыше, и пообещали объяснить, как значением элемента массива может быть функция.
^intro

Вся статья держится на одной мысли, и её стоит назвать сразу. У функции есть место в памяти, а значит, её адрес — такое же значение, как число или адрес переменной. С ним можно делать всё то же самое: сохранить в переменную, передать в другую функцию, сложить в массив. Разница только в типе, и разобраться с этим типом — главная работа раздела.

## Адрес функции — обычное значение

Начнём с того, что вообще означает имя функции, написанное без скобок. Возьмём самую короткую функцию, какую можно придумать:

```c
int add(int a, int b)
{
    return a + b;
}
```

Скобки в записи `add(2, 2)` — оператор вызова: они означают «передать управление по этому адресу с такими аргументами и дождаться результата». Само же имя `add`, если за ним не следует вызов, никакого действия не обозначает. Это адрес первой команды функции, обычное 32-разрядное число, которое компоновщик вписал в образ при сборке. Его можно напечатать, что вы и сделаете в задании [[п2.1.4 Память программы#^intro|п2.1.4]], а можно положить в переменную и пользоваться им дальше.

Одну особенность этого числа мы уже разобрали в разделе [[т2.1.6 Указатели как доступ к памяти#^intro|Указатели как доступ к памяти]]: в младшем разряде адреса функции стоит единица, которой ядро помечает адрес как адрес кода. Для вызова она нужна, а для чтения байтов её сбрасывают. Здесь нас интересует только вызов, поэтому дальше адрес берётся как есть, и поправка не понадобится ни разу.

## Тип указателя на функцию

Раз адрес функции — значение, его можно положить в переменную. Но у переменной в **C** есть тип, и вот здесь указатель на функцию расходится с указателем на данные. Указателю на `uint32_t` достаточно знать размер: по адресу лежат четыре байта, прочитать их можно всегда одинаково. С функцией так не выйдет. Чтобы её вызвать, нужно знать, сколько ей передать аргументов, какого они типа и что она вернёт обратно, — иначе вызов просто нельзя составить. Этот набор сведений называют **сигнатурой функции**, и именно он задаёт тип указателя.

![[Сигнатура функции#^def]]

У `add()` сигнатура читается прямо из объявления: два аргумента типа `int`, результат типа `int`. Тип указателя на такую функцию записывается так:

```c
typedef int (*add_ptr_t)(int, int);
```

Запись нечитаема с первого взгляда, поэтому разберём её по частям. Читать нужно изнутри: в скобках `(*add_ptr_t)` стоит имя со звёздочкой, то есть указатель; справа `(int, int)` — на функцию с двумя аргументами типа `int`; слева `int` — возвращающую `int`. Скобки вокруг `*add_ptr_t` обязательны, без них `int *add_ptr_t(int, int)` означало бы функцию, возвращающую указатель на `int`, — совсем другую вещь. Слово `typedef` превращает всё это в имя типа, и дальше `add_ptr_t` ведёт себя как любой другой тип.

![[Указатель на функцию#^def]]

С готовым именем типа остальное просто:

```c
// адрес функции add() в переменной
add_ptr_t add_func = add;

// вызов по адресу из переменной
int result = add_func(2, 2);
```

Присваивание `add_func = add` не требует ни оператора `&`, ни приведения: имя функции уже адрес. Вызов `add_func(2, 2)` делает ровно то же, что `add(2, 2)`, с одной разницей: адрес перехода берётся из переменной, а не вписан [[Компоновщик#^def|компоновщиком]] в команду. Значит, вызов можно направить туда, куда на этапе сборки никто не смотрел, и решать это уже во время работы прибора.

Тип здесь работает как защита. Попытка присвоить `add_func` функцию с другой сигнатурой, скажем `void on_timeout(void)`, вызовет предупреждение компилятора, и вы узнаете об ошибке до прошивки платы. Защита пропадает, как только вместо имени функции подставлено число: приведение `(add_ptr_t)0x10000281` компилируется без замечаний, потому что проверить, что лежит по этому адресу, компилятор не может. Там может оказаться другая функция, середина функции или вообще константа, и чем кончится такой вызов, предсказать нельзя.

>[!NOTE] Попробуйте
>Обычный указатель на функцию объявляется и без `typedef`, только читать такую запись тяжело: `int (*add_func)(int, int) = add;`. Попробуйте объявить в этой форме аргумент функции, которая принимает обработчик, и сравните с вариантом через `typedef`. Именно поэтому в реальном коде, и в Pico SDK в том числе, указатели на функции почти всегда идут через `typedef`.

## Обратный вызов

Раз адрес функции — обычное значение, его можно передать другой функции как аргумент. Так функция получает не данные, а действие: не «с чем работать», а «что делать». Пусть нужно выполнить что-то через заданное время, а что именно — решает тот, кто вызывает:

```c
typedef void (*callback_t)(void);

void run_after_delay(uint32_t ms, callback_t callback)
{
    sleep_ms(ms);

    // нулевой указатель — действие не задано
    if (callback != NULL)
    {
        callback();
    }
}

void on_timeout(void)
{
    gpio_put(LED_PIN, 1);
}

int main()
{
    // через секунду включить светодиод
    run_after_delay(1000, on_timeout);
}
```

Функция `run_after_delay()` ничего не знает про светодиод. Ей известна только сигнатура: передадут функцию без аргументов и без результата, и вызвать её надо по истечении задержки. Что при этом произойдёт, решает вызывающая сторона. Приём называется обратным вызовом, и слово «обратный» здесь точное: обычно ваш код вызывает библиотеку, а тут библиотека вызывает ваш.

![[Обратный вызов#^def]]

Проверка `callback != NULL` перед вызовом — не формальность. Указатель, которому ничего не присвоили, часто равен нулю, а вызов по нему означает переход на нулевой адрес, где никакого вашего обработчика нет. Такой переход ядро выполнить не может и останавливает программу: прибор перестаёт отвечать, и терминал молчит. Стоит проверка одного сравнения, а избавляет от прошивки, которая замирает при первом же вызове без обработчика.

Вы уже пользовались обратными вызовами, только на другом языке. На Raspberry Pi в **Python** реакция на нажатие кнопки записывалась примерно так: `GPIO.add_event_detect(pin, GPIO.RISING, callback=on_press)`. Функция `on_press` передавалась по имени, а библиотека вызывала её, когда на выводе появлялся фронт. В **C** механизм тот же, только передаётся адрес, а библиотека обязана заранее объявить сигнатуру, которую ждёт. На этом приёме построен весь Pico SDK, и в занятии 2.2 вы будете читать такие объявления постоянно:

```c
// hardware/irq.h: обработчик прерывания
typedef void (*irq_handler_t)(void);
void irq_set_exclusive_handler(uint num, irq_handler_t handler);

// pico/time.h: действие по таймеру
typedef int64_t (*alarm_callback_t)(alarm_id_t id, void *user_data);
```

Тип `irq_handler_t` объявлен буквально так же, как наш `callback_t`. А `add_alarm_in_ms()`, которая принимает `alarm_callback_t`, — это `run_after_delay()` без ожидания: управление возвращается сразу, а обработчик вызывается позже и уже не вашей программой. Как такое возможно и кто в этот момент вызывает ваш код, разберём в занятии 2.2.

## Массив указателей на функции

Указатель на функцию — переменная, а из переменных одного типа составляют массив. Получается набор действий, выбираемых по номеру. Пусть прибор бывает в трёх состояниях, и в каждом надо делать своё:

```c
typedef void (*handler_t)(void);

// действие для каждого состояния, по номеру
handler_t handlers[] = {handle_idle, handle_run, handle_error};

void dispatch(uint8_t state)
{
    // за границей массива лежит не адрес функции
    if (state < sizeof(handlers) / sizeof(handlers[0]))
    {
        handlers[state]();
    }
}
```

Ничего нового в этом коде нет: массив как массив, только вместо чисел в нём адреса функций. Адреса известны компоновщику при сборке, поэтому он записал их в образ сразу, и по правилам раздела [[т2.1.2 Состав образа ВПО. Секции#^intro|Состав образа ВПО. Секции]] массив попал в `.data`. Вот как он лежит в ОЗУ сборки `blink` с добавленными функциями из примеров, Pico SDK 2.3.0, тип сборки Release; в вашей сборке адреса будут другими:

```text
адрес       значение    что это
0x20000fcc  0x10000291  handle_idle
0x20000fd0  0x100002a1  handle_run
0x20000fd4  0x100002b1  handle_error
```

Три слова подряд, в каждом адрес функции с единицей в младшем разряде. Сравните с врезкой таблицы векторов из раздела Т2.1.4: форма та же. Проверка границы массива перед вызовом обязательна по той же причине, что и проверка на `NULL`, — за концом массива лежит соседняя переменная, и её значение будет принято за адрес.

Такой массив меняет форму программы. Без него выбор действия по состоянию пишется цепочкой `if`/`else` или `switch`, и с каждым новым состоянием цепочка растёт. С массивом выбор — одна строка `handlers[state]()`, а добавить состояние значит дописать элемент. Этим вы воспользуетесь сразу: в задании [[п2.1.2 Таблица команд#^intro|п2.1.2]] цепочка сравнения строк из [[п2.1.1 Многосимвольные команды#^intro|п2.1.1]], которую вы сейчас пишете, превратится в таблицу пар «имя команды — обработчик», и добавить прибору команду будет значить дописать элемент массива. В занятии 2.3 та же таблица переедет в отдельный модуль и станет описанием API прибора, а тем же приёмом будет задано и поведение прибора по состояниям.

Здесь же закрывается обещание из раздела Т2.1.4. Таблица векторов — ровно такой массив: в первом слове начальное значение указателя стека, дальше адреса функций-обработчиков, и лежат они по фиксированным смещениям, чтобы искать их можно было по номеру. Отличие одно, и оно не в устройстве, а в том, кто вызывает: элементы `handlers[]` вызывает ваша программа, а элементы таблицы векторов — само ядро, когда периферия подаёт сигнал прерывания. Назначить обработчик — значит присвоить значение элементу этого массива, и функция SDK `irq_set_exclusive_handler()`, которой вы воспользуетесь в занятии 2.2, сводится именно к присваиванию. Никакой магии в стартап-коде не осталось: там массив, который вы теперь умеете и объявить, и заполнить, и вызвать.

## Итог

Имя функции без скобок — адрес её первой команды, то есть обычное значение. Его можно сохранить в переменную, передать в функцию и положить в массив, а отличается такая переменная от указателя на данные только типом: чтобы вызвать код по адресу, мало знать размер, нужна сигнатура — типы аргументов и тип результата. Отсюда запись через `typedef`, которая этот тип и задаёт. Функция, переданная в другую функцию адресом, — обратный вызов: библиотека получает от вас действие, не зная, в чём оно состоит, и так устроены обработчики прерываний и таймеров в Pico SDK. Массив указателей на функции выбирает действие по номеру и заменяет растущую цепочку условий, а таблица векторов — такой же массив, элементы которого вызывает ядро. Проверки на `NULL` и на границу массива обязательны обе: переход по случайному значению уводит исполнение неизвестно куда, и прибор перестаёт отвечать без единого сообщения.

На этом занятие закончено. Мы прошли образ от секций до стартап-кода, увидели, что появляется в ОЗУ во время работы, и получили инструмент, которым всё это достижимо из программы: адрес переменной, регистра и функции стал значением, с которым можно работать. Как только память и указатели становятся инструментом, в микроконтроллере почти не остаётся области, к которой нельзя обратиться осознанно. В следующем занятии инструмент понадобится сразу: прибор начнёт отвечать на события, а обработчик события — это функция, адрес которой вы передадите ядру.
