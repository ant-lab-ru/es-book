Приложение к [[ТЗ 2.3 Прибор|части 1 технического задания, «Прибор»]]. Описывает, как прибор обменивается сообщениями с компьютером: из чего состоит кадр команды и кадр ответа и как прибор поступает с кадром, который нарушает формат.
^intro

## 1. Канал

| Параметр | Значение |
| --- | --- |
| Физический канал | USB, виртуальный COM-порт |
| Доступ из прошивки | стандартный ввод-вывод Pico SDK |
| Кодировка | ASCII, допустимые символы кадра — коды от `0x20` до `0x7e` |
| Порядок обмена | запрос — ответ: компьютер отправляет кадр команды, прибор отвечает кадром ответа |

Символы с кодами меньше `0x20`, кроме перечисленных в этом приложении, в кадре не допускаются; что прибор с ними делает, протокол не определяет.

## 2. Обозначения

| Запись | Значение |
| --- | --- |
| `текст` | символы передаются буквально |
| `<поле>` | поле кадра, описанное в таблице полей |
| `[ ... ]` | необязательная часть |
| `{ ... }` | часть повторяется ноль или более раз |
| `a \| b` | одно из значений |
| `SP` | пробел, `0x20` |
| `CR`, `LF` | символы `0x0d` (`\r`) и `0x0a` (`\n`) |

## 3. Кадр команды

Направление — от компьютера к прибору.

```
{SP} <имя> { SP {SP} <аргумент> } {SP} <конец>
```

| Поле | Формат | Ограничения |
| --- | --- | --- |
| `<имя>` | один или больше символов, кроме `SP` | имя команды из приложения Б |
| `<аргумент>` | один или больше символов, кроме `SP` | не больше 4 аргументов |
| `<конец>` | `CR` \| `LF` | пара `CR LF` допустима: второй символ даёт пустой кадр, который не обрабатывается |
| весь кадр без `<конец>` | — | не больше 63 символов |

Слова кадра разделены одним или несколькими пробелами; пробелы в начале и в конце кадра допустимы. Кадр, в котором нет ни одного символа, кроме `SP`, командой не считается: прибор его не обрабатывает и не отвечает.

Примеры кадров:

```
led_enable\r
  led_period   500  \r
pi_start 100000\n
```

## 4. Эхо и правка набираемого кадра

Кадр набирает человек в терминале, поэтому прибор показывает, что принял, и позволяет исправить опечатку до конца кадра.

| Принят символ | Что прибор делает с кадром | Что прибор отправляет |
| --- | --- | --- |
| от `0x20` до `0x7e`, кадр короче 63 символов | добавляет символ в конец кадра | тот же символ |
| от `0x20` до `0x7e`, в кадре уже 63 символа | не сохраняет символ и помечает кадр как переполненный | ничего |
| `0x08` или `0x7f` (Backspace), кадр не пуст | удаляет последний символ и снимает пометку о переполнении | `0x08 0x20 0x08` — стирает символ на экране |
| `0x08` или `0x7f`, кадр пуст | ничего | ничего |
| `<конец>`, кадр не пуст | завершает приём кадра | `CR LF`, затем кадр ответа |

## 5. Кадр ответа

Направление — от прибора к компьютеру.

```
<строка> CR LF { <строка> CR LF }
```

| Поле | Формат |
| --- | --- |
| `<строка>` | символы от `0x20` до `0x7e`; формат строк каждой команды — в приложении Б |

Ответ об ошибке состоит из одной строки и начинается с `error: `:

```
error: <описание> CR LF
```

Конец кадра ответа отдельным символом не отмечается: программа на компьютере, которая читает ответ, ждёт следующую строку с ограничением по времени.

## 6. Ошибки кадра

| Ситуация | Ответ | Выполняется ли команда |
| --- | --- | --- |
| кадр длиннее 63 символов или аргументов больше 4 | `error: command longer than 63 characters or 4 arguments` | нет |
| имени нет среди команд прибора | `error: unknown command '<имя>', try help` | нет |
| аргументы не соответствуют описанию команды | ошибка, указанная в описании команды в приложении Б | нет |

## 7. Сообщения журнала

Журнал прошивки выводится в тот же канал. Строка журнала не является ответом на команду и имеет формат:

```
<уровень> SP <функция>:<строка> SP <текст> CR LF
```

| Поле | Формат |
| --- | --- |
| `<уровень>` | `err` \| `inf` \| `dbg` |
| `<функция>` | имя функции на **C**, из которой выведено сообщение |
| `<строка>` | номер строки исходного файла, десятичное число |
| `<текст>` | текст сообщения |

При запуске прибор выводит строку журнала уровня `inf` с именем и версией прошивки.
