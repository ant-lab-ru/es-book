В прошлом разделе мы разобрали, как прошивка работает с АЦП. Она даёт команду снять отсчёт или поручает модулю снимать их самому, а результат читает из регистра или из буфера. Но каждое из этих действий в конце концов сводится к записи и чтению по адресам. Что именно и куда записывает прошивка, чтобы получить одно измерение?
^intro

## Карта регистров АЦП

Мы уже знаем, что у каждого модуля есть свой участок адресов и свои регистры в нём. Полный их перечень для модуля и есть его карта регистров.

![[Карта регистров#^def]]

Карта регистров АЦП стоит в конце его раздела в документации ([[RP2040 Datasheet.pdf#page=565|RP2040 Datasheet, раздел «4.9.6. List of Registers»]]). Базовый адрес модуля равен `0x4004c000`, а регистров девять. Смещения между ними идут с шагом 4 байта, потому что каждый регистр занимает одно 32-разрядное слово.

| Смещение      | Регистр                        | Назначение                       |
| ------------- | ------------------------------ | -------------------------------- |
| `0x00`        | `CS`                           | команды и состояние модуля       |
| `0x04`        | `RESULT`                       | результат последнего отсчёта     |
| `0x08`        | `FCS`                          | настройка и состояние буфера     |
| `0x0c`        | `FIFO`                         | очередной отсчёт из буфера       |
| `0x10`        | `DIV`                          | делитель для непрерывного режима |
| `0x14`–`0x20` | `INTR`, `INTE`, `INTF`, `INTS` | прерывания                       |

Каждому способу работы из прошлого раздела соответствует свой регистр. Отсчёт по команде запускают и проверяют через `CS`, а результат читают из `RESULT`. Непрерывному режиму нужен ещё `DIV`, буферу нужны `FCS` и `FIFO`, прерываниям последние четыре регистра. Для одного измерения хватит первых двух, и с них начнём.

## Битовые поля

Регистр `CS` хранит сразу несколько настроек. В нём есть бит, который включает АЦП, номер канала, команда начать отсчёт, признак готовности. Отводить под каждую настройку целое слово было бы расточительно, поэтому регистр делят на поля.

![[Битовое поле#^def]]

Ширину поля определяет число значений, которые оно должно хранить. Чтобы включить или выключить АЦП, хватает одного бита. Номер канала выбирается из пяти, и для него нужны три бита, потому что двух хватает только на четыре значения. Для перебора каналов по кругу нужно отметить каждый канал отдельно, и поле занимает пять бит, по одному на канал. Так же мы управляли выводом светодиода в разделе [[т1.2.9 GPIO#^intro|GPIO]], где выводу 25 соответствовал бит 25 в регистре.

![[Регистр CS АЦП.excalidraw|100%]]

Для каждого поля в документации указаны его биты, назначение, значение после сброса и тип доступа. Биты, отмеченные словом *Reserved*, не используются. В них записывают нули, а читать оттуда нечего.

| Биты | Поле | Тип | Назначение |
| --- | --- | --- | --- |
| 0 | `EN` | RW | включить АЦП |
| 1 | `TS_EN` | RW | включить датчик температуры |
| 2 | `START_ONCE` | SC | снять один отсчёт |
| 3 | `START_MANY` | RW | снимать отсчёты непрерывно |
| 8 | `READY` | RO | АЦП готов, прошлый отсчёт закончен |
| 9 | `ERR` | RO | ошибка в последнем отсчёте |
| 10 | `ERR_STICKY` | WC | ошибка была хотя бы в одном отсчёте |
| 14:12 | `AINSEL` | RW | номер канала |
| 20:16 | `RROBIN` | RW | каналы для перебора по кругу |

## Типы доступа

Поля различаются не только шириной. Одни хранят то, что в них записали, другие показывают состояние модуля и сами меняются, третьи выполняют команду. Что делает с полем запись и что показывает чтение, говорит его тип.

![[Тип доступа#^def]]

В регистре `CS` встречаются четыре типа. Поле типа RW хранит записанное значение и при чтении возвращает его, так устроены `EN` и `AINSEL`. Поле типа RO только показывает состояние модуля, и запись его не меняет. Записать единицу в `READY` нельзя, готовность выставляет сам АЦП, когда отсчёт закончен. Поле типа SC выполняет команду и само возвращается в ноль. Записанная в `START_ONCE` единица запускает отсчёт, и сразу после этого поле снова читается нулём. Поле типа WC сбрасывается записью единицы. `ERR_STICKY` запоминает, что ошибка была хоть раз, и остаётся в единице, пока прошивка не запишет в него единицу. Ошибка, к слову, бывает, когда напряжение на входе слишком близко к порогу компаратора и тот не успевает решить, больше оно или меньше.

Вспомним, что в разделе [[т3.1.1 Управление периферией#^intro|об управлении периферией]] бит регистра оказался проводником внутри схемы модуля. Теперь видно, что такие «проводники» бывают направлены в две стороны. Одни задаёт программа, а схема модуля их читает, это поля RW. Другие задаёт схема, а программа их только читает, это поля RO. Значения в полях RO меняются без участия программы, и компилятору нельзя считать, что прочитанное однажды останется прежним. Поэтому указатель на регистр объявляют с `volatile`, как мы делали в разделе [[т2.1.6 Указатели как доступ к памяти#^intro|об указателях]].

## Изменение поля без порчи соседей

Регистр записывают только целиком. Если записать в `CS` номер канала, все остальные поля получат нули, и АЦП выключится. Поэтому одно поле меняют приёмом «чтение, изменение, запись». Регистр читают, в прочитанном значении очищают маской биты поля и вписывают новое значение, а потом записывают слово обратно. Маска поля `AINSEL` в битах 12–14 равна `0x7u << 12`. Как строят маски и что делают операторы в коде ниже, разобрано в навыке [[Работа с битовыми полями#^def|«Работа с битовыми полями»]].

```c
volatile uint32_t *cs = (volatile uint32_t *)(0x4004c000 + 0x00);

// Прочитать регистр целиком
uint32_t value = *cs;

// Очистить биты поля AINSEL и вписать в них канал 4
value &= ~(0x7u << 12);
value |= 4u << 12;

// Записать регистр обратно, остальные поля не изменились
*cs = value;
```

RP2040 позволяет сделать это короче. В разделе [[т1.2.9 GPIO#^intro|GPIO]] у регистров выводов были отдельные адреса для установки, сброса и переключения битов. У регистров периферии такие адреса тоже есть, и устроены они одинаково для всех модулей. Каждый регистр доступен ещё по трём адресам, со сдвигом на `0x1000`, `0x2000` и `0x3000` от обычного ([[RP2040 Datasheet.pdf#page=18|RP2040 Datasheet, раздел «2.1.2. Atomic Register Access»]]). Запись по первому переключает указанные биты, по второму устанавливает их в единицу, по третьему сбрасывает в ноль, а остальные биты не меняются. Читать регистр перед такой записью не нужно.

![[Регистры на адресах.excalidraw|100%]]

У модулей UART, SPI и I2C этих адресов в самом модуле нет. Это блоки других компаний, о которых шла речь в разделе об управлении периферией, и их проектировали без них. Raspberry Pi добавила дополнительные адреса прослойкой на шине перед модулем, и запись по ним у этих модулей идёт на два такта дольше.

## Одно измерение по шагам

Теперь соберём одно измерение из полей регистров `CS` и `RESULT`. Оно состоит из пяти шагов.

1. Записать единицу в `EN` и дождаться единицы в `READY`, АЦП включился.
2. Записать в `AINSEL` номер канала.
3. Записать единицу в `START_ONCE`, отсчёт начался, и `READY` стал нулём.
4. Дождаться единицы в `READY`, отсчёт закончен.
5. Прочитать 12-разрядный код из `RESULT`.

Функции Pico SDK выполняют ровно эти шаги. Чтобы обращаться к регистрам по именам, SDK описывает модуль структурой, поля которой стоят в том же порядке, что регистры в карте, и накладывает её на базовый адрес.

```c
typedef struct {
    io_rw_32 cs;
    io_ro_32 result;
    io_rw_32 fcs;
    io_ro_32 fifo;
    io_rw_32 div;
    io_ro_32 intr;
    io_rw_32 inte;
    io_rw_32 intf;
    io_ro_32 ints;
} adc_hw_t;

#define adc_hw ((adc_hw_t *)ADC_BASE)
```

Тип `io_rw_32` в SDK означает `volatile uint32_t`, а `io_ro_32` ещё и `const`, чтобы в регистр только для чтения нельзя было записать. Поле `adc_hw->result` поэтому лежит по адресу `ADC_BASE + 0x04`, как в карте регистров, так же, как поля структуры в памяти лежат друг за другом по своим смещениям ([[т2.1.6 Указатели как доступ к памяти#^intro|раздел об указателях]]). Шаг 1 выполняет `adc_init()`, шаги 3–5 выполняет `adc_read()` из прошлого раздела, а шаг 2 вот такая функция:

```c
static inline void adc_select_input(uint input) {
    valid_params_if(HARDWARE_ADC, input < NUM_ADC_CHANNELS);
    hw_write_masked(&adc_hw->cs, input << ADC_CS_AINSEL_LSB,
        ADC_CS_AINSEL_BITS);
}
```

Она проверяет номер канала и записывает его в поле `AINSEL` маской, не трогая остальные поля. Константы `ADC_CS_AINSEL_LSB` и `ADC_CS_AINSEL_BITS` равны 12 и `0x7000`, это сдвиг и маска поля, взятые из той же карты регистров. Ещё одна функция, `adc_gpio_init()`, готовит сам вывод. Она отключает у него цифровую часть и подтяжки, чтобы они не искажали напряжение на входе.

Как и функции GPIO в разделе [[т1.2.9 GPIO#^intro|GPIO]], функции SDK для АЦП оказываются именами для записей в поля регистров. В шаблоне прибора их вызывает только модуль `platform`, и об устройстве регистров остальная прошивка ничего не знает.

Теперь прибор умеет снимать отсчёты, в том числе с периодом. Но смотреть на них, хранить и обрабатывать будут не на плате, а на компьютере. Как доставить туда поток измерений, разберём в последнем разделе занятия.
