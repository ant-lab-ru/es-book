**Результат** — Pico читает ID датчика по I²C.
^intro

## Задание

### Что должно получиться

- [ ] `i2c_write_reg` и `i2c_read_reg` передают один байт значения.
- [ ] Из регистра ID получен ответ датчика, а в проекте есть лог `device-4-1-1.log`.

### Как проверить

1. Датчик отвечает `0x60` на чтение регистра ID.
2. Скрипт сохраняет обмен в `device-4-1-1.log`.
3. Автоматическая проверка проверяет обе USB-команды, чтение с повторным START и ответ датчика в логе.

## Ход работы

### 1. Понять техническое задание на прибор

Ознакомьтесь с [[ТЗ 4.1 Связь с внешним устройством#^intro|ТЗ на проект 411-i2c-spi]]. Попробуйте составить план вашей реализации из 4–6 крупных шагов, которые приведут вас к результату, чтобы потренироваться планировать разработку. Сравните ваш план с заданиями практики.

### 2. Создать проект

Рядом с `libs` создайте папку `411-i2c-spi`. Скопируйте туда `pico_sdk_import.cmake` из предыдущего проекта. Создайте `main.c`, пару файлов `platform/platform.h` и `platform/platform.c`, а также папку `logic/api`. Из `231-firmware-template/logic/api` скопируйте `api.h`, `api.c` и `api-commands.h`. Файл `api-callbacks.c` создайте здесь заново для команд этого прибора. См. [[ТЗ 2.3 Шаблон проектирования#1. Раскладка|раскладку проекта из ТЗ 2.3]].

>[!info] `CMakeLists.txt`
>```cmake
> cmake_minimum_required(VERSION 3.15)
>
> set(PICO_BOARD pico)
> set(PICO_PLATFORM rp2040)
> include(pico_sdk_import.cmake)
>
> project(411_i2c_spi)
> pico_sdk_init()
>
> add_compile_options(-Wall)
> add_subdirectory(../libs ${CMAKE_BINARY_DIR}/libs)
>
> add_library(platform STATIC platform/platform.c)
> target_include_directories(platform PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
> target_link_libraries(platform PRIVATE
>     pico_stdlib
>     hardware_i2c
> )
>
> add_library(logic STATIC
>     logic/api/api.c
>     logic/api/api-callbacks.c
> )
> target_include_directories(logic PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/logic)
> target_link_libraries(logic
>     PUBLIC stdio_text_protocol
>     PRIVATE platform
> )
>
> add_executable(${PROJECT_NAME} main.c)
>
> target_link_libraries(${PROJECT_NAME} logic platform pico_stdlib)
>
> pico_enable_stdio_usb(${PROJECT_NAME} 1)
> pico_enable_stdio_uart(${PROJECT_NAME} 0)
> pico_add_extra_outputs(${PROJECT_NAME})
>```

`stdio_text_protocol` подключаем как `PUBLIC`, потому что заголовок `api.h` использует тип `command_t`. См. [[п2.3.7 Железо и логика#3. Собрать логику библиотекой|сборку библиотеки logic в п2.3.7]].

### 3. Настроить I²C0

В `platform/platform.c` подключите `platform/platform.h`, `hardware/i2c.h` и `pico/stdlib.h`. Задайте в перечислении `BUS_BAUD = 100000` и `I2C_TIMEOUT_US = 10000`. В начале `platform_master_init()` вызовите `stdio_init_all()`, затем настройте I²C0.

>[!info] Настройка I²C0
>```c
>     i2c_init(i2c0, BUS_BAUD);
>     gpio_disable_pulls(8);
>     gpio_set_function(8, GPIO_FUNC_I2C);   // SDA
>     gpio_disable_pulls(9);
>     gpio_set_function(9, GPIO_FUNC_I2C);   // SCL
>```

Следующие функции добавьте в `platform.c`. В `platform.h` поставьте `#pragma once`, подключите `<stdbool.h>` и `<stdint.h>` и объявите эти функции и `void platform_master_init(void)`.

>[!info] Чтение и запись регистра по I²C
>```c
> bool platform_i2c_write(uint8_t address, uint8_t reg, uint8_t value)
> {
>     const uint8_t bytes[] = {reg, value};
>     return i2c_write_timeout_us(i2c0, address, bytes, sizeof(bytes), false,
>                                 I2C_TIMEOUT_US) == sizeof(bytes);
> }
>
> bool platform_i2c_read(uint8_t address, uint8_t reg, uint8_t *value)
> {
>     if (i2c_write_timeout_us(i2c0, address, &reg, 1, true, I2C_TIMEOUT_US) != 1)
>     {
>         return false;
>     }
>
>     return i2c_read_timeout_us(i2c0, address, value, 1, false, I2C_TIMEOUT_US) == 1;
> }
>```

При записи номер регистра и значение уходят за одно обращение. При чтении `nostop = true` оставляет шину занятой после передачи номера. Следующий вызов начинает чтение с повторного START и заканчивает его через STOP. См. [[т4.1.5 Контроллеры I²C и SPI RP2040#Пример I²C|пример I²C в теории]].

### 4. Добавить USB-команды

Сохраняем [[п2.3.7 Железо и логика#2. Разделить api на механизм и содержание|разделение API из п2.3.7]]. В `api.h` вход в модуль задаёт `api_handle(const command_t *command)`. Внутренний заголовок `api-commands.h` объявляет `api_callback_t`, `api_command_t` с полями `name`, `help` и `callback`, а также `api_commands` и `api_command_count`. В `api.c` остаются проверка `truncated`, обработка `help`, поиск по таблице и ответ на неизвестную команду. См. [[т2.3.8 Протокол и API прибора#Выполнение команды в API|разбор этих действий]].

В `logic/api/api-callbacks.c` подключите `api/api-commands.h`, `platform/platform.h`, `<stdio.h>` и `<string.h>`. Здесь будут обработчики I²C и строки для справки. Каждый обработчик остаётся `static` и получает введённые аргументы через `command->argv`.

>[!info] Разбор байта в `api-callbacks.c`
>```c
> static int hex_digit(char c)
> {
>     if (c >= '0' && c <= '9')
>     {
>         return c - '0';
>     }
>     if (c >= 'A' && c <= 'F')
>     {
>         return c - 'A' + 10;
>     }
>     return -1;
> }
>
> static bool read_byte(const char *text, uint8_t *byte)
> {
>     if (strlen(text) != 4 || text[0] != '0' || text[1] != 'x')
>     {
>         return false;
>     }
>
>     int high = hex_digit(text[2]);
>     int low = hex_digit(text[3]);
>     if (high < 0 || low < 0)
>     {
>         return false;
>     }
>
>     *byte = (uint8_t)(high * 16 + low);
>     return true;
> }
>```

Следующие функции разместите после `read_byte()`. Адреса от `0x08` до `0x77` доступны для обычных устройств. Остальные значения зарезервированы.

>[!info] Проверка адреса и обработчик чтения в `api-callbacks.c`
>```c
> static bool read_address(const char *text, uint8_t *address)
> {
>     return read_byte(text, address) && *address >= 0x08 && *address <= 0x77;
> }
>
> static void cmd_i2c_read_reg(const command_t *command)
> {
>     uint8_t address, reg;
>     if (command->argc != 2 || !read_address(command->argv[0], &address) ||
>         !read_byte(command->argv[1], &reg))
>     {
>         puts("error: usage i2c_read_reg <address> <register>");
>         return;
>     }
>
>     uint8_t value;
>     if (!platform_i2c_read(address, reg, &value))
>     {
>         puts("error: i2c transfer");
>         return;
>     }
>
>     printf("i2c: addr 0x%02X reg 0x%02X value 0x%02X\n", address, reg, value);
> }
>```

Добавьте обработчик записи рядом с обработчиком чтения. Он принимает адрес устройства, адрес регистра и значение.

>[!info] Обработчик записи в `api-callbacks.c`
>```c
> static void cmd_i2c_write_reg(const command_t *command)
> {
>     uint8_t address, reg, value;
>     if (command->argc != 3 || !read_address(command->argv[0], &address) ||
>         !read_byte(command->argv[1], &reg) || !read_byte(command->argv[2], &value))
>     {
>         puts("error: usage i2c_write_reg <address> <register> <value>");
>         return;
>     }
>
>     if (!platform_i2c_write(address, reg, value))
>     {
>         puts("error: i2c transfer");
>         return;
>     }
>
>     printf("i2c: addr 0x%02X reg 0x%02X sent 0x%02X\n", address, reg, value);
> }
>```

В конце `api-callbacks.c` добавьте таблицу и её длину. Поле `help` хранит синтаксис команд из [[ТЗ 4.1 Связь с внешним устройством#3. Интерфейс по USB|ТЗ]].

>[!info] Таблица команд в `api-callbacks.c`
>```c
> const api_command_t api_commands[] = {
>     {"i2c_write_reg", "<address> <register> <value>", cmd_i2c_write_reg},
>     {"i2c_read_reg", "<address> <register>", cmd_i2c_read_reg},
> };
>
> const uint32_t api_command_count = sizeof(api_commands) / sizeof(api_commands[0]);
>```

Свяжите протокол с API в `main.c`, как в [[п2.3.1 Протокол и API#4. Связать протокол и api|п2.3.1]]. Перед циклом вызовите `platform_master_init()` и `stdio_text_protocol_init()`. В цикле передавайте в `api_handle()` только полученную команду.

>[!info] `main.c`
>```c
> #include "api/api.h"
> #include "platform/platform.h"
> #include "stdio-text-protocol/stdio-text-protocol.h"
>
> #include <stddef.h>
>
> int main(void)
> {
>     platform_master_init();
>     stdio_text_protocol_init();
>
>     while (1)
>     {
>         const command_t *command = stdio_text_protocol_handle();
>         if (command != NULL)
>         {
>             api_handle(command);
>         }
>     }
> }
>```

### 5. Подключить датчик

![[Монтаж ведущего I²C и BME280.excalidraw|100%]]

Отключите питание и подключите BME280 по схеме. Если у модуля шесть контактов, дополнительно соедините CSB с питанием интерфейса и задайте SDO низким уровнем для адреса `0x76` либо высоким для `0x77`. На проверенном четырёхконтактном GYBMEP адрес уже выбран на плате.

![[Стенд SPI и I²C — подключение BME280.jpeg|100%]]

На фотографии видны четыре контакта модуля на собранном стенде.

>[!info] Подтяжки I²C
>На проверенном GYBMEP SDA и SCL подтянуты к VIN через 10 кОм. При питании VIN от 3,3 В отдельных резисторов не добавляем. Для другой платы проверьте схему или сопротивление от линий к питанию на отключённом модуле. Если подтяжек нет, поставьте по 4,7 кОм от SDA и SCL к 3,3 В.

### 6. Собрать и прошить

В папке проекта создайте `build` и перейдите в неё. При следующих сборках используйте ту же папку.

```bash
cmake -G "Unix Makefiles" ..
make -j8
```

### 7. Прочитать ID и записать лог

После прошивки наберите `help` и убедитесь, что обе команды I²C есть в списке.

>[!success] Должно получиться так
>```text
> help             list of commands
> i2c_write_reg    <address> <register> <value>
> i2c_read_reg     <address> <register>
>```

Затем введите `i2c_read_reg 0x76 0xD0`. Если у датчика адрес `0x77`, укажите его. При ошибке проверьте питание, землю, подтяжки и адрес. См. [[т4.1.3 Подключение устройств по I²C#Чтение регистра внешнего устройства|схему чтения]].

Закройте терминал. Скопируйте [[check-4-1-1.py]] в папку проекта. Для скрипта нужен `pyserial`, как в [[п1.3.2 Скрипт проверки на устройстве#^intro|п1.3.2]]. Для `0x76` запустите первую команду, для `0x77` вторую.

```bash
python check-4-1-1.py
python check-4-1-1.py --address 0x77
```

Ниже приведён конец вывода после справки.

>[!success] Должно получиться так
>```text
> --> i2c_read_reg 0x76 0xD0
> <-- i2c_read_reg 0x76 0xD0
> <-- i2c: addr 0x76 reg 0xD0 value 0x60
> Обмен записан в device-4-1-1.log
>```
